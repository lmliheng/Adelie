# Adelie v0.8.7 —— 大文件改成几路一起传，网络面板能看模型请求和响应

跨洋传一个大文件，以前只有一条连接在跑：来回 200 毫秒的链路上，单个连接的吞吐被拥塞窗口卡在几
Mbps，一个 155MB 的安装包要等好几分钟。这一版把它切成 4MB 的分片、四路并行，服务端边收边落盘、全
部分片到齐才落成正式附件。网络面板的「模型」行也不再只有一个耗时——点开就是 Adelie 发给模型服务商
的 messages、工具和参数，以及模型回的文字和工具调用。

## 安装

**已经装过的人**：桌面端在应用内更新（账号菜单的更新入口，或应用菜单里的「检查更新」）；命令行与
Web 用 `penguin update`，或重装 `npm install -g @adelie/cli` —— 两者都需要 Node >= 24。npm 上的包都
到了 0.8.7。Windows 安装包仍未签名，SmartScreen 会提示一次（「更多信息 → 仍要运行」）。

**全新的机器**，单行脚本：

```bash
curl -fsSL https://github.com/lmliheng/Adelie/releases/latest/download/install.sh | sh
```

```powershell
irm https://github.com/lmliheng/Adelie/releases/latest/download/install.ps1 | iex
```

## 亮点

**大文件分片、并行上传。** 超过 8MB 的附件不再只走一条连接：浏览器把文件切成 4MB 的片，四路同时
发，服务端为这个上传在会话的暂存区预建目标文件，每一片按偏移写进去，乱序到达也没关系；所有片到齐
才落成正式附件，中途失败只重传那一片，整份放弃时半成品当场删掉。进度卡上的读数是所有分片加起来
的，四条流在传，数字就一直在走。8MB 以下仍然一次请求直接传完——小文件为它多两个来回不值。

**网络面板的「模型」行有内容了。** 面板里「模型」那一行原来只告诉你这次调用花了多久、是成功还是
重试，看不到发出去和收回来的是什么。现在点开这一行：请求页是 Adelie 发给服务商的完整 messages、工
具定义、系统提示词与参数，响应页是模型回的文字、思考过程和工具调用。模型调用发生在服务端，页面看
不到它的 HTTP，所以内容由服务端记录、按会话取回，只保留最近 100 次，每条请求和响应各截断到 256KB；
图片和视频的 base64 会换成 `data:image/png;base64,<1.2MB>` 这样的占位符，不把几 MB 的字节再存一遍。

## 值得一提

- 上传不再有反向代理那一层 64MB 的隐形上限：请求体上限与 Adelie 自己的 200MB 对齐，慢链路也不
  会因为在两个数据包之间停顿超过 60 秒被断开。
- 服务端启用了 BBR 拥塞控制（可选，部署侧生效）：高延迟链路上页面与文件下载明显更顺。
- 分片上传的失败是可重试的：某一片掉了只补那一片，不再从头再来。

## 兼容

- 这一版**没有数据库迁移**，数据根与配置文件格式一个字节没动；数据根与上一个版本互相兼容。
- 服务端新增了四条分片上传路由（申请、单片、完成、放弃）和一条模型调用查询路由；旧的单次上传照旧
  可用，同时更新的前端与后端之间没有先后要求。
- 内置浏览器连接协议仍是第 2 版，与 v0.8.6 的桌面应用互相兼容。

## 要求

- Node.js >= 24（单行安装脚本自带运行时，npm 安装需要本机有）。
- Linux / macOS / Windows 的 x64 与 arm64；其他 POSIX 平台用 `--universal` 安装包。
- 桌面端：Linux 提供 AppImage 与 deb，Windows 提供 exe；macOS 未签名，这一版不随 Release 发布。

上一版（v0.8.6）让大附件改走独立直传、对话页多了「网络」面板；再上一版（v0.8.5）给大附件的上传
加了进度卡、把打不开的原因留在原地。文档在 <https://lmliheng.github.io/Adelie/docs/>。本版全文见
[`docs/releases/RELEASE-v0.8.7.md`](https://github.com/lmliheng/Adelie/blob/main/docs/releases/RELEASE-v0.8.7.md)。
