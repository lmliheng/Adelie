# Adelie v0.6.2 —— 手机上的终端断了会自己重连，删大 Agent 不再卡住应用

这一版自 v0.6.1 起在 `main` 上落了 **10 个用户看得见的改动**（其余是每轮的记账与测试整理）。
数据根、配置格式、包名与既有的请求接口都没有变化，装好的机器升级后不用改任何配置。

两件事撑起这一版。一是**连接不可靠的时候，界面自己要爬回来**：手机上的 socket 不会礼貌地关闭，
页面上却写着「已连接」，唯一的回去方式是刷新；现在两端互相探测，断了就按有界的退避重新接入，
回来的那一屏由服务端自己的快照重绘。二是**同一件事在别处已经做对了，这里补齐**：插件市场过去只认
「这次构建带了什么」，发布到 npm 的插件在里面看不见；桌面端在 Windows 上不会随登录自己起来；
设置里还有四处「点了没反应」只留一条六秒的通知。这些都在这一版里改掉了。

## 这一版改了什么

1. **终端在手机网络下不再假死，断了会自己重连。** 基站切换、运营商回收空闲流、浏览器冻结标签页
   —— 这些都不会给 socket 一个体面的关闭，页面手里于是留着一条再也不会传字节的连接，界面上仍然
   写着「已连接」。现在任意一端都会发 Ping、对端原样回 Pong，沉默超过窗口的连接被判死：服务端关掉
   它，页面按有界退避自己重连，重连后由服务端自己的快照整屏重绘。网络恢复或标签页回到前台时，
   等待会收成「立刻重试」；界面上这一态叫「重连中」，与首次接入的「连接中」分开。几个原本按局域网
   调出来的常量改成按链路测量（输出合并窗口跟往返时延走、背压按时间界、容器尺寸静置后才落一次）。
   只有应答过探测的对端才会被沉默判决，因此热更新之后新旧两端不会互相踢下线。

2. **删除大 Agent 不再卡住应用。** 删一个文件很多的 Agent（临时 Workspace 里装过依赖是常见的一种）
   时，服务端要在请求里等整个目录递归删完，期间的其它读文件请求全排在它后面，确认框一直转；中途被杀
   还会留下「列表里有、点进去 404」的幽灵行。现在删除先用一次 rename 把目录移进待删区、删掉索引行，
   立刻返回 202 —— 从这一刻起它在任何列表里都不在了，同一个名字可以马上再用；内容交给后台服务按两个
   并发槽慢慢删，右下角出现一张进度卡片（先统计条目、再显示已删/总数、最后显示结果），关掉卡片不影响
   删除，离开这一页卡片也跟着。下次启动接着删没删完的。移不走目录（别的程序打开着里面的文件）时直接
   报错，什么都不删。

3. **插件市场的货架也列出发布到 npm 的插件。** 此前要进市场只能先进仓库、再随一次版本发出去。现在
   货架多读一侧：作用域是 `@adelie/`、带 `adelie-plugin` 关键词的 npm 包，下一个版本就会出现在上面，
   唯一的动作是「装入插件库」（就是运维本来要手工敲进导入对话框的那一步，管理员操作）。同名时以本地
   构建那一份为准。查询十分钟缓存一次、失败时沿用上一次结果，页面加载不会因为它失败。设
   `ADELIE_PLUGIN_MARKET=off` 可以整条关掉这次对外查询。

4. **插件库收下 `gpu-model-serving`。** 它此前只发在 npm 上，得靠「从 npm 导入」才装得进去；现在随构建
   发布，插件库与插件市场各有一条。它不预装 —— 装到要自己起模型服务的 Agent 上。

5. **桌面端可以随 Windows 登录自己启动。** 设置 › 外观多一行「开机自启动」，默认关闭；打开后装好的
   Adelie 会在你登录 Windows 时自己起来，那一次只在托盘待命、不弹窗。这一行显示的是 Windows 自己的
   启动项登记，所以在「任务管理器 › 启动应用」里禁用，这里也会如实显示成关闭。条目写在当前用户的
   Run 键下，不需要管理员权限、不装服务；卸载时连启用记录一起删掉。

6. **版权信息页写明七套主题的来源与许可。** 应用自带的三套与外观页主题库里的四套，此前都没有许可
   说明；现在在字体致谢下面一段列清：各由谁维护、都是 Apache-2.0，并给出主题库仓库地址。

7. **「代理选项」保存被拒、设置读不出来，原因都留在设置区里。** 保存被拒时这次什么都没写进去，两个
   开关与地址原样不动、再按一次保存就是重试，但屏上剩下的只是一个看起来没被碰过的表单；读取失败时
   每个控件都停用、显示的是表单默认值，页面一个字都不留。现在两句话都画在设置区：保存那句在地址
   下面、保存按钮上面，读不出来那句在控件上面。

8. **连通性测速被拒时，原因留在测速块里。** 测速自己能得到的结果（已连通 / 超时 / 域名 / 拒绝 / TLS）
   都落在那一行；只有请求本身失败时一个格子都填不上，整块与按下按钮之前一模一样、六个目标都还写着
   「未测试」，原因只是盖在上面的一条通知。

9. **工作区「新建文件夹」被拒时，原因留在名称框下面。** 那只框被拒时本来就留着（名字在、光标也放回
   框里，再按一次 Enter 就是重试），缺的只是「为什么」。句子留到名字改动或下一次尝试开始；带分隔符的
   名字就地拒绝，一条请求都不发。

10. **「导入 Trace」被拒时，原因留在这一行下面。** 三个控件（项目 / Agent / 选文件）被拒时原样不动，
    再选一次文件就是重试；服务端拒绝、按文件种类超上限、读取文件出错这三条路现在都画在这一行的控件
    下面，留到下一次尝试开始。

## 兼容

- 请求、响应与磁盘格式都没有变。新增的只有：终端 WebSocket 上的探测帧（老页面不发也不应答，因此不会
  被判决）、删除接口的 202 应答与进度查询（旧的 `DELETE` 单发仍然照旧生效）、插件市场货架多出来的
  npm 一条。数据根一个字节没动。
- 新装的机器与升级的机器都不需要改配置；`ADELIE_PLUGIN_MARKET=off` 可以让服务器不发那次对外查询。
- 桌面端的「开机自启动」只影响 Windows，且默认关闭。

## 升级

**桌面端**在应用内更新：账号菜单的更新入口，或者应用菜单里的「检查更新」。Windows 安装包仍未签名，
SmartScreen 会提示一次（「更多信息 → 仍要运行」）。

**命令行与 Web**：`penguin update`（或重装 `npm install -g @adelie/cli`）。npm 上的包都到了 0.6.2。

## 安装

```bash
curl -fsSL https://github.com/lmliheng/Adelie/releases/latest/download/install.sh | sh
```

```powershell
irm https://github.com/lmliheng/Adelie/releases/latest/download/install.ps1 | iex
```

也可以只装 CLI：`npm install -g @adelie/cli`（需要 Node.js >= 24）。

## 要求

- Node.js >= 24（单行安装脚本自带运行时，npm 安装需要本机有）。
- Linux / macOS / Windows 的 x64 与 arm64；其他 POSIX 平台用 `--universal` 安装包。
- 桌面端：Linux 提供 AppImage 与 deb，Windows 提供 exe；macOS 未签名，这一版不随 Release 发布。

上一版（v0.6.1）把「被拒绝」的原因留在被点的那一处，不再是一条六秒就消失的提示。文档在
<https://lmliheng.github.io/Adelie/docs/>。变更明细见仓库里的
[`CHANGELOG.zh.md`](https://github.com/lmliheng/Adelie/blob/main/CHANGELOG.zh.md)。
