# Adelie v0.4.0 —— 四家国内模型厂商进预置目录，插件库多一个 Offer岛

这一版自 v0.3.9 起在 `main` 上落了 **8 个功能性提交**：四条新面孔（小米、百度、腾讯、讯飞四家的
预置模型，加一个新插件 Offer岛），三条界面修补，以及 WPS 插件的两处真问题。**没有破坏性改动**：
数据根（`~/.adelie/data`）、配置格式、既有 HTTP 接口都没动，已装好的机器不需要改任何配置。

主线是「少一步手工」。这四家模型以前只能自己到模型页「自定义端点」里手填 base URL 才用得上，现在
各是一个预置分组，贴一把 key 就能用；Offer岛的 skill 以前只发在它自己的仓库里、要手动拷文件，现在
它是一个正经插件，装上就能搜岗位、发 JD、读 AI 资讯。

## 这一版改了什么

1. **小米、百度、腾讯、讯飞四家进模型页预置分组。** 小米 MiMo（`mimo-v2.6-pro` / `flash`，1M
   上下文、支持图片）、百度文心（`ernie-5.1` / `5.0` / `4.5-turbo-vl` / `4.5-turbo-128k` / `x1.1`）、
   腾讯混元（`hunyuan-a13b` 与三个视觉模型）、讯飞星火（`4.0Ultra` / `pro-128k` / `lite`），共 14 行。
   每行的上下文窗口、图片支持与价格都取自各厂商自己的文档（价格按目录惯例折成美元），**读不出来的
   不编**：讯飞那几行不带价格（它的 HTTP 文档没有价格表，产品页又只按另一个型号系列列价），星火的
   Max 一对、混元的角色扮演 / 翻译 / 向量化、小米的 ultraspeed 档也都没收录，理由写在目录的注释里。
   四家在 AgentHub 里都没有一方客户端，所以每行都钉住 Chat Completions 协议并内联端点；分组图标
   先走首字母方块（没有可核对的品牌图形，不手画商标）。
2. **新插件 Offer岛：搜岗位、发布 JD、看 AI 资讯。** `@adelie/use-offerdao`，插件库「办公效率」
   分类，**不预装**。按公司 / 岗位 / 地点 / 工作类型 / 时间搜已审核的岗位、查 AI 公司目录、找面经
   攻略、读每日 AI 资讯；把一段 JD 或一个链接交给它，还能解析成结构化岗位替你提交审核。公司目录、
   面经、资讯不需要 key；搜索与发布要一把 Offer岛的 key，存进 Agent 密钥库的 `OFFERDAO_API_KEY`
   即可。按 Adelie 的规矩做了四处适配（补 `Before you start`、把原文的 `browser-act` 换成本仓库的
   `browser-automation`、去掉只对 Offer岛自家客户端成立的站内卡片与 daemon 自动更新约定、把密钥
   改成写进密钥库）；上游是 MIT 许可，许可证原文随内容一起放，出处与改动记在插件 README 与
   SKILL.md 末尾。
3. **WPS 插件：装好了摸不到文档工具，重连后还会一直卡在「正在处理…」。** 两处都在桥里。其一，
   安装脚本把文档工具那一条写在 `tools.mcpServers` 下，而 Adelie 的配置接口里这份列表是顶层的
   `mcpServers`——接口对不认识的键照答 200 却把内容丢掉，于是「安装成功」的下一步是会话里一个
   `mcp__wps__*` 工具都看不到；卸载脚本是同一处问题，那条登记也就删不掉。其二，侧栏每次连上事件
   流时，桥先把这一轮的真实状态补一帧：之前只有下发命令时才转达状态，面板在回合开始之后才打开
   （或断开重连）就等不到收尾，一直停在「Adelie 正在处理…」。
4. **用户管理表多一列「最近一次会话」。** 该账号名下全部项目里最近活跃的一次对话，显示时间与标题；
   没有会话显示 `—`，会话还没有标题就只显示时间。服务端 `GET /api/admin/users` 多带
   `lastSessionAt` / `lastSessionTitle` 两个字段，面板从 5xl 加宽到 6xl 以放下第七列。
5. **被压缩过的长会话可以整套搬到另一台 Adelie。** 以前只能导出/导入单个 Trace 文件，而一个长会话
   被上下文压缩切开后是多个文件，导入端只收第一片、同一会话再来一片直接拒绝——搬过去的其实是断的。
   现在对话的轨迹面板多一个「导出整个会话」，把该会话的全部分片打成一个包；在设置里导入这个包，
   会在目标机上落成一个完整会话，侧栏可见、可续聊。包在落盘前整体校验：分片必须从 1 连续、每片都
   声明同一个会话 id，任一片不合法就整包拒绝且不写任何文件；本机已有同 id 会话仍然拒绝，不覆盖也
   不追加。
6. **成本中心的错误提醒：标记已读之后重启不再回来。** 成本中心读的是屏幕上那个时间范围的错误，
   却把应用启动时那次探测的时间戳标成已读——于是应用开着时进来的错误被这个标记盖住，重启后又冒
   出来。现在打开页面先刷新这条提醒，表格和标记指向的是同一个最新错误；而且标记只有在偏好写入
   成功之后才隐藏提醒：写失败会报出接口错误并把提醒留在原地，连续关闭按顺序落盘，先发的请求不会
   覆盖后发的标记（上游 #1118 移植）。
7. **设置里 WSL 的中文诊断不再乱码。** 插件页里凡是 `wsl.exe` 用 UTF-16LE 回话的地方都显示成
   乱码——即使每次调用都带 `WSL_UTF8=1`：字节先按 UTF-8 解了一遍，UTF-16 回话留下的 NUL 再也
   变不回字符。现在宿主把 `wsl.exe` 的输出当字节收着，最后只解码一次：`decodeOutput()` 认带或不带
   BOM 的 UTF-16LE（它的标签、空格、换行高位字节都是 0，而 UTF-8 文本不会），UTF-8 输出原样放行；
   安装日志走同一个解码器，实时进度仍用流式 UTF-8 解码器，所以一个汉字被行边界切开也能整字到达
   （上游 #1125 移植）。

## 升级

桌面端（Windows / Linux 的 AppImage）在应用内更新：账号菜单的更新入口，或应用菜单里的「检查更新」。
默认的镜像源当前不可用，客户端会自动回退到 GitHub Releases；Windows 安装包仍未签名，
SmartScreen 会提示一次（「更多信息 → 仍要运行」）。

服务器 / CLI 装的（tar 包或 npm 全局）用同一条链路，数据根（`~/.adelie/data`）不动：

```bash
penguin update --check     # 看有没有新版
penguin update --yes       # 原地替换 bin/lib/web/node
```

| 产物 | 目标 |
| --- | --- |
| `adelie-desktop-win32-x64.exe` | Windows x64 桌面端（未签名，NSIS 安装器） |
| `adelie-desktop-linux-x86_64.AppImage` / `adelie-desktop-linux-amd64.deb` | Linux x64 桌面端 |
| `penguin-linux-x64.tar.gz` | Linux x64 命令行版（自带 Node 24.18.0） |
| `penguin-win32-x64.zip` | Windows x64 命令行版（自带 Node 与 MinGit） |
| `penguin-universal.tar.gz` | 任意平台（不带运行时，需要 Node ≥ 24） |
| `install.sh` / `install.ps1` | 在线安装脚本（`penguin update` 取的就是它） |
| `latest.yml` / `latest-linux.yml` | 桌面端自动更新读的元数据 |

安装包都在 GitHub Release 上：<https://github.com/lmliheng/Adelie/releases/tag/v0.4.0>，
下载页同样直指这里。npm 上整条链同样是 **0.4.0**（3 个宿主包 + 20 个插件包，其中新加入的是
**Offer岛**）：`npm install -g @adelie/cli`。

**存储清理仍是出厂关闭的。** 想用就在设置页「存储」页打开开关，或 `penguin storage mode on`；
不想用就什么都不用做，行为与上一版一致。

## 已知待办

- **没有代码签名**：Windows 的 Authenticode 与 macOS 的 Developer ID 都没有；macOS 的 dmg 会被
  Gatekeeper 拦，所以仍不发 macOS。
- **WPS 插件这一版只带两处修复**：面板的视觉改版（图标、字号、权限胶囊）还没并进仓库，随插件走的
  仍是当前这一版界面；WPS 那一侧本身也仍没有验证——功能区按钮、任务窗格、文档接口只在装了 WPS 的
  机器上存在，第一次必须发生在 Windows 上、并且当着 WPS 的面。
- **OSS 镜像当前不可用**：镜像账号被停用，直链与读写都返回 `403 UserDisable`；因此下载页与 Release
  资产都只指向 GitHub，桌面端更新自动回退到 GitHub。等镜像恢复后一行换回即可。
- **存储清理的第 3、4 步未做**：删会话时把它留下的临时工作区一并移入回收站（止漏）、以及重复工具
  环境的合并迁移（人工点一次）。数据库维护（`VACUUM`）也推迟。
- 命令名仍是 `penguin`、数据根 `~/.adelie`；安装脚本与打包脚本里的产物名仍是 `penguin-*`。
- `.github/workflows/release.yml` 仍是上游那条（只能手动 dispatch，且会推上游的 Docker 镜像），
  Adelie 自己的发布流水线还没写；这一版的安装包是「本机脚本 + `desktop-build.yml` 手工 dispatch」
  打的。
