# Adelie v0.3.7 —— 翻看更早的对话不再被甩走，回复可以只复制正文

这一版自 v0.3.6 起在 `main` 上落了 **10 个功能性提交**，多数是从上游带回来的健壮性与界面修补，
另有一笔是直接点单的新能力：回复能复制成纯文本。**没有破坏性改动**：数据根（`~/.adelie/data`）、
配置格式、既有 HTTP 接口都没动，已装好的机器不需要改任何配置。

最值得先说的一条是对话页的翻页：滚到顶部取回更早的一页时，过去读者会被新插入的整页推走或被甩到底部，
现在正读的那条消息留在原处。另一条是 `penguin chat` 的粘贴：Task 运行期间贴进去的内容过去会被静默丢掉，
现在会和键入的一行一样成为插话。其余是：等待审批的会话在所有列表里实时标出、排队的 follow-up 加上限、
组织工单的存储在崩溃面前不再丢数据、平台的 HTTP 面在鉴权上收紧了几处。

## 这一版改了什么

1. **往上翻页时，读者停在原来读的那条消息上。** 对话页滚到顶部会取回更早的一页并插到已有内容的上方；
   过去这次插入会把正在读的内容推走、有时直接甩到对话最底部。现在正看着的那条消息留在原处：
   列表与滚动修正在同一次渲染里变化（缓存以已插入的内容本身为键，而不只是那个被节流的版本号），
   修正量是**量出来的**——每次滚动与渲染记下最靠上那条提问在屏幕上的位置，插入后按它实际被挪动的
   距离补回（浏览器自己的滚动锚定在非顶端会补偿、在顶端不会，按高度差固定修正要么重复要么缺失）；
   顶部那行加载提示在上方还有历史时保持高度，出现和消失不再挪动对话（上游 #995 移植）。
2. **回复可以复制成纯文本，不再只有 Markdown 源码。** AI 回复的页脚原本只有一个复制按钮，给的是
   回复的 Markdown 源码——粘到聊天窗口、工单或文档里，对方看到的是 `##`、`**`、`| --- |` 这些标记本身。
   现在页脚上有两个按钮：原来的照旧复制 Markdown，旁边新增的**「复制纯文本」**给出把标记去掉之后的正文。
   纯文本按渲染时的同一套方言拆开（标题 / 强调 / 行内代码去标记，列表保留 `- ` 与编号并按层级缩进，
   表格去首尾竖线与那条对齐用的 `| --- |`，引用去 `>`，链接写成 `标签 (地址)`，图片取 alt，
   围栏代码块里的代码原样保留），只有这一轮确实有正文时这个按钮才出现。
3. **等待审批的会话在所有列表里实时标出。** 过去侧栏行上的审批标记只来自最近一次列表拉取，所以当你
   开着另一个对话时，某个开始等待工具审批的会话不会显示任何标记，直到列表重新加载。现在用户通道新增
   `session_approvals` 事件（带该会话等待审批的调用数），Web App 收到就立刻更新对应那一行：
   升级给人、回答、中断或 Task 边界上被拒都会发布，一次中断拒掉多个调用只发一个事件，计数归零同样发出
   （上游 #1002 移植）。
4. **`penguin chat` 在 Task 运行期间的粘贴不再被丢掉。** 过去终端里贴进去的文本既没送到模型、屏幕上
   也没有任何提示，而同一时刻键入的一行却会成为插话；Task 刚结束、REPL 还没回到提示符时的粘贴同样会丢。
   现在粘贴在所有接受消息的状态下都与键入的文本一致：运行中贴入的文本回显并等 Enter，按下后整段作为
   **一条**插话发出（多行粘贴因此是一条消息），等待期间流式输出暂停；Task 若在按 Enter 之前结束，
   这段文本留在续行提示符下，下一次 Enter 把它作为下一条 Prompt 发送。审批询问与退出确认期间的粘贴
   仍按要求只接受键入的 y/N（上游 #1001 移植）。
5. **`penguin chat` 为终端标记提示符。** 在终端里现在会输出 OSC 133 语义提示符序列——支持它的终端
   可以在对话的提示符之间跳转、整轮选中输出，承载对话的宿主程序也能知道对话何时回到提示符、可以接收
   输入，而不必去匹配提示符文本。只有 stdin 与 stdout 都是终端且 `TERM` 不是 `dumb` 时才输出，
   被重定向或接管道时一个标记都没有；这些序列宽度为零，不认识的终端会忽略它们（上游 #1003 移植）。
6. **一个会话排队的 follow-up 上限 16。** 带 `queueIfBusy` 提交的 Task 现在对第 17 条排队的 follow-up
   以 `429 queue_full` 拒绝，而不是无上限入队。总是要求排队的路径——组织频道的 @提及、日程向繁忙工位的
   派发——把拒绝记下来后继续（周期日程项在下一个槽位照常触发），于是一场提及风暴或一次 @all 扇出
   不再让工位队列无限增长、再把每一条都重放成一次模型调用。不带 `queueIfBusy` 的 `409 task_in_progress`
   不变，排出一条即空出一个位置（上游 #853 移植）。
7. **派发失败的一次性日程项在下一轮重新触发。** 一次性日程项派发返回 skipped（开不出工位，或 Task 无法
   入队）时，已消耗的时间槽现在会释放，于是下一轮对账重新触发该事件，并带上随之重新入队的工位通知。
   此前那个时间槽一直算已消耗，员工的工单变化无限期留在队列里，只留下一行派发错误。这类失败运行从未
   开始，重试不会让事件触发两次；持续失败仍会在每一轮以 `error` 结果显露（上游 #852 移植）。
8. **组织存储的写入改原子、崩溃后同时出现在两列的工单不再丢。** 组织存储写出的每个文件——组织配置、
   架构图、工单、频道、日程项、手册——现在都经由核心的原子写入（唯一命名的临时文件再重命名到位）落盘，
   写到一半崩溃不会再留下被对账判为非法、从而从看板移除的截断文件；移动工单时删旧列也不再吞掉错误，
   只放过文件本已不存在的情形。同一工单 id 出现在两列时（写入与删除之间崩溃），看板保留最新的一份、
   过期的一份列入非法文件，而不是两份一起消失（上游 #850 移植）。
9. **阻塞工单时按组织架构校验 `by` 主体。** 阻塞工单（`block` 接口、`penguin org ticket block --by`
   与员工工具）现在对 `agent:<id>` / `user:<id>` 形式的 `by` 施加组织接受的其他主体早已遵循的规则：
   agent 必须是架构图上的员工，user 必须是本 Project 的成员，否则以 `400 invalid_principal` 拒绝写入。
   此前任何形状合法的 id 都会写进 `blocked_by`，并在摘要与看板上显示成「(by …)」。工单 id 形式仍只做
   存在性检查，省略 `by` 仍清除阻塞，已存储的值不会被改写（上游 #851 移植）。
10. **路由组的 `auth` 标记不再随挂载位置而变。** 平台的 HTTP 面原先只在第一个受保护路由组之前、
    于 `/api/*` 上挂一次登录门，于是路由组的 `auth` 标记实际取决于它的排列顺序。现在登录门挂在每个受保护
    路由组自己的前缀上：以 `auth: "none"` 贡献、位于 `/api` 下的路由组即使排在受保护组之后也保持公开
    （此前未登录请求会拿到 401）；没有任何路由组服务的路径由平台拒绝、返回 **404**（此前 `/api` 下的
    这类路径对未登录请求返回 401）；一条路径经过多个受保护前缀时只鉴权一次。顺带一处收紧：
    `GET /api/contributions` 每条贡献的 `id` 与 `from` 恒为服务端自己的归属信息，贡献数据里的同名字段
    不再能覆盖它们（上游 #793 移植）。

## 升级

桌面端（Windows / Linux 的 AppImage）在应用内更新：账号菜单的更新入口，或应用菜单里的「检查更新」。
默认的镜像源当前不可用，客户端会自动回退到 GitHub Releases；Windows 安装包仍未签名，
SmartScreen 会提示一次（「更多信息 → 仍要运行」）。

服务器 / CLI 装的（tar 包或 npm 全局）用同一条链路，数据根（`~/.adelie/data`）不动：

```bash
penguin update --check     # 看有没有新版
penguin update --yes       # 原地替换 bin/lib/web/node
```

| 产物 | 目标 |
| --- | --- |
| `adelie-desktop-win32-x64.exe` | Windows x64 桌面端（未签名，NSIS 安装器） |
| `adelie-desktop-linux-x86_64.AppImage` / `adelie-desktop-linux-amd64.deb` | Linux x64 桌面端 |
| `penguin-linux-x64.tar.gz` | Linux x64 命令行版（自带 Node 24.18.0） |
| `penguin-win32-x64.zip` | Windows x64 命令行版（自带 Node 与 MinGit） |
| `penguin-universal.tar.gz` | 任意平台（不带运行时，需要 Node ≥ 24） |
| `install.sh` / `install.ps1` | 在线安装脚本（`penguin update` 取的就是它） |
| `latest.yml` / `latest-linux.yml` | 桌面端自动更新读的元数据 |

安装包都在 GitHub Release 上：<https://github.com/lmliheng/Adelie/releases/tag/v0.3.7>，
下载页同样直指这里。npm 上整条链同样是 **0.3.7**：`npm install -g @adelie/cli`。

**存储清理仍是出厂关闭的。** 想用就在设置页「存储」页打开开关，或 `penguin storage mode on`；
不想用就什么都不用做，行为与上一版一致（只有只读的分类账多出来）。

## 已知待办

- **没有代码签名**：Windows 的 Authenticode 与 macOS 的 Developer ID 都没有；macOS 的 dmg 会被
  Gatekeeper 拦，所以仍不发 macOS。
- **OSS 镜像当前不可用**：镜像账号被停用，直链与读写都返回 `403 UserDisable`；因此下载页与
  Release 资产都只指向 GitHub，桌面端更新自动回退到 GitHub。等镜像恢复后一行换回即可。
- **存储清理的第 3、4 步未做**：删会话时把它留下的临时工作区一并移入回收站（止漏）、以及重复工具环境的
  合并迁移（人工点一次）。数据库维护（`VACUUM`）也推迟——`web.db` 不是占用大头。
- 命令名仍是 `penguin`、数据根 `~/.adelie`；安装脚本与打包脚本里的产物名仍是 `penguin-*`。
- `.github/workflows/release.yml` 仍是上游那条（只能手动 dispatch，且会推上游的 Docker 镜像），
  Adelie 自己的发布流水线还没写；这一版的安装包是「本机脚本 + `desktop-build.yml` 手工 dispatch」打的。
