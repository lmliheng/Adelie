# Adelie v0.3.8 —— 断掉的实时流自己追上，手机上的频道消息读得清

这一版自 v0.3.7 起在 `main` 上落了 **12 个功能性提交**，全部是从上游带回来的健壮性与界面修补。
**没有破坏性改动**：数据根（`~/.adelie/data`）、配置格式、既有 HTTP 接口都没动，已装好的机器
不需要改任何配置。

最值得先说的一条是页面的实时连接：会话流或用户事件流如果在没有任何报错的情况下断掉（半开的连接、
卡住的代理、休眠或换了网络的笔记本），页面过去会一直停在原处直到你手动刷新，而 Agent 其实还在
服务器上继续跑；现在页面会察觉这段静默、从收到的最后一个事件处续接，服务器也会主动切断对端已不再
读取的流。另一条是公司模式：打开某个组织的页面时，侧栏不再停留在上一次打开的那家。其余集中在几处
日常会碰到的界面问题——手机上的频道消息变宽、频道记住你没发出的字、输入框打字不再把对话带得抖、
全屏的智能体面板输入区回到对话那一列、回复里的波浪号不再被当成删除线、白领主题的滚动条常显。

## 这一版改了什么

1. **实时流无声断开时，Web App 自行追上进度。** Session 流或用户事件流的连接如果在没有任何错误的
   情况下断掉（半开的连接、卡住的代理或 NAT、休眠或切换了网络的笔记本），页面会一直停在原处，
   直到刷新，而 Agent 仍在服务器上继续运行。现在页面会察觉这段静默，从收到的最后一个事件处续接流；
   服务器也会切断对端已不再读取的流。做法是：服务器心跳改为名为 `ping` 的事件（不带 `id:`），
   在流的初始事件之后立即发送、之后每 20 秒一次；页面在见过 ping 之后，把 50 秒内没有任何事件判定为
   连接已死，关掉这条流并从见到的最后一个事件 id 新开一条，服务器据此重放（该 id 已移出缓冲区时回
   `resync_required`），标签页重新显示时立即检查一次。没有 `Last-Event-ID` 请求头时，两条流接口也
   接受以查询参数 `lastEventId` 传来的最后事件 id。两条兼容性都保住了：从不发送 ping 的旧服务器拿到的
   仍是普通 EventSource，旧页面没有 `ping` 监听器、而这个不带 id 的帧也不改动它的 `Last-Event-ID`
   （上游 #1026 移植）。
2. **公司侧栏显示的是当前页面所在的组织。** 公司模式下打开某个组织的页面时，侧栏（工位、频道）可能
   停留在**上一次**打开的组织上：页面写着一家公司，侧栏列的却是另一家的员工，切换组织时看起来像新
   组织没有任何 Session。原因是「没有路由指明组织时采用上次打开的组织」这个判断用的是发起它的那次渲染
   里的值，而组织路由在同一次提交里先执行、shell 看到的仍是「没有」，于是用存储的组织盖掉了路由指定的
   那个。现在这个判断按当下的 store 状态决定：路由的选择优先，只在没有任何组织被指定时才采用存储的
   那个（上游 #824 移植）。
3. **在输入框打字不再带动对话。** 输入框每次按键都会重新计算文本框高度：先收成 `height: auto`，
   再读内容高度——这次读取让页面按变矮的输入框排一次版，上方按剩余空间定高的消息列表随之瞬间变高，
   停在底部的列表被夹到更高视口的底部，高度恢复后滚动位置却没有退回来。草稿只有一两行时，在部分主题
   与字号组合下列表会滑动一个设备像素，回复流式输出期间每次更新把它拉回底部、下一次按键又让它滑开，
   于是打字时列表一直在抖；草稿达到三行及以上时，第一次按键就让列表往回滚动多出的那几行，自动跟随
   把这次跳动当成用户向上滚动，流式回复不再自动滚入视野、「回到最新消息」按钮随之出现。现在仍然收起
   文本框来测量，但测量期间把它的父元素固定在当前高度，输入框以外的布局不受影响；公司频道的输入框
   同样修复（上游 #1052 移植）。
4. **频道保留你还没发出的消息。** 在频道输入框里写了还没发出的文字，过去只活在当前视图里：打开另一个
   频道、某个工位、任何别的页面——或刷新——都会把它丢掉。现在它按用户、项目、组织与频道保存在浏览器里
   （`penguin.channelDraft.…`），与对话里未发送的输入同一口径：回到该频道，文字还在原处；别的频道不会
   继承它；发出消息（或清空输入框）才会结束它。磁盘与服务端什么都不变（上游 #810 移植）。
5. **手机上的频道消息有了足够的宽度。** 手机上公司频道的消息气泡偏窄，时间戳又把文字往左挤，中文每行
   只排得下七个字左右。现在窄屏上气泡最多占列宽的 88%（`sm` 断点及以上仍是 75%），时间戳不再作为正文
   旁边的一栏，而是收在气泡末尾——一行放得下就跟在文字后面，文字需要整行宽度时就单独占一行、靠右、
   贴在最后一行下面；正文在手机上是 `text-base`，`sm` 及以上仍是 `text-sm`（上游 #826 移植）。
6. **智能体面板全屏时，输入区与子会话对话对齐。** 智能体面板把所选子会话的对话排在主对话的阅读列里
   （居中，限宽 `max-w-3xl`），输入区却铺满整个面板：停靠时两者重合，停靠栏全屏后对话仍是居中一列、
   输入区却横贯被覆盖的整行（1440px 窗口下是 768px 的列配 1100px 的输入区，1920px 下输入区宽达
   1616px）。现在输入区与主对话的输入区一样落在对话所在的列内；停靠时的面板没有变化（上游 #1050 移植）。
7. **回复中的波浪号按原样显示，不再渲染删除线。** 回复里的 `~` 多用来表示范围（`3~5 天`）或「大约」
   （`~30 秒`），很少用作删除线；同一段里出现两个时，二者之间的文字会被整段划掉。现在不再渲染删除线：
   `~text~` 与 `~~text~~` 的波浪号按原样显示，夹在中间的内容保留各自的格式。这在 Web App 中凡是以
   Markdown 渲染回复的地方（对话、Trace、插件页、文件预览）都生效，转发到飞书、Telegram、QQ 与微信的
   回复也一样；GFM 的其余部分（表格、任务列表、自动链接、脚注）不变（上游 #1017 移植）。
8. **远程控制的启用开关置灰时，点击会说明先做什么。** 对话的远程控制编辑器里，前序步骤未完成时
   **启用连接**开关仍呈置灰样式，但点击它不再没有反应：点击不会向服务器发出请求，而是把提示行的原因弹为
   提示消息、短暂强调该行，并把焦点移到要补的地方——微信和 QQ 移到扫码区，飞书和 Telegram 移到第一个
   未填写的凭证字段，表单有未保存的修改时移到**保存**按钮；另一个渠道已启用时，提示会点名该渠道，焦点
   保持不动。远程控制文档补充了这一行为（上游 #1029 移植）。
9. **创建组织时在组织的锁内写入目录布局。** 创建组织现在在组织的锁内写入布局——骨架、`org_config.toml`、
   `org_chart.yaml`、手册——并创建 CEO 的 Agent，而删除组织把目录移入回收站时持有的正是同一把锁；
   前置检查仍在加锁前进行。此前一次落在「创建写出第一个文件」与「加锁」之间那几毫秒里的删除能通过自己的
   守卫、把写了一半的目录移走，留下一个任何列表都不显示的目录、一个占着该 id 的 CEO Agent，却给调用者
   一个「未找到」。现在创建进行中到达的删除会等待，随后看到的要么是尚不存在的目录，要么是完整的组织
   （上游 #957 移植）。
10. **白领主题的滚动条常显。** 白领主题是新安装的默认主题，新装的桌面应用也是它。此前在这个主题下，
    滚动条只在指针悬停于滚动区域时才出现，有嵌套滚动区的弹窗（如插件详情及其中的文件预览）看不出哪一块
    还能滚动；现在白领和朴素、极客一样细滚动条始终显示，颜色沿用它自己的浅色与深色滚动条配色
    （上游 #1070 移植）。
11. **沙盒不加限制的文件写入模式改称「完全访问」。** 沙盒设置里不加任何限制的文件写入选项，名称由
    「关闭（完全访问）」（英文 "Off (full access)"）改为**完全访问**（英文 "Full access"）——旧名对
    选项列表来说太长，也没有别处用它，新名正是权限菜单与预设已经在用的那个；该设置的说明与「没有可用
    沙盒后端」的提示也改用同一个名字。已保存的值（`danger-full-access`）不变，只改了显示名称
    （上游 #1021 移植）。
12. **目录里的 Dots3-Note Preview 改用半角括号。** 内置目录把 `dots-3-note-preview` 列为
    **Dots3-Note Preview（Free）**，全角括号沿用自卖方的中文目录，而目录里的模型名不随界面语言翻译，
    于是英文界面里也照样显示成一对贴着字的宽字形。用词仍按卖方的写法，只改标点，与目录里其他带括号的
    名称一致（`Nemotron 3 Ultra (free)`、`Gemini 3.1 Pro (Preview)`）（上游 #996 移植）。

## 升级

桌面端（Windows / Linux 的 AppImage）在应用内更新：账号菜单的更新入口，或应用菜单里的「检查更新」。
默认的镜像源当前不可用，客户端会自动回退到 GitHub Releases；Windows 安装包仍未签名，
SmartScreen 会提示一次（「更多信息 → 仍要运行」）。

服务器 / CLI 装的（tar 包或 npm 全局）用同一条链路，数据根（`~/.adelie/data`）不动：

```bash
penguin update --check     # 看有没有新版
penguin update --yes       # 原地替换 bin/lib/web/node
```

| 产物 | 目标 |
| --- | --- |
| `adelie-desktop-win32-x64.exe` | Windows x64 桌面端（未签名，NSIS 安装器） |
| `adelie-desktop-linux-x86_64.AppImage` / `adelie-desktop-linux-amd64.deb` | Linux x64 桌面端 |
| `penguin-linux-x64.tar.gz` | Linux x64 命令行版（自带 Node 24.18.0） |
| `penguin-win32-x64.zip` | Windows x64 命令行版（自带 Node 与 MinGit） |
| `penguin-universal.tar.gz` | 任意平台（不带运行时，需要 Node ≥ 24） |
| `install.sh` / `install.ps1` | 在线安装脚本（`penguin update` 取的就是它） |
| `latest.yml` / `latest-linux.yml` | 桌面端自动更新读的元数据 |

安装包都在 GitHub Release 上：<https://github.com/lmliheng/Adelie/releases/tag/v0.3.8>，
下载页同样直指这里。npm 上整条链同样是 **0.3.8**：`npm install -g @adelie/cli`。

**存储清理仍是出厂关闭的。** 想用就在设置页「存储」页打开开关，或 `penguin storage mode on`；
不想用就什么都不用做，行为与上一版一致。

  Gatekeeper 拦，所以仍不发 macOS。

  Release 资产都只指向 GitHub，桌面端更新自动回退到 GitHub。等镜像恢复后一行换回即可。
