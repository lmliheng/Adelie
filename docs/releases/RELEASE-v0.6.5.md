# Adelie v0.6.5 —— 输入框会听写了，另七处「点了没反应」的原因留在原地

这一版自 v0.6.4 起在 `main` 上落了 **11 个用户看得见的改动**（其余是每轮的记账）。数据根、配置格式、
包名与既有的请求接口都没有变化；多出来的一组设置（语音输入）没配过的服务器行为与上一版一样。

## 这一版的新东西

### 1. 输入框会听写了

麦克风按钮就在输入框旁边：点一下开始录，再点一下结束，识别出的文字落进草稿框，发送前还能读一遍、改一改。

识别在**服务器**上做，不在页面里。桌面外壳没有 Web Speech API，把识别放进浏览器会让同一个账号在网页版
和桌面版上表现不同；密钥也因此只留在这台服务器上，不随每个打开页面的浏览器下发。用哪个服务识别是
「设置 → 服务器 → 语音输入」里的一项，管理员配一次，所有人就能用麦克风：

| 地址 | 端点 |
|---|---|
| `https://tokendance.space`（默认） | `wss://…/gateway/alibaba/api-ws/v1/inference` |
| `https://dashscope.aliyuncs.com` | `wss://…/api-ws/v1/inference` |

两家说同一套协议、用同一个模型 `qwen-audio-3.1-asr-flash-streaming`，区别只在地址。密钥是只写的：
设置页读回来的是「有没有存过」，管理员只改模型时不必重新贴一遍。没配过的服务器上，麦克风按钮会说还没有
配识别模型，并指向设置页。

真服务发完 16 秒语音会看到一件事：**同一句话会来很多次**。服务还在识别时就带着同一个 `sentence_id`
再发一遍、多出几个字（`"呵" → "呵我" → "呵，五岳剑派，哎呀呀" → …`，一次十几二十回），而且从头到尾
没有一帧把 `sentence_end` 置真。所以转写按句子编号覆盖、各句按首次出现的顺序相接，不逐帧拼接、也不等
那个收尾标志——第一版按后者写的话，一个字都拿不到。

### 2. 麦克风拿不到时，说的是真原因

原来只有一句「请检查浏览器或系统的麦克风权限」，可用户最常撞上的那一种恰恰是**没有权限可给**的：浏览器只在
https 或 localhost 下才把麦克风交给页面，`http://<某台机器的地址>:7777` 不在其列，那里
`navigator.mediaDevices` 根本不存在，连权限框都不会弹。现在先判后问，四种情况四句话——地址不是安全上下文
（悬停提示给三条出路：用桌面版、让 Adelie 走 https、或临时把这个地址加进浏览器的 flag）、浏览器不支持、
权限被拒过、没有设备或被别的程序占着。

设置页多了「测试连通性」：对服务跑一遍完整任务（开 task、半秒静音、收尾），验的是屏幕上那三个框而不是已存的
配置，保存成功后也自动跑一次，所以「配好了却连不通」不会留着不说。握手失败时——错密钥、域名不存在、路径不是
端点，在 WebSocket 那层长得一模一样——会拿同一份凭据对同一地址再发一次普通 HTTP 请求：401 报「密钥被拒」，
不再是笼统的「连不上服务」。

### 3. 浏览器版 VS Code 可以一次装好

新增插件 `@adelie/web-vscode`：装完就是能用的样子——`code-server` 只监听回环，HTTPS 反代终结 TLS 并直通
WebSocket，站点证书由本机 CA 签发，安装器自己等到健康检查通过。SKILL.md 附 Windows / macOS / iOS / Android
的证书信任步骤与三项验收；`reference/` 记下那些看着像「装坏了」的坑（点「继续前往」救不了 webview、受限模式
把 `.ipynb` 打开成 JSON、6665–6669 是浏览器危险端口）。

顺带修了它的卸载：此前按固定单元名 `disable` 并删除，同机另一份安装（或手工维护的入口）会被一次 `--prefix`
清理带走。现在先读单元文件的 `ExecStart`，不属于这个 prefix 的跳过并提示，比较时按「后一个字符不是路径字符」
判定，`/opt/web-vscode` 不会命中 `/opt/web-vscode-proxy`；安装侧遇到别人的同名单元拒绝覆盖，要覆盖得显式
加 `--force`。

## 另外七处：点了没反应，是因为原因只活了六秒

这七页都不做乐观写入——被拒之后表单、开关、卡片一个字都不变，于是「为什么」是唯一能说明这颗按钮被按过的
东西；而它此前只在一条六秒的通知里。现在每一处都把服务端的原话画在发起动作的那个控件旁边，留到下一次同一种
写为止：

4. **员工手册保存被拒**——原因画在标题行与文本框之间；草稿与文件不同时一并说「编辑器里的改动没有写进文件」。
5. **插件导入被拒**（上传插件 / 远程下载）——原因画在发问的那个对话框的来源字段下面；409 同名仍进覆盖确认。
6. **文件面板保存被拒**——原因画在标题行与编辑框之间，带着文件路径、只画在它所属的那份草稿上。
7. **文件面板上传被拒**——原因画在列表上方：整批没上去只说原因，半途卡住时点名没上去的那几个。
8. **插件库「装入插件库」被拒**——原因画在那一行下面，且在链接之外，点它不会被带去 registry 页。
9. **插件装不到某个 Agent 上**——原因画在那张插件卡片里，并点名是哪个 Agent 没装上。
10. **沙箱后端的安装没落地**——对话框留着，原因画在它自己的问题下面，并且只提供还缺的那些包：它的「安装」
    按钮就是重试，重试不会把已装好的再装一遍（每次安装都会重新装载插件、中止正在进行的 Agent 运行）。

## 兼容

- 请求、响应与磁盘格式都没有变；没有删任何接口，也没有新增环境变量。
- 多一组部署级设置（语音输入），与其它设置一样按 KV 行存放。没配过它，麦克风按钮只提示去设置页。
- 在一台走 http 的部署上用麦克风，需要那个地址被浏览器当成安全上下文（https、localhost，或浏览器里那条
  flag）——这是浏览器的规矩，不是这个页面的选择；桌面版跑在 localhost 上，不受影响。

## 升级

**桌面端**在应用内更新：账号菜单的更新入口，或者应用菜单里的「检查更新」。Windows 安装包仍未签名，
SmartScreen 会提示一次（「更多信息 → 仍要运行」）。

**命令行与 Web**：`penguin update`（或重装 `npm install -g @adelie/cli`）。npm 上的包都到了 0.6.5。

## 安装

```bash
curl -fsSL https://github.com/lmliheng/Adelie/releases/latest/download/install.sh | sh
```

```powershell
irm https://github.com/lmliheng/Adelie/releases/latest/download/install.ps1 | iex
```

也可以只装 CLI：`npm install -g @adelie/cli`（需要 Node.js >= 24）。

## 要求

- Node.js >= 24（单行安装脚本自带运行时，npm 安装需要本机有）。
- Linux / macOS / Windows 的 x64 与 arm64；其他 POSIX 平台用 `--universal` 安装包。
- 桌面端：Linux 提供 AppImage 与 deb，Windows 提供 exe；macOS 未签名，这一版不随 Release 发布。

上一版（v0.6.4）把七处被拒的原因从六秒的通知里搬到了控件旁边。文档在
<https://lmliheng.github.io/Adelie/docs/>。变更明细见仓库里的
[`CHANGELOG.zh.md`](https://github.com/lmliheng/Adelie/blob/main/CHANGELOG.zh.md)。
