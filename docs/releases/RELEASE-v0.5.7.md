# Adelie v0.5.7 —— 模型库多了火山方舟，对话里能发视频、也能看视频

这一版自 v0.5.6 起在 `main` 上落了 **15 笔提交，其中 7 个用户看得见的改动**（其余是每轮的记账）。
数据根、配置格式、包名与既有 HTTP 接口都没有变化，装好的机器升级后不用改任何配置。

## 这一版改了什么

1. **模型库多了一个分组：火山方舟（字节跳动的平台）。** 排在讯飞后面，收进方舟自己服务的十一条模型：
   豆包 Seed 家族七条，加上方舟转售的四条（GLM、Kimi、两条 DeepSeek）。Project 用「同步预置」或下一个
   新 Project 就能拿到。整个分组是一个 OpenAI 兼容端点，把方舟控制台的 API key 贴进分组抬头就通，
   不用挑协议、不用填地址。十一条里**七条能吃视频**（六条豆包 Seed 加转售的 GLM-5.3-Flash），
   卡片上标着「视频」。

2. **对话里能发视频了，模型也能看。** 输入框的「+」菜单多一项**上传视频**，片子也能拖进来或粘贴。
   发送前它是一张带首帧、文件名与体积、可移除的卡片；发送后它是对话里一段能播、能全屏的视频。
   片子怎么走**由服务端判断，不问你**：这一轮的模型**能看视频**，它就是随本轮请求送上去的一个视频部分，
   模型可以直接描述它、总结它、回答画面里的问题，中间不用多一步；模型**不能吃视频**也不会被拒——
   片子落进会话草稿区，消息里带一行 `[attached file: …]`，和附件一样，让 Agent 用自己的工具打开。
   历史页里的视频**按引用取回**（一条视频是几十兆的 base64，整份返回会把页面拖死），刷新之后照样能播。
   内联的视频上限 32MB，超出会明说原因。

3. **顺带修掉一处「两边说法不一样」。** 内联还是落成文件，本来有两处各自判断：输入框看它手上的模型，
   任务与转向两条路由只看内置目录。于是手工在 Project 里把某个目录外的模型标成能收视频时，输入框给了
   视频入口，服务端却一声不响把片子落成了附件。现在两边读同一份答案（先看 Project 条目，再退回目录）。
   `packages/server/test/video-input.test.ts` 加了这两条用例，并配了一条真浏览器用例从头走完这条路。

4. **插件库多了出片技能，Agent 能产出视频。** 内置插件 `use-seedance` 把火山方舟的豆包 Seedance 接了
   进来：跟 Agent 说清要什么，它提交任务、轮询、把生成的 mp4 下载到工作区再交给你。这是 Adelie 第一个
   **产出视频**的能力——模型库里那十一条方舟条目负责看得懂视频，这个插件负责做得出来。视频按秒计费，
   所以 Agent 提交前会把提示词跟你对一遍。缺的只是一把钥匙：方舟控制台领的 API key 加到这个 Agent 的
   密钥库，键名 `ARK_API_KEY`。

5. **两枚品牌图标补上。** 火山方舟与 Abliteration 换上各自的标志（取自厂商自己的站点、压成单色、去掉
   字标与底板），模型库与模型选择器不再给它们画一个字母方块。

6. **「被拒的原因留在框里」这条线铺到工单与财务。** 公司页剩下的四处一并改掉，做法同前几版：只有写成功
   才关框，被拒就把服务端那句话画在句子下面、重试按钮旁边；重开不带上一次的旧原因，写入在途时连点也只
   认一次。四处是：新建工单（十个字段原样留着）、工单的保存 / 解除阻塞 / 移动、标记阻塞（原因留着）、
   财务页的行内预算（金额与原因留着）。

7. **主题能在界面上导入。** 设置 › 外观 里，管理员多一个「导入主题…」：选一个 `.json` 文件上传，或者
   填一个地址让服务端取回来。导入与手放文件没有区别——写的还是数据根 `themes/` 里的同一个文件，校验用
   的还是同一个读法；同名主题再导一次是覆盖（先问一句），读不出来的文件一个字节都不写，并把读法的原话
   带回来。

## 兼容

- 这一版开始，`pnpm install` 会应用一处补丁：`patches/@prismshadow__agenthub.patch`，给外层的
  AgentHub 补上 `video_url` 这种内容部分（上游还没有），因此视频才能作为一个部分发出去。包本身仍是
  发布的 `@prismshadow/agenthub@0.4.15`，补丁按版本钉住——上游一升版，pnpm 会报错而不是悄悄丢掉它。
  视频**不重新编码**，按原始数据 URL 传，所以一条片子就是几十兆的 base64，这就是上限与「每次只带一条、
  更早的换成一行说明」的由来。
- 服务端接口只增不改：老的输入部分、老的转向请求体照旧；不吃视频的模型拿到的仍是一条普通附件消息。
- 「被拒的原因留在框里」只改了「什么时候关框」与「原因画在哪」，没有新文案，除既有的前缀。

## 升级

**桌面端**在应用内更新：账号菜单的更新入口，或应用菜单里的「检查更新」。Windows 安装包仍未签名，
SmartScreen 会提示一次（「更多信息 → 仍要运行」）。

**命令行与 Web**：`penguin update`（或重装 `npm install -g @adelie/cli`）。npm 上 26 个包都到了 0.5.7。

## 安装

```bash
curl -fsSL https://github.com/lmliheng/Adelie/releases/latest/download/install.sh | sh
```

```powershell
irm https://github.com/lmliheng/Adelie/releases/latest/download/install.ps1 | iex
```

也可以只装 CLI：`npm install -g @adelie/cli`（需要 Node.js >= 24）。

## 要求

- Node.js >= 24（单行安装脚本自带运行时，npm 安装需要本机有）。
- Linux / macOS / Windows 的 x64 与 arm64；其他 POSIX 平台用 `--universal` 安装包。
- 桌面端：Linux 提供 AppImage 与 deb，Windows 提供 exe；macOS 未签名，这一版不随 Release 发布。

上一版（v0.5.6）把公司页剩下九处「被拒的原因留在框里」铺完，插件库收进画图技能
`use-lieflat-charts`（六十几套图型，能直接产出可交互的 HTML 图表）。文档在
<https://lmliheng.github.io/Adelie/docs/>。变更明细见仓库里的
[`CHANGELOG.zh.md`](https://github.com/lmliheng/Adelie/blob/main/CHANGELOG.zh.md)。
