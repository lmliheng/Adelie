# Adelie v0.6.1 —— 写入被拒绝时，原因留在被点的那一处，不再是一条六秒就消失的提示

这一版自 v0.6.0 起在 `main` 上落了 **10 个用户看得见的改动**（其余是每轮的记账与测试整理）。
数据根、配置格式、包名与既有的请求接口都没有变化，装好的机器升级后不用改任何配置。

整版只有一个主题：**「点了没反应」这种时刻，屏幕上要留下说法。** 界面上有一批开关与按钮不做
乐观写入 —— 状态要等服务端点头之后才动；这本身是对的，可一旦服务端拒绝，按钮就停在原地、什么都不
变，而原因此前只有一条 toast，六秒之后自己消失。用户看见的便是一颗点了没动的按钮，和一句已经
看不见的解释。这一版把这些话留在**发起动作的那一处**：被点的那一行、那个框、那颗开关下面。

## 这一版改了什么

1. **定时任务的启用开关被拒时，原因留在那一行下面。** 「定时任务」页与对话停靠栏里的定时任务
   面板共用同一行，两处同时生效。两个 Agent 可以有同名任务，所以只有被拒的那一行画出这句话，
   旁边那一行一个字都不加；下一次翻转会把它清掉，它是那一次点击的答复，不是这一行的长期状态。

2. **Agent 设置页「定时任务」tab 的启用 / 停用被拒时，原因留在那一行的状态徽标下面。** 这是同一
   件事的第三处列表（它用的是按钮与表格）：此前被拒时表里什么都不会变，按钮不动、徽标不动，只剩
   一条会消失的提示。

3. **「远程控制」的连接开关被拒时，原因留在开关下面。** 这里的失败恰恰都是用户要据此动作的那几
   种：另一个对话已经占用这个机器人、凭证还没保存、连接断了。编辑器的两个宿主（侧栏弹窗与对话内
   的面板）共用同一份正文。

4. **MCP Server 表的开关被拒时，原因留在那一行下面。** 同一族里的第四处。

5. **「用 AI 生成 ID」被拒时，原因写在 ID 框下面。** 项目、Agent、Benchmark、组织、渠道五个创建
   对话框共用同一个 id 字段，因此五处一起生效。它与「这是占位」「这是按名称转写」的说明占同一个
   位置 —— 一次编辑或下一次点击就清掉。

6. **主题导入被拒时，对话框与被点的那张卡片各自留住原因。** 外观页有对话框（选文件或给地址）与
   主题库卡片两层入口：对话框本来就会在失败时留着（选好的文件、敲好的地址都还在，按同一个按钮
   就是重试），缺的只是原因；卡片那一层，被拒的导入让每张卡看起来都和点之前一样，屏上不止一张卡
   时那条提示甚至没说是哪一张。现在只有被点的那张卡画这句话。「主题已存在」仍是唯一一种去问
   「要不要覆盖」的答复，两处判定收成了一处。

7. **给模型分组「从用户密钥分配」被拒时，密钥列表不再被顶掉。** 写失败时对话框此前会用原因
   替换整块内容 —— 勾好的那条、以及能改勾的其余几条一起消失，只能先取消再重来。现在原因排在
   列表上方，勾选原样留着，「确认」就是同一次重试（那次拒绝本来就没写下任何东西）。

8. **换模型的确认框，正文跟着「压缩失败就直接切换（放弃摘要）」那个勾选框走。** 勾上之后，框
   里此前仍写着「压缩失败则保持『当前模型』」—— 与紧挨着的勾选框、以及接下来真正发生的事正好
   相反。现在勾上就写明「压缩失败则放弃摘要，直接以目标模型继续」。换模型本身的行为一个字节没改。

9. **导入的深色主题不再留白色色带。** 界面里还有六百多处直接写死的浅色类，自带的主题靠重新声明
   灰阶让它们跟着自己走，导入的主题此前做不到 —— 深色主题里卡片是暗的，同一行的底色、边线和字
   却还是浅色，字几乎看不见。现在生成导入主题的样式表时，把它自己声明过的颜色值按同样的对应
   关系接到灰阶上；只接真的声明过的那些，避免默认主题的别名绕成循环。

10. **满载跑测试时，几处扫描源码的用例不再被超时判红。** 这条只影响开发者：机器忙的时候跑整轮
    测试，web 包里几个扫全仓源码的用例会撞上 5 秒默认超时、单独跑又全过。超时放宽到 30 秒，
    断言一个字没动。

## 兼容

- 请求、响应与磁盘格式都没有变；这一版**没有新增任何接口**。失败那条路从 toast 改成了留在原地的
  一句话，成功路径与界面上其它地方一字未改。
- 新装的机器与升级的机器都不需要改配置；数据根一个字节没动。

## 升级

**桌面端**在应用内更新：账号菜单的更新入口，或者应用菜单里的「检查更新」。Windows 安装包仍未签名，
SmartScreen 会提示一次（「更多信息 → 仍要运行」）。

**命令行与 Web**：`penguin update`（或重装 `npm install -g @adelie/cli`）。npm 上的包都到了 0.6.1。

## 安装

```bash
curl -fsSL https://github.com/lmliheng/Adelie/releases/latest/download/install.sh | sh
```

```powershell
irm https://github.com/lmliheng/Adelie/releases/latest/download/install.ps1 | iex
```

也可以只装 CLI：`npm install -g @adelie/cli`（需要 Node.js >= 24）。

## 要求

- Node.js >= 24（单行安装脚本自带运行时，npm 安装需要本机有）。
- Linux / macOS / Windows 的 x64 与 arm64；其他 POSIX 平台用 `--universal` 安装包。
- 桌面端：Linux 提供 AppImage 与 deb，Windows 提供 exe；macOS 未签名，这一版不随 Release 发布。

上一版（v0.6.0）让点开的图片有一整条工具条、模型分组的 key 能直接从用户密钥分配。文档在
<https://lmliheng.github.io/Adelie/docs/>。变更明细见仓库里的
[`CHANGELOG.zh.md`](https://github.com/lmliheng/Adelie/blob/main/CHANGELOG.zh.md)。
