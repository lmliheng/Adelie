# Adelie v0.6.8 —— 被拒的原因都留在原地，另外多了三件查账与省钱的工具

这一版自 v0.6.7 起在 `main` 上落了 **16 个用户看得见的改动**（其余是每轮的记账）。没有删除任何功能，
数据根、配置格式与既有接口都没有变；升级不需要做任何事。

## 这一版的新东西

### 1. 命令策略页：保存被拒时说出仍在执行哪一份，规则表满了会说上限

那一页把整个 `[command_policy]` 块（总开关加每一条规则）先攒在界面里，一次保存整块发出去。被拒的时候
界面停在「已经改了」的样子，而引擎跑的还是旧的：刚把拦截关掉的人以为什么命令都不拦了，刚加一条 deny
的人以为它已经在管。

原因现在画在保存按钮那一行，并点明项目此刻仍在执行什么——如果这次连总开关一起动了，就说清生效的仍是
原来那档（拦截开着/关着，外加最后一次保存下来的规则）；只动了规则表，就说存储里的策略一个字节没变。
不往上摞一行：规则表自己就会撑满对话框的滚动区，一句话压在上面，正好把重试按钮挤出视野。

规则表加满时也一样：达到上限的那一下，页面直接说出这是上限，「添加规则」按钮同时收起来，省得再点一次
只换来一句「加不进去」。

### 2. 批量归档只成功一半时，说清哪些对话没有动

侧栏的批量条没有批量接口，批量归档与批量取消归档是每个打勾的对话发一条请求。以前结果当成一个整体读，
一条被拒就把其它行的答复一起丢掉：已经归档进去的行还挂在原来的位置，已归档文件夹没有出现，勾也全留着，
原因只在那条六秒后自己消失的通知里，底下的列表看起来一点没动。

现在两种动作都逐行读结果（删除那一支一直是这么做的）：落地的行按服务端的样子挪进已归档文件夹，被拒的
行保持打勾——它们正是重试会作用到的那些——批量条上留着「还剩几条」与服务端自己的原话。那两颗按钮就是
重试，所以句子放在条上：这两个动作都不先问一句，没有卡片可以留。

### 3. 另外九处「被拒的原因只活六秒」，也搬到了发问的地方

从 v0.6.5 起一直在做同一件事：一次写入被服务端拒掉时，界面一个字都不变，于是「为什么」是唯一能说明
这颗按钮被按过的证据——而它此前只在页面顶部一条六秒后自己消失的通知里。这一版又收了九处：

- **新建对话的默认值一次保存写两处**（那一块设置，然后是项目的默认模型）。后一半被拒时，前一半可能已经
  落地了；原因画在控件下面，并点明落的是哪一半：「默认值仍是旧的」「默认值已保存、模型没有」。每一次尝试
  都先清掉上一句，保存按钮就是重试。
- **成员的写入被拒**——原因留在表上方，说清这次改的是哪一位、哪一项没被接受。
- **结束一个终端被拒**——以前列表先把那一项删了再等回音，拒绝之后屏幕上显示「已结束」而进程还在跑，而且
  一句话都没有。现在拒绝时把它放回去、重读列表，原因留在确认卡片里，标签与窗口都还在，卡片上那颗按钮
  就是重试；只有结束真的落地了，标签才离开。
- **会话里换模型被拒**（忙、目标模型没了或不可用、压缩没配置）——卡片不再一按就关，原因留在卡片里，
  旁边就是重试同一件事的按钮，会话仍跑在旧模型上。
- **错误中心的两张卡（清除、忽略）被拒**——原因留在卡片里，卡片不再关掉重开成「什么都没发生」的样子；
  重开时是干净的。
- **子会话的思考等级钉不住**——选择器改成写入落地之后才采用点中的那一档（主输入框两个选择器早就是这么
  做的），原因留在它输入框上方。
- **快捷键没能从账号读出来**——这个键位表在任何请求回来之前就已经存在，行上读的是浏览器镜像；读取被拒
  时镜像留在原地而一句话没有，重绑一次就可能把账号里还有的覆盖掉。原因现在画在设置页顶部那几行上方
  （一次 PUT 带整份文档，没有哪一行说得清）。
- **快捷键没能保存到账号**——同上，一次编辑先写浏览器镜像，拒绝后那一行还显示账号没听过的组合，下次
  加载又被账号里的那份盖回去，改动凭空消失。原因同样在设置页顶部，下一次尝试、一次成功的水合或换账号
  时清掉。
- **文件夹删不掉**——确认卡片会写明服务端的规矩（只有空文件夹能删），以前两种答复都会把卡片关掉；现在
  只有删除落地才关，拒绝时卡片站着，原因在同一个按钮上方，把里面的东西清掉再按一次即可。

### 4. 实时流一个字节都收不到时，页面不再停在原地

连接握手成功、响应体却始终不来（中间的代理或 NAT 把它吞了），客户端唯一的存活判断要等第一个心跳才武装，
于是一条心跳都没送到的连接根本没人管：页面停在原地，服务端明明在跑的活看起来像卡死的智能体。

现在两种失败各有期限：30 秒一个事件都没有的连接按「开着但没通」重开，连着三条就判定为停止，不再立刻
重开、每分钟试探一次并告诉页面；页面随即靠定时重取历史保持最新，并在对话框上方说明，第一个送到的帧把
这一切清掉。

配套的「传输」视图也从这一版起**默认就在录**（只留在本页内存、最多 300 条）：会话还没有任何轨迹文件、
「暂无轨迹」的空态里也照样显示这一行。真正想问「实时流到底有没有把东西送来」的时候，从点开开关那一刻
才开始录的帧，恰恰就是已经错过的那批。

### 5. 左下角菜单能看到此刻在跑的会话，也能按天查花了多少 Token

账号菜单顶上新列了正在跑（或正在压缩）的对话，点一下就进去；下面新增「会话运行记录」，先看今天的合计，
按天展开能看到每个对话占了多少 Token、多少钱、多少次请求。

侧栏的会话列表是按 Agent、分类分页拉的，看不到「全项目在跑」，所以服务端补了一条项目级查询；运行记录
按「天 × 会话」一次算出来，标题在服务端补齐。菜单关着时不发任何请求，开着时跟着会话状态事件刷新。

### 6. 「用 AI 生成 id」不再花你的钱

以前它走项目配置的默认模型，而新建项目默认种的是付费的 deepseek-flash——一个只是给项目起个 id 的动作，
也要按用户自己的 key 花钱（它不挂会话、不进成本中心，但厂商那边是真扣的）。

现在只找项目里三个价格桶都为 0 的免费模型，按配置顺序最多试 4 个、合计不超过 30 秒，默认模型不再参与，
所以生成 id 永远不会花钱。免费端点常被限流和下线，一个不回答就换下一个；构造不出来的条目直接跳过。
项目里没有能用的免费模型时，退到名称的 ASCII 转写或带日期的占位 id，原因码从 `no_default_model` 改成
`no_free_model`。

## 兼容

- 没有删除任何页面、路由或环境变量；没有新增环境变量。
- 数据根、配置文件格式、请求与响应都没有变化。
- 界面新增的只有几处「原因」槽位、两个菜单区块与一个默认开着的「传输」视图；它们不动既有用法。
- 行为上唯一需要知道的两点：生成项目 id 不再调用付费模型（没有免费模型时改用名称转写）；
  会话运行记录是只读查询，不写任何东西。

## 升级

**桌面端**在应用内更新：账号菜单的更新入口，或者应用菜单里的「检查更新」。Windows 安装包仍未签名，
SmartScreen 会提示一次（「更多信息 → 仍要运行」）。

**命令行与 Web**：`penguin update`（或重装 `npm install -g @adelie/cli`）。npm 上的包都到了 0.6.8。

## 安装

```bash
curl -fsSL https://github.com/lmliheng/Adelie/releases/latest/download/install.sh | sh
```

```powershell
irm https://github.com/lmliheng/Adelie/releases/latest/download/install.ps1 | iex
```

也可以只装 CLI：`npm install -g @adelie/cli`（需要 Node.js >= 24）。

## 要求

- Node.js >= 24（单行安装脚本自带运行时，npm 安装需要本机有）。
- Linux / macOS / Windows 的 x64 与 arm64；其他 POSIX 平台用 `--universal` 安装包。
- 桌面端：Linux 提供 AppImage 与 deb，Windows 提供 exe；macOS 未签名，这一版不随 Release 发布。

上一版（v0.6.7）把最后六处「被拒的原因只活六秒」收尾，并让三处后台噪音记进错误中心。文档在
<https://lmliheng.github.io/Adelie/docs/>。变更明细见仓库里的
[`CHANGELOG.zh.md`](https://github.com/lmliheng/Adelie/blob/main/CHANGELOG.zh.md)。
