# Adelie v0.5.10 —— 文件面板能直接读 Word 和 PDF，回复里的图点一下看全图，外观页多了个装主题的地方

这一版自 v0.5.9 起在 `main` 上落了 **34 笔提交，其中 14 个用户看得见的改动**（其余是每轮的记账与
测试）。数据根、配置格式、包名与既有的请求接口都没有变化，装好的机器升级后不用改任何配置。

## 这一版改了什么

1. **文件面板里的 Word 与 PDF 能直接看了。** 点开一个 `.docx` 以前只有一句「该类型不支持预览」，
   而 Word 与 PDF 恰恰是最常交给 Agent 的两类文档。现在 Word 由服务端解析成 Markdown 再显示
   （`.docx` 就是装 XML 的 zip，不需要机器上装 Office），PDF 由应用自己逐页画到画布上 —— 桌面端、
   任何浏览器、没装 PDF 插件的机器看到的都一样，不会再有「一块空白，分不清是文件坏了还是阅读器
   不在」。旧版 `.doc` 会提示另存为 `.docx`，读不出来的 `.docx` 直接说读不出来。

2. **回复里的图片从工作区取，点一下能看全图。** 模型写图片和写 README 一样（`![](shot.png)`，
   相对它工作的那个工作区），而会话以前把地址照原样渲染，浏览器把它当成 App 自己的路由，于是回复里
   每一张工作区图片都是坏图 —— 要看见自己刚生成的图只能去文件面板。现在会话里的图片与链接走同一套
   判断：指向工作区文件的从这个会话自己的文件路由取（在别的机器上的会话照样路由到那台机器），指向
   别的站点的原样保留。图片按阅读栏宽度缩放，想看细节点一下就开着同一个大图浮层（Esc 关、回车
   在原尺寸打开）。回复之外的每一处 Markdown 界面 —— README、手册、记忆、文件预览 —— 保持静止不动。

3. **Agent 能生成图片了。** 此前只能出视频：方舟的图像生成不是对话模型，进不了模型库，也没有对应
   插件。新增的 `use-seedream` 把一句话变成落在工作区的一张图，支持参考图（最多 14 张）、组图
   （一次最多 15 张）、图层拆分（底图加最多 16 个透明图层）与透明底。它需要火山方舟的密钥，并且账号
   要在方舟控制台开通 Seedream。

4. **外观页多了一个「主题库」，装别人的主题不用再去找文件。** 以前想要一套别人做的主题，只能把 json
   放进数据根，或者由管理员上传文件、填地址。现在外观页下面是一排来自远端目录的卡片，点「导入」，
   服务端取回那份文件、按同一套规矩校验、写进本机主题目录；装过的标「已安装」，再点一次先问要不要
   覆盖。目录本身是独立的仓库与 npm 包，以后加主题只是往仓库里放一个文件，不用改 Adelie。服务端默认
   从 npm 镜像读目录（它对新包要等同步），第一个地址不通时自动换到 jsDelivr 的副本；自建镜像可以设
   `ADELIE_THEME_REGISTRY`。（卡片本身的字号这一版也收进了字号阶梯。）

5. **模型没额度了，也能在这次对话里换掉它。** 切换模型的第一步是让当前模型把上下文压成摘要，而这次
   摘要请求也发到当前模型上 —— 于是整个模型不可用（额度用尽、凭据失效）时，会话卡在它上面，而会话内
   换模型又是唯一能改变当前模型的手段。现在会跑压缩的那次切换，确认框里多一个默认不勾的复选框：压不动
   时放弃摘要、直接带着上下文里的纯文本切到新模型。丢上下文是用户的选择，所以不做成静默行为。

6. **同时派发多个子智能体时，每个孩子挂在自己的那张卡上。** 以前子会话按位置绑到「最近一张已放行、
   还没有孩子、还没完成的卡片」上，于是会挂到别人的卡片：借的是另一个调用的描述与思考等级回落，
   转写区的芯片也指着另一条对话。现在由孩子的第一条模型消息（就是派发它的调用交给它的开头提示词）
   来定归属。元数据缺失导致无从分辨时，按位置的绑定照旧。

7. **取消一次输出，上游请求当场停。** 调用方在响应结束之前就不再读流时，过去既不中断那次请求、
   也不关上游迭代器：供应商继续往没人读的流里生成并继续计费，连接挂到它自己写完为止。现在清理
   尽力而为 —— 已经报过结束的响应一个字不动。

8. **目标模式的额度算的是整轮，不再漏掉轮中压缩之前的部分。** 停止钩子过去只读最新一个 Trace
   分片，一轮中途压缩换了日志之后，这一轮已经花掉的额度留在旧分片里：一轮用了 110 个 token、预算是
   100，却被记成 20 并继续跑，收尾那一轮永远不开始。现在会往前翻到这个 Session 前面几个分片，
   一直数到这轮自己的输入为止；分片缺失、读不了或属于别的 Session 就停下，用手上已有的数。

9. **桌面端「检查更新」每次都真的去问源。** 以前只要查到过一次新版本，之后每次点都只是把那个版本
   再念一遍，云端随后发了更新的版本，界面上却一直是旧的，只能等重开应用。现在菜单、更新弹窗与每六
   小时的定时检查都重新读源：查到更新的就换掉手上这条提示，查到已是最新就撤掉它。正在下载、已有安装
   包在等重启、或另一个检查在路上时，仍然不去打扰。

10. **把平台推送到一个更旧的运行时上不再被拒绝。** 运行时发货之后才加进配置的成员（`penguinGoOrigin`）
    过去被当成平台声明的必备项，于是每一个比它旧的已装运行时都拒绝握手 —— 兼容的平台推不上去，而每次
    被拒的推送还可能顺手把服务重启一遍。现在这类成员在服务端配置里是可选的，由用到它的那一侧给默认值。

11. **分叉对话被拒时，原因留在框里。** 以前按「确认」先把框收起、再发请求，分叉没成时唯一的告知是
    一枚六秒后自己消失的提示，浮在已经不在的框上方，而对话本来也没变。现在对话框由这次请求的结果
    决定去留：请求落地之前一直开着，成了才收起，没成就留着并把服务端自己的那句话画在框里。

12. **内置浏览器「清除浏览数据」被拒时，原因留在卡片里。** 卡片本来就会在失败时留着，丢的是原因：
    它落进一条几秒后自己消失的提示，卡片照旧只说「选择要删除的数据」。现在拒绝的原话画在卡片自己
    那句话下面，紧挨着重试它的那个按钮，勾好的种类原样留着。

13. **取消的消息流当场停住，缓存里的事件不再交付。** 流式读取只在拉到下一个数据块之后才看取消信号，
    而在生成器挂着的时候发生的取消，要等到下一块到达才被发现 —— 当前块里已经解析出来的事件照样交付，
    跟在最后一条事件后面的结束标记更会把这次读取平静地收尾，于是已经取消的那一次被报成「已完成」。
    现在每交付一条事件就检查一次信号。流已经正常结束之后才来的取消，仍不会撤销它。

## 兼容

- 只多了一个可选请求字段（会话内换模型的 `onCompactionFailure`）、一个插件包（`@adelie/use-seedream`）、
  一条可选环境变量约定（`ADELIE_THEME_REGISTRY`）与一条 UI 约定（主题库卡片；对话里的图片可点开
  大图）。既有的请求、响应与磁盘格式都没有变。
- 新装的机器与升级的机器都不需要改配置；数据根一个字节没动。

## 升级

**桌面端**在应用内更新：账号菜单的更新入口，或者应用菜单里的「检查更新」。Windows 安装包仍未签名，
SmartScreen 会提示一次（「更多信息 → 仍要运行」）。

**命令行与 Web**：`penguin update`（或重装 `npm install -g @adelie/cli`）。npm 上 27 个包都到了 0.5.10。

## 安装

```bash
curl -fsSL https://github.com/lmliheng/Adelie/releases/latest/download/install.sh | sh
```

```powershell
irm https://github.com/lmliheng/Adelie/releases/latest/download/install.ps1 | iex
```

也可以只装 CLI：`npm install -g @adelie/cli`（需要 Node.js >= 24）。

## 要求

- Node.js >= 24（单行安装脚本自带运行时，npm 安装需要本机有）。
- Linux / macOS / Windows 的 x64 与 arm64；其他 POSIX 平台用 `--universal` 安装包。
- 桌面端：Linux 提供 AppImage 与 deb，Windows 提供 exe；macOS 未签名，这一版不随 Release 发布。

上一版（v0.5.9）让主题能看见颜色再挑、成本中心的异常能整条复制走，并修掉了流式输出时向上滚被拽回
底部。文档在 <https://lmliheng.github.io/Adelie/docs/>。变更明细见仓库里的
[`CHANGELOG.zh.md`](https://github.com/lmliheng/Adelie/blob/main/CHANGELOG.zh.md)。
