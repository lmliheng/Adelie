# Adelie v0.8.5 —— 大附件的上传有了进度，打不开的原因留在原地

附一个大文件发送时，页面不再从头到尾一声不吭：右下角会出现一张进度卡片，写着已经发出多少、总共
多少。文件面板和工作区选择器打不开东西时，那句原因留在原地，不再跟着六秒的通知一起消失。长任务
结束后，回复下方那条多余的「智能体 + 短 id」行也没了。这一版都改在 Web 端，服务端自 v0.8.4 以来
没有改动。

## 安装

**已经装过的人**：桌面端在应用内更新（账号菜单的更新入口，或应用菜单里的「检查更新」）；命令行与
Web 用 `penguin update`，或重装 `npm install -g @adelie/cli` —— 两者都需要 Node >= 24。npm 上的包都
到了 0.8.5。Windows 安装包仍未签名，SmartScreen 会提示一次（「更多信息 → 仍要运行」）。

**全新的机器**，单行脚本：

```bash
curl -fsSL https://github.com/lmliheng/Adelie/releases/latest/download/install.sh | sh
```

```powershell
irm https://github.com/lmliheng/Adelie/releases/latest/download/install.ps1 | iex
```

## 亮点

**大文件附件的上传有了进度。** 附一个 177MB 这样的文件发送时，页面原先从头到尾没有任何读数 ——
输入框只是被禁用，慢链路上就是几分钟看着像卡住。原因是附件跟着这一次的请求正文一起发（base64 编码，
177MB 在线上约 236MB），而发它的浏览器接口没有上传进度事件。现在这一个请求改走能读进度的那条路，
读数画在右下角的进度卡上：标题、一根实心进度条，以及「已发出 / 总共」两个字节数；发送一结束
（成功或失败）就自动收起，几百 KB 的小消息不会出现这张卡。

**打不开的原因留在原地，不再六秒就消失。** 文件面板里点「编辑」，若文件超过上限或读不出来，原因
原先只挂在一条六秒的通知上，手一慢就看不见了；现在它留在预览上方，直到你再次尝试。工作区选择器里
填了一个进不去的路径也是同理：那句原因留在地址栏下面，输入框带着你刚填的路径回来、整条选中，改一个
字就能重试。

**长任务结束后，回复下方那条多余的「智能体」行没了。** 子智能体由 stop 钩子收尾时，父会话并不为它
保留一个指针，流模型于是给它补出一条独立的子智能体项 —— 点开是个空面板。现在这种收尾方式派生出来的
会话不再画出那一行。

## 值得一提

- 这一版**没有数据库迁移**，数据根、配置文件格式一个字节没动。
- 改动**全在 Web 端**：命令行、Web 端与桌面应用更新后都能看到；桌面端这版的安装包与上一版在功能上
  只差这几处前端改动。

## 兼容

- 没有接口、协议与配置格式的变化；服务端源码自 v0.8.4 以来没有改动，数据根与上一个版本互相兼容。
- 内置浏览器连接协议仍是第 2 版，与 v0.8.4 的桌面应用互相兼容。

## 要求

- Node.js >= 24（单行安装脚本自带运行时，npm 安装需要本机有）。
- Linux / macOS / Windows 的 x64 与 arm64；其他 POSIX 平台用 `--universal` 安装包。
- 桌面端：Linux 提供 AppImage 与 deb，Windows 提供 exe；macOS 未签名，这一版不随 Release 发布。

上一版（v0.8.4）给内置模型库补上 Google Gemini 4 的四条、把桌宠的实时语音通话改成气泡对话；再上一版
（v0.8.3）把桌面应用的内置浏览器按对话分开，标签与 cookie 不再互串。文档在
<https://lmliheng.github.io/Adelie/docs/>。本版全文见
[`docs/releases/RELEASE-v0.8.5.md`](https://github.com/lmliheng/Adelie/blob/main/docs/releases/RELEASE-v0.8.5.md)。
