# Adelie v0.3.9 —— 在 WPS 文字里和 Adelie 一起改手上的文档

这一版自 v0.3.8 起在 `main` 上落了 **5 个功能性提交**：一个新插件（WPS），加四条从上游带回来的
界面修补。**没有破坏性改动**：数据根（`~/.adelie/data`）、配置格式、既有 HTTP 接口都没动，
已装好的机器不需要改任何配置。

主角是新插件 **WPS**（`@adelie/use-wps-office`）：它把 Adelie 的对话搬进 WPS 文字——功能区点一下
开侧栏，再把你屏幕上那份打开的文档交到 Agent 手里。读随便读，**每一处改动都要你在侧栏里点一下同意**。
其余四条都是日常会碰到的界面问题：窗口底部的悬停提示不再被底边截掉一半、上一轮还在跑的智能体不会从
面板上消失、切走再切回一个会话时它的面板仍停在原来的全屏状态、很长的会话往上翻时记忆更新卡片不再丢。

## 这一版改了什么

1. **Adelie 能读改你正在看的 WPS 文档。** 新插件 WPS 在 WPS 文字的功能区加一个「Adelie」按钮，
   点开是侧栏，可以像聊天一样让它操作当前这篇文档：九个操作——读概况、读正文、搜索、替换、插入、
   删除、插分隔符、新建、定位——以 `mcp__wps__*` 工具的形式交给会话。运行时就是一个零依赖的 Node
   文件（`kit/serve.mjs`），全程不出这台机器：桥只绑 `127.0.0.1`，Adelie 走回环地址访问，不对网络
   开任何端口。要有这个桥，是因为面板跑在 WPS 的内嵌浏览器里、与 Adelie 不同源，而 Adelie 明确不开
   CORS；桥只做四件事——托管加载项那页、把文档指令下发给真正执行它的面板、替面板跟 Adelie 说话、
   通过 WPS 自己的本机上架服务登记加载项。**改文档要用户点头**：面板建的会话是只读的，读随便读，
   每一处改动都是侧栏里的一次审批；替换与删除还能带一个「期望原文」，对不上就拒绝执行并回
   「段落已变，先重新读取」，因为模型读到的段号会过期。指令一次只跑一条、按顺序（同一份文档上两个
   写者会让两边都读不懂），面板始终不回话时那一轮会报一句看得懂的错而不是一直卡着。安装脚本会写设置、
   把加载项交给 WPS、把桥登记成 Agent 的一个 MCP 服务器并自己连一次核对、在 Windows 的启动文件夹放
   一个开机自启项、然后把桥拉起来，**每一步都可以重复跑，所以重跑就是修复**；卸载脚本是它的反面。
   设置、状态和 `bridge.log` 都在 `<数据根>/wps-bridge/` 下，不放插件目录（插件更新会整体替换）。
2. **窗口底部的悬停提示改在上方弹出。** 悬停输入框的上下文圆环时，提示原本出现在下方、被窗口底边
   截去一半，三套主题都是如此。现在，挂在控件下方的提示若下方放不下、而上方的空间更大，就改在控件
   上方弹出——面板以自己的下边缘定位、向上生长，文字折成几行都不会被裁掉；其余情况仍在下方。窗口
   底部任何控件的悬停提示都按同样规则处理，不只圆环（上游 #1098 移植）。
3. **运行中的子智能体跨轮次留在面板上。** 后来的一条消息开启新一轮任务时，智能体面板原本会整张换掉
   调用图——于是仍在后台运行、运行时也仍报告为「运行中」的子智能体从面板上消失了。现在默认调用图
   会把「运行时报告为运行中」的已加载子节点与最新一轮任务派生的子智能体一并留下：每个都保留原有的
   任务描述与自己那条会话，任务结束后它自己再消失。点击历史子智能体快捷行时，显示的仍只有那一轮
   自己的调用图（上游 #1110 移植）。
4. **切回某个 Session，它的面板仍停在原来的全屏状态。** 切到别的 Session 再切回来，停靠面板原本
   总是普通尺寸——因为切换本身把全屏状态清掉了。现在全屏按**停靠布局**记在内存里：一个 Session 可以
   让右侧停靠栏全屏，另一个同时让底部停靠栏全屏，草稿发出的第一条消息所创建的 Session 也继承草稿的
   全屏状态。跨 Session 共用的面板宽度与底部高度不变；退出全屏、隐藏停靠栏、关掉它的最后一个标签页
   都会清掉（上游 #1128 移植）。
5. **分页读取长会话时，记忆更新卡片不再丢失。** 打开一条很长的会话时，记忆更新卡片原本可能整块
   不见，尽管它对应的文件其实已经改成功了：历史窗口可能从 `session_meta` 那条记录**之后**开始，而
   Agent State 目录正是那条记录带着的，于是流模型手里没有 `<agent_state>/memory/` 这个根，认不出
   哪些文件写入属于记忆。现在历史分页的信封里带上「窗口起始那个上下文记录下来的」Agent State 目录，
   流控制器在回放这一页之前先把它填进去。打开会话、往上加载更早的消息、断开后重连三种情形下卡片都
   回来了；同一个话题被反复编辑仍只画一行，对记忆索引的编辑照旧不算（上游 #1138 移植）。

## 升级

桌面端（Windows / Linux 的 AppImage）在应用内更新：账号菜单的更新入口，或应用菜单里的「检查更新」。
默认的镜像源当前不可用，客户端会自动回退到 GitHub Releases；Windows 安装包仍未签名，
SmartScreen 会提示一次（「更多信息 → 仍要运行」）。

服务器 / CLI 装的（tar 包或 npm 全局）用同一条链路，数据根（`~/.adelie/data`）不动：

```bash
penguin update --check     # 看有没有新版
penguin update --yes       # 原地替换 bin/lib/web/node
```

| 产物 | 目标 |
| --- | --- |
| `adelie-desktop-win32-x64.exe` | Windows x64 桌面端（未签名，NSIS 安装器） |
| `adelie-desktop-linux-x86_64.AppImage` / `adelie-desktop-linux-amd64.deb` | Linux x64 桌面端 |
| `penguin-linux-x64.tar.gz` | Linux x64 命令行版（自带 Node 24.18.0） |
| `penguin-win32-x64.zip` | Windows x64 命令行版（自带 Node 与 MinGit） |
| `penguin-universal.tar.gz` | 任意平台（不带运行时，需要 Node ≥ 24） |
| `install.sh` / `install.ps1` | 在线安装脚本（`penguin update` 取的就是它） |
| `latest.yml` / `latest-linux.yml` | 桌面端自动更新读的元数据 |

安装包都在 GitHub Release 上：<https://github.com/lmliheng/Adelie/releases/tag/v0.3.9>，
下载页同样直指这里。npm 上整条链同样是 **0.3.9**（3 个宿主包 + 19 个插件包，其中新加入的是
**WPS**）：`npm install -g @adelie/cli`。

**存储清理仍是出厂关闭的。** 想用就在设置页「存储」页打开开关，或 `penguin storage mode on`；
不想用就什么都不用做，行为与上一版一致。

## 已知待办

- **没有代码签名**：Windows 的 Authenticode 与 macOS 的 Developer ID 都没有；macOS 的 dmg 会被
  Gatekeeper 拦，所以仍不发 macOS。
- **WPS 插件里，WPS 那一侧本身没有验证**：面板和桥这边都测过（桥、安装脚本、加载项托管走
  `node --test`；十四条浏览器测试让真面板跑在假 WPS 上），但功能区的按钮、任务窗格、文档接口只在
  装了 WPS 的机器上存在——第一次必须发生在 Windows 上、并且当着 WPS 的面。
- **OSS 镜像当前不可用**：镜像账号被停用，直链与读写都返回 `403 UserDisable`；因此下载页与
  Release 资产都只指向 GitHub，桌面端更新自动回退到 GitHub。等镜像恢复后一行换回即可。
- **存储清理的第 3、4 步未做**：删会话时把它留下的临时工作区一并移入回收站（止漏）、以及重复工具
  环境的合并迁移（人工点一次）。数据库维护（`VACUUM`）也推迟。
- 命令名仍是 `penguin`、数据根 `~/.adelie`；安装脚本与打包脚本里的产物名仍是 `penguin-*`。
- `.github/workflows/release.yml` 仍是上游那条（只能手动 dispatch，且会推上游的 Docker 镜像），
  Adelie 自己的发布流水线还没写；这一版的安装包是「本机脚本 + `desktop-build.yml` 手工 dispatch」
  打的。
