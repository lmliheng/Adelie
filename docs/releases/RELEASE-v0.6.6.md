# Adelie v0.6.6 —— 错误表能忽略一类噪音，另有九处「点了没反应」的原因留在原地

这一版自 v0.6.5 起在 `main` 上落了 **11 个用户看得见的改动**（其余是每轮的记账）。数据根、配置格式与
既有的请求接口都没有变；**有一个功能被整套删掉了**，升级前请先看下面第二节。

## 这一版的新东西

### 1. 错误表能忽略某一类报错，一条记录都不删

成本中心的错误表一直只有两条路：要么看着，要么清空。而清空是真删——按当前筛选把整批记录从库里抹掉，
全项目的人此后都查不到。对一个下午重试几百次、每次都叫 `[llm] llm_fatal` 的那类噪音，这个代价太大，
于是它就一直躺在表的第一页，把真正要看的那三条挤到后面。

现在每一行多一颗眼睛图标：按下去就按它那一行的**来源 + 错误码**立一条规则，这类记录从表里消失，而
**一条都没删**。想连「一类里的另一种声音」一起留下也行——规则可以再窄到「消息包含某段文字」，于是同一
来源与错误码里只有带那段的被隐藏（`llm_fatal` 一次 500 的报错可以留着，整下午的套接字断流不用看）。

立规则与撤销规则是项目主人（owner）的事，和清空同一条线：规则改的是所有人看到的表。成员照样看得到统计
行里那个「已忽略 N」，也照样能切到「已忽略」视图读那批记录——被规则挡住的东西，从不对他们隐身。

界面上是第四个分段页签（全部 / 未预期 / 预期内 / 已忽略）、行里那颗「忽略这类异常」、忽略之后表上方一条
**可撤销**的横条（「已忽略 … · 本次隐藏 N 条记录」+「撤销」），以及「已忽略」视图里那张规则列表（每条念
自己覆盖什么、已隐藏多少条、最近一条何时，带「取消忽略」）。横条落在表的位置上，因为那颗按钮原来所在的
行已经消失了；通知区里同样的句子还是会六秒后自己走掉，撤销不会。

清空照旧只清屏幕上那一批，但它的确认句现在会说清被忽略的那批不在其内（「另有 N 条已忽略的记录不在此列。」）；
站在「已忽略」视图上按清空，句子说的就是那一批。

规则**永久**有效，没有过期时间——现在没有任何地方读「什么时候失效」，所以先不写一个没人读的字段。

## 删掉的东西

### 2. 服务器浏览器整套没了

**服务器浏览器**这个页面删掉了，侧栏里那一行、全部 `/api/server-browser` 路由（状态读、启动、停止、
导航、后退、前进、刷新、改尺寸、输入，以及那条 MJPEG 的 `frames` 流）一起走。`/browser` 现在会像其它
没见过的路径一样落到 `/chat`。`ADELIE_SERVER_BROWSER` 与 `ADELIE_SERVER_BROWSER_BIN` 也不再被读——
仍然导出它们的部署照常启动，这两个名字只是不再有人读。

它的存在意义是「在服务器那台机器上看一个自己的机器够不到的页面」，而在真正用过它的那台机器上，画面
的开销比这个页面带来的东西更贵（MJPEG 全量重编码）。**桌面应用自己的内置浏览器一点没动**：它的页面
就是应用自己窗口里的元素，从来不需要服务器上有一个浏览器。

那台机器上留下的浏览器配置（数据根目录里的 `browser-profile/`，里面有登录状态留下的东西）升级不会
自己删——等里面那份数据不再要紧时，手工删掉那个目录即可。

## 另外九处：被拒的原因不再只活六秒

这九处都不做乐观写入——被拒之后控件、表单、卡片一个字都不变，于是「为什么」是唯一能说明这颗按钮被按过
的东西；而它此前只在一条六秒后自己消失的通知里。现在每一处都把服务端的原话画在发起动作的那个控件旁边，
**留到下一次同一种写为止**（控件自己就是重试）：

3. **新对话的第一条消息发不出去**——原因画在输入卡下面。这两半写入里任何一半被拒，什么都没落盘：前一半
   建出来的空 Session 会被删掉，消息与暂存的文件仍留在输入框里。
4. **思考等级没切过去**——原因画在输入卡上方（与麦克风的提示同一处：它解释的是卡里的一个控件），并点明
   是哪一档没改动。
5. **远程控制卡片的凭证保存被拒**——原因画在卡片末尾、两个宿主里都在「保存」上方；服务端刚拒掉的那个
   凭证，正是这张表单上的一个字段。
6. **远程控制卡片发测试消息没发出去**——原因画在两个探测按钮下面，单占一个槽位、不与凭证探测共用：
   「凭证连不上」和「聊天不收这条消息」是两件事。
7. **Agent 的 API 页三处写没写进去**（打开 API、审批模式、关掉无密钥访问）——原因各留在自己的控件下面，
   三句话故意说得不一样。这三处里代价最大的是无密钥访问：没关掉意味着任何能访问这个地址的程序都能无
   密钥调用这个 Agent，而记忆里那个开关还停在「已关」。
8. **新增分组里导入被拒**——原因画在对话框自己的报错那一行（base URL 字段下面、按钮上面），并说清哪个
   分组没建成、身后那张表没有动。
9. **压缩阈值没改成**——原因画在发问的那张确认卡片里，念出被要求的那个阈值，并明说 Agent 上仍然是原来
   的值。
10. **技能「打包导出」被拒**——原因画在发问的那一行下面，并明说技能仍然装在这个 Agent 上（导出失败是
    唯一会让人担心「已安装的那份是不是被动了」的时刻）。
11. **钩子包「打包导出」被拒**——同上，画在发问的那一行下面。

## 兼容

- 新增一张表（`error_ignore_rules`）与三条路由；`GET/DELETE /usage/errors` 只是多一个可选参数
  （`ignored=1|0`），仪表盘多一个字段。没有规则的项目读到的表与以前逐行相同，升级后老数据一条不动。
- **破坏性**：服务器浏览器页面与全部 `/api/server-browser` 路由已删除，两个环境变量不再被读。产品里没
  有别的地方调过这些路由。
- 请求、响应与磁盘格式没有别的变化；没有新增环境变量。规则改的是所有人看到的表，权限与「清空」同档。

## 升级

**桌面端**在应用内更新：账号菜单的更新入口，或者应用菜单里的「检查更新」。Windows 安装包仍未签名，
SmartScreen 会提示一次（「更多信息 → 仍要运行」）。

**命令行与 Web**：`penguin update`（或重装 `npm install -g @adelie/cli`）。npm 上的包都到了 0.6.6。

## 安装

```bash
curl -fsSL https://github.com/lmliheng/Adelie/releases/latest/download/install.sh | sh
```

```powershell
irm https://github.com/lmliheng/Adelie/releases/latest/download/install.ps1 | iex
```

也可以只装 CLI：`npm install -g @adelie/cli`（需要 Node.js >= 24）。

## 要求

- Node.js >= 24（单行安装脚本自带运行时，npm 安装需要本机有）。
- Linux / macOS / Windows 的 x64 与 arm64；其他 POSIX 平台用 `--universal` 安装包。
- 桌面端：Linux 提供 AppImage 与 deb，Windows 提供 exe；macOS 未签名，这一版不随 Release 发布。

上一版（v0.6.5）让输入框会听写，并把七处被拒的原因从六秒的通知里搬到控件旁边。文档在
<https://lmliheng.github.io/Adelie/docs/>。变更明细见仓库里的
[`CHANGELOG.zh.md`](https://github.com/lmliheng/Adelie/blob/main/CHANGELOG.zh.md)。
