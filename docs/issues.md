# Issue 规则

Adelie 是一条长期产品线：一次对话会被压缩、会被忘掉，而问题还在。所以**发现即记录**，
记录的地方是 issue，不是聊天记录里的某一段。

## 1. 存在哪里

| 地方 | 作用 | 谁写 |
| --- | --- | --- |
| `docs/issues/*.md` | **草稿区**：发现问题的当下就写，不需要任何凭证，跟着 commit 一起进历史（`git log` 能看出是哪天发现的） | 人、代理 |
| GitHub Issues（`lmliheng/Adelie`） | **正式跟踪**：对外可见、可被 `Fixes #N` 引用、可被搜索 | 由草稿同步上去 |
| `docs/redesign.md` / `CHANGELOG.md` | 设计与已发布的历史。**不是** issue —— 它们是「已经定下来的」，issue 是「还没解决的」 | — |

同步是一条命令：`node scripts/issues-sync.mjs`（要 `GH_TOKEN` 或 `GITHUB_TOKEN`）。
它按正文里的隐藏标记做到幂等 —— 同一条草稿推两次只会得到同一个 issue 号。
没有凭证时**不要卡住**：草稿写进仓库就算记下了，回答里注明「待同步」即可。

## 2. 什么时候开

**开**（发现的那一刻，不等收到指令）：

1. 发现的缺陷，但当场不该修或修不了；
2. **未验证的结论**：模型 id 取自文档、某个平台没装过、某条路径没真跑过；
3. 已知欠账：临时兼容分支、写死的路径、`TODO`；
4. 需要人拍板的取舍（两条路都能走，代价不同）；
5. 阻塞：缺凭证、缺环境、缺外部条件。

**不开**：

- 当场顺手修完的 —— 它属于那次 commit 与 `CHANGELOG`，另开一条 issue 只是把同一件事说两遍；
- 纯问答、需求本身 —— 那属于对话与 `docs/redesign.md`。

**纪律**：发现即记，记完**继续原来的任务**，不当场岔开去修（P0 除外 —— 数据丢失、
密钥泄漏、主流程不可用，那种要先停下来说）。
「我待会儿再记」等于不记：上下文一旦压缩，细节就没了。

## 3. 一条 issue 长什么样

**标题**：`<范围>: <一句话，可判定>` —— 读完标题就知道是什么事、算不算解决。
范围取一个词：`core` / `providers` / `tools` / `runtime` / `server` / `cli` / `web` /
`desktop` / `docs` / `brand` / `release`。

**正文五段，缺一段就是没写完**：

| 段 | 要求 |
| --- | --- |
| 现象 | 能观察到的样子，不是猜测的原因 |
| 复现 | 一条命令或一串步骤；"偶尔发生" 要写清概率与条件 |
| 期望 | 正确的样子是什么 |
| 影响 | 谁会踩到、多严重、有没有绕过办法 |
| 证据 | 命令与输出、`文件:行`、commit hash、issue 编号 —— 要能被独立复核 |

原因分析、修法写成「可选」，别当成必填：写不出原因的也要能开 issue，否则「先搞懂再记」
会让问题在搞懂之前先丢掉。

## 4. 标签与优先级

- **类别**（必选一个）：`bug` 缺陷 · `未验证` 结论没被证实 · `欠账` 已知的临时做法 ·
  `决策` 等人拍板 · `阻塞` 外部条件卡住
- **范围**：`scope:core` … `scope:release`（与标题前缀一致）
- **优先级**：`P0` 数据丢失 / 密钥泄漏 / 主流程不可用 · `P1` 主流程出错或有安全含义 ·
  `P2` 体验与文档 · `P3` 打磨
- 草稿用 frontmatter 表达，同步脚本负责把标签建出来（不依赖仓库里预先存在同名标签）

## 5. 生命周期

- 修复的提交在信息里写 `Fixes #N`（若是仓库内草稿先同步过，就写同步后的编号）。
- **关之前必须回过一次**：要么给出复现，要么给出测试。没有验证的关闭等于把问题藏起来。
- 关不掉的**长尾**（例如「没在 Windows 上装过」）要在正文里写清「为什么一直开着、
  什么条件下能关」，否则它会在半年后变成一条谁都不敢动的僵尸 issue。
- `决策` 类只在人拍板后关；拍板的结论要回写进 issue 与 `docs/`。

## 6. 草稿的格式

```markdown
---
title: "server: 非管理员改密钥返回 500 而不是 403"
labels: [bug, scope:server, P1]
---

## 现象
...
```

- 文件名：小写连字符，`<范围>-<短描述>.md`
- 同步成功后，脚本会在 frontmatter 里补一个 `issue: <编号>`；有 `issue:` 的草稿不再重复推送
- 同步脚本：`node scripts/issues-sync.mjs --dry-run` 先看一遍要发什么，再去掉 `--dry-run`
