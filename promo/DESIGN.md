# 设计思路：一条 60 秒的 Adelie 宣传片（第二版）

写给下一次要改这条片子的人。这里记的是**为什么这么拍**：叙事、构图、颜色、参数，以及每一条
为什么是这样而不是那样。

> **第二版改了什么。** 第一版（57 秒、八场、纯黑底 + 亮蓝）有三处问题，
> 这一版按三条意见重做：
>
> | 意见 | 诊断 | 这一版的做法 |
> | --- | --- | --- |
> | 主题色不太符合 | 全片纯黑 `#000000` + 亮蓝 `#015dfc` 当主色铺满（光环、柱子、箭头、数字），而应用默认主题是白底近黑（强调色就是 `#171717`），唯一的品牌彩色是链接蓝 `#0b57d0`，其余彩色只属于状态（成功 / 警告 / 危险） | 画布换成应用自己的纸面（`#ffffff` / `#fafafa`），强调色取应用里真实存在的 `#0b57d0`；`#0258ee` 只留在图标那一圈轨道上 |
> | 四周太空洞 | 每场都是「居中一块内容 + 四周空白」，主体只占画布的 81%×68%，边缘全靠低透明度的点阵和辉光撑 | 满幅构图：安全边收到 96px，每场至少一条出血，背景改成从边到边都有细节的纸面网格 + 边缘文字 |
> | 没讲应用核心 | 片子讲了「它会动手」「它会变强」，但没讲**为什么是 Adelie**：智能体就是一段文字，改这段文字就是进化 | 新增第 3 场「一段文字」；第 6 场从「数字自己变大」改成「**改字**之后分数才动」 |

## 一、要解决的问题

| 问题 | 结论 |
| --- | --- |
| 谁看 | 第一次听说 Adelie 的技术同行：能看懂「工具调用」四个字，不需要解释什么是 Agent |
| 在哪看 | GitHub README 首屏、群聊转发、B 站/视频号。**大概率静音播放**，前 3 秒决定去留 |
| 多长时间 | 一分钟左右。超过一分钟，README 首屏的人不会点 |
| 只记住一件事 | **智能体就是一段文字：写一段话配出它，改这段文字让它变强** |
| 第二件（如果记住了） | 它在你电脑上真的动手，而不是只会聊天 |

整条片子的功能因此被定成一句话：**先让人看见「一段文字 = 一个智能体」，再让人看见它动手，
再让人看见这段文字自己变好，最后告诉他去哪儿拿。**

第一版把「动手」放在第一位，是因为它最容易被一句话讲清；但「动手」是同类的通用能力，
**「配置即文本、进化即改文本」才是 Adelie 独有的**，而它恰好也最需要一次演示才能被看懂。
所以这一版把这一幕提到第 3 场，在观众还有注意力的时候先讲清楚它是什么。

## 二、叙事骨架

九场，60 秒，1920×1080 / 30fps / 1800 帧。每场只承担一个功能，情绪曲线是
「认得 → 被钩住 → **听懂它是怎么造出来的** → 看见 → 摸到底 → 相信它会变强 → 放心 → 敢用 → 找得到」。

| # | 场景 | 帧 | 时长 | 功能 | 一句话 |
| --- | --- | --- | --- | --- | --- |
| 1 | 开场 | 0–120 | 4s | 认得它 | 轨道画出、图标落位、字标收拢 |
| 2 | 立题 | 120–270 | 5s | 被钩住 | 把「只会聊天」划掉，改成「一段文字就够」 |
| 3 | **一段文字** | 270–570 | 10s | 听懂 | 左边写 AGENTS.md，右边长出一个智能体 |
| 4 | 演示 | 570–840 | 9s | 看见 | 一句话，六步工具调用，产出 docx |
| 5 | 能力 | 840–1080 | 8s | 摸到底 | 技能 / 子代理 / 定时 / 记忆 |
| 6 | **自进化** | 1080–1350 | 9s | 相信它会变强 | 评估找失分 → **改文本** → 62 → 78 → 91 |
| 7 | 透明 | 1350–1515 | 5.5s | 放心 | 每一步的耗时与花费都记账 |
| 8 | 本地优先 | 1515–1650 | 4.5s | 敢用 | 文件不出机器，模型随你换 |
| 9 | 收尾 | 1650–1800 | 5s | 找得到 | 字标 + 一句话 + 仓库地址 |

排序的三条理由：

- **「一段文字」必须在演示之前。** 演示回答「它能不能干活」，文字场回答「它是怎么做出来的」。
  看完演示再来听机制，观众已经把它归进「又一个 agent 产品」；先讲机制，演示就变成了机制的证据。
- **自进化紧跟能力。** 自进化抽象，必须先有「技能也是文本、也能被写」这场铺垫，
  「它给自己加分」才不是空话；而在这一版里，它更具体——**加分的动作是改字**。
- **总长压到 60 秒整。** 第一版 57 秒，这一版净加 3 秒：新场吃掉 10 秒，其余各场一共挤出 7 秒——
  开场 5→4（观众不需要 5 秒认图标）、立题 7→5（两句话念完就够）、演示 11→9（六步工具行里每 15 帧
  落到 12 帧）、能力 9→8（四张卡铺满，读得更快）、透明 6→5.5、本地优先 5→4.5。自进化 8→9
  多要了一秒，因为「改字」这个动作需要观众看清删了什么、加了什么。**一分钟是硬上限**：
  超了 README 首屏的人就不点了。

## 三、逐场的设计取舍

### 1. 开场（0–120）：用图标和字标，不用字幕

纸面上第一眼给的不是文案，是**应用里那个图标**——白牌、海军蓝企鹅、蓝色轨道。

- 轨道在片里被放大成一圈半径 226px 的环，先用 1.2 秒只画出一道弧（`strokeDashoffset`），再整体缓慢
  旋转。**这一圈的蓝是 `#0258ee`，取自图标本身**；它是全片唯一一处饱和蓝，别处不许出现。
- 字标 `Adelie` 入场是**字距从 0.3em 收到 0.03em**，配 36–62 帧的淡入。六个字母逐个弹会显得廉价，
  收字距只有一次动作，更像「东西落地」。
- 图标块与环共用一个定位容器：环只围着图标，字标落在环下方 136px，永远不会撞（第一版的翻车点）。
- **背景不是空的。** 纸面网格从第一帧就在，边缘文字（`AGENTS.md` 的片段，2.5% 墨色）从左上向右下
  缓慢流；开场结束时它已经铺满四边——观众潜意识里看到的是「一处正在被写的字」，正是全片的主题。

### 2. 立题（120–270）：靠一个「划掉」的动作成立

两句话对偶：`大多数 AI，只会陪你聊天。` → `Adelie：写一段话，它就开始干活。`

- 第一句在 16–40 帧被一条灰线**划掉**，随后整句降到 38% 不透明度。划掉是全片唯一的否定，
  它让第二句不需要形容词就站住。
- **全片只有这里把「写一段话」四个字涂成链接蓝 `#0b57d0`。** 蓝是稀缺资源，用在一个动作上，
  观众记得住；也把主题从「它会动手」提前换成「它是被写出来的」。
- 版面不再居中：第一句左上对齐、出血到左边缘，第二句右下对齐、出血到右边缘，中间用一道 1px 的
  斜线连起来。**整幅画面被对角线组织**，四角都有东西，这是治「空洞」的第一处。

### 3. 一段文字（270–570）：这一版的核心

整场只讲一件事：**一个智能体就是一个文件夹里的一段文字。**

**版面：65 / 35 出血。** 左边 65% 是一张全高的编辑器（白纸、等宽字体、行号、`#e5e5e5` 的装订线），
从左边框一路出血到画面中缝；右边 35% 是同一个智能体被这段文字「配出来」的样子。右边不留白，
被一张塞满卡片的窄栏占着，卡片依次亮起。

编辑器里写的是真东西——`agents/default_agent/agent_state/AGENTS.md` 的一段中文：

```text
你是 Adelie 的研究助理。
每天 09:00 汇总 arXiv 上 cs.CL 的新论文，按主题分组，每条不超过两行。
写进 ~/notes/arxiv/YYYY-MM-DD.md，并在聊天里只报标题与条数。
不确定的论文放在最后，标「待确认」。
```

**这一场的动作是「写一句，长出一个东西」**——这段文字里的四件事，一件一件长成右边的东西
（第一句「你是 Adelie 的研究助理」不进表，它长成最后那张 agent 卡的名字）：

| 文本里的这一句 | 右侧长出的东西 | 在应用里对应什么 |
| --- | --- | --- |
| 每天 09:00 汇总 | 一条定时任务（09:00 · 每天） | 「定时任务」面板里的一条 |
| `~/notes/arxiv/…` | 一条文件工具（写文件） | 工作区里的读写工具，路径就是文本里那个 |
| 每条不超过两行 | 一条输出约束 | AGENTS.md 原文进系统提示词，模型照它答 |
| 标「待确认」 | 一条兜底规则 | 同上——规则也是这一段文字 |

四张卡落齐后，它们合拢成一张 agent 卡：名字 `研究助理`、四个技能、下一次运行时间。**这时候观众
看见的是「一段话变成了一个可运行的智能体」**，而不是「一个模型在聊天」。

节奏（30fps，场内帧号）：

| 时刻 | 发生什么 |
| --- | --- |
| 0–20 | 编辑器从左侧滑入并出血，光标在第一行闪 |
| 20–30 | 第一句逐字写出（每 1.1 帧一个字，中文比英文慢一点才读得完） |
| 30–38 | 右侧第一张卡从行尾「长」出：先一条 1px 线拉过去，再卡片淡入 |
| 46–54 / 62–70 / 78–86 | 其余三句同理，卡与卡之间有 8 帧间隙，避免齐刷刷一起冒 |
| 96–112 | 四卡收拢成一张 agent 卡，行尾连线一起收 |
| 112–150 | 缓推 1 → 1.012，底部出血条压上来一行字：「写一段话，就是一个智能体。」 |
| 150–240 | 停住不动，只留缓推——给观众读那四张卡的时间（这一段最容易被剪掉，一剪就只剩口号） |
| 240–300 | 底部那行换成：「改这段文字，就是进化。」镜头同时推向那张 agent 卡 |

底部那条出血条（全宽、`#fafafa`、上边一条 1px 线）就是这一场的收束：它压在画面最下沿，
把「内容到边」这件事做实在，不留 180px 的黑边。

### 4. 演示（570–840）：重建界面，不用截图

这是整条片子成本最高、也最值钱的一场。

**为什么不用真截图。** 本机抓真实窗口只需要一次 `PrintWindow`（脚本留在 `tools/capture_window.py`，
不抢焦点），但截图有三个硬伤：截到的是我自己那次会话的内容、分辨率停在 1280 宽、而且没法让工具
调用一条条「长」出来。宣传片需要的是**可控的时间**，不是一个静止的真相。

**重建的边界。** 界面照着真实 Adelie 画：白底、1px `#e5e5e5` 分隔线、左侧导航就是
新建对话 / 智能体 / 模型库 / 插件市场 / 评估中心 / 机器管理 / 成本中心，右上角「本地运行」和侧栏
底部「内测版 · v0.6.8」都是真的。改掉的只有内容——任务换成「整理 11 月销售月报」，因为这件事
任何人一听就懂。

**窗口铺到 90%。** 第一版窗口 1560×740（81%），四周留 180px 黑边，那个黑边正是「空洞」的来源。
这一版窗口 **1728×880**，左右各留 96px、窗口顶 200px，**下沿与画面下沿齐平**——
于是它像一块屏幕**立在纸面上**，而不是浮在虚空里。第一稿想把窗口再往下压 40px 让它「沉出」
画面，实拍时才发现被切掉的正是底部的输入框，于是只保留齐平。（`promo/src/scenes/Demo.tsx`
就是按齐平写的。）

**节奏是靠帧数卡出来的：**

| 时刻 | 发生什么 |
| --- | --- |
| 6–26 | 输入框逐字出现（每 1.1 帧一个字） |
| 10–27 | 光标从窗口内滑到发送键，不从天而降 |
| 27–36 | 点击涟漪扩散；38 帧消息落到右侧气泡 |
| 62 帧起 | 工具行逐条落下，每 12 帧一条，行高 48px，带 8 帧的 spinner → ✓ 翻转 |
| 150 帧 | 状态从「运行中」翻成「运行完毕 · 34s · 6 步」（步数按工具列表长度算，不写死） |
| 156 帧 | 结果卡升起来，柱状图 4 帧一组依次长高 |
| 168–268 | 整个窗口缓推 1 → 1.012，把注意力推回内容 |

窗口做成 1728×880（约 1.96:1），不是 16:9：**留白是为了让界面的 13–15px 字在 1080p 上还看得清**，
但留白只留 96px，且被纸面网格与边缘文字填满。第一版窗口高 880 时结果卡下面空出 200px 白色死区，
看着像渲染失败；现在窗口高 880 而内容按 6 条工具行 + 结果卡重新排过，最后一屏不出现空带。

### 5. 能力（840–1080）：四张卡，因为插件库就是四类

用 2×2 卡片而不用四行列表，是因为这四件事**没有先后关系**，是并列的「工具箱」；列表会被读成流程。

- 卡片尺寸 876×300，两列间距 24，整块 1776 宽——**接近满幅**（安全边 96）而不是第一版的 1400。
- 四张卡的标题压在 README 的语言上：技能即插件（对应插件市场）、子代理并行、定时任务、长期记忆。
- 每张卡右上角有一个同名的文本文件名：`SKILL.md`、`subagents`、`schedule`、`memory`。
  **它们全都很轻地重复第 3 场的那句话**：这些东西都是一段段文本，不是黑盒。
- 卡内留白按 24px 内距重排过：第一版每张卡下半截空着，观众会以为内容没加载出来。

### 6. 自进化（1080–1350）：把「变强」画成一次改字

第一版是三张并排的分数卡 `62 → 78 → 91`，数字自己变大——观众只看见「分数涨了」，没看见
**为什么会涨**。这一版把动作还给文本：

| 阶段 | 画面 | 观众读到 |
| --- | --- | --- |
| 1（0–60 帧） | 左：同一份 `AGENTS.md` 的 v1，两行被灰波浪线标出；右：一张评估卡，`62`（小字「示意数据」） | 它被打了分，也知道哪两句扣了分 |
| 2（60–120 帧） | 失分点两行具体写出来：「摘要常常超过两行」「『待确认』那一组还是并进了主题」——**两条都能指回第 3 场那四句话里的两句** | 失分点是可以指到句子上的 |
| 3（120–200 帧） | 文本上真的动刀：把那两句写硬——「超过两行就截到第二行末」「『待确认』单独一段，不并进任何主题」，diff 用 `#0b57d0` 的左边框与浅蓝底标出（不是红绿） | **进化 = 改这段文字** |
| 4（200–240 帧） | 分数从 62 滚到 78，只在 diff 落定之后才动 | 分数是改字的结果，不是自变量 |
| 5（240–270 帧） | 再一轮：v3，`91`，v3 那张文本卡用蓝色描边标成「当前版本」 | 这是一条可重复的流水线 |

- **数字旁边标「示意数据」。** 片子里没有实测依据的数字只能当图示，不标就是撒谎——13px 灰色，
  不抢戏但能看清。
- 三颗药丸补的是「万一变坏呢」：每轮之前给 `agent_state/` 存一份快照、每个请求能在轨迹里回放、
  改坏了回滚到上一份文本。**自进化的说服力有一半在兜底上**，只讲变强会被懂行的人当场拆掉。
- 箭头上的两个动词（找失分点 / 再优化）是这条流水线的真实步骤，对应 `agent-evaluation`（跑
  Benchmark、打分）与 `agent-optimization`（提假设、改 State、接受或回滚）两个 Skill。

### 7. 透明（1350–1515）：左边给主张，右边给证据

「每一步，都算得清」是主张，所以右边必须有一张像账单的东西：步骤 42、工具调用 18、128k tokens、
$0.068，下面五行执行轨迹，**每行进度条的长度按真实耗时比例画**（网页抓取 7.2s 比读取文件 0.9s 长
得多），数字从 0 滚到位，约 36 帧。数字不动的话，观众会以为那是静态图。

这一场的进度条**不再用蓝**（第一版用蓝，等于把「品牌色」用在了一个和被品牌无关的东西上）：
用墨色 `#171717`，已完成那段加粗。蓝只留给「可点」和「这是 Adelie」。

### 8. 本地优先（1515–1650）：把「数据」和「密钥」分成两件事

一句「文件不出这台电脑」是主张，但技术读者会立刻反问两件事：数据存哪、密钥给谁。所以第二行直接
把它们分开写：智能体、工作区、密钥都在你自己的机器上；模型随你换。下面七个 chip
（Claude / GPT / Gemini / DeepSeek / Qwen / Moonshot / Ollama）不是凑数——它们是应用里真实存在的
供应商标识，逐一在打包代码里查过。

版面用整幅的一条横向「机器边框」：画面就是一台机器的轮廓，文字与 chip 都贴在这条边框的内侧，
**四周因此没有一处是空的**。

### 9. 收尾（1650–1800）：只留三样东西

字标、一句 slogan（「写一段话，就是一个智能体」）、一个仓库地址。

- 字标 116px，撑到 92% 宽；下面一道 1px 线从左边框拉到右边框，线中央留一小段 `#0b57d0`——
  全片最后一笔彩色，也是把「可点」这个语义收束到仓库地址上。
- 没有二维码、没有「立即下载」、没有扫一扫。片子的分发场是 README 和聊天窗口，观众要的是
  **一个能记住、能搜到的名字**。地址用等宽字体放在描边药丸里，是为了让它像「链接」而不是广告语。

## 四、视觉系统

### 色板：全部取自应用本身

第一版的蓝 `#015dfc` 只存在于图标那一圈轨道上，应用界面里从来没有它，却被当成主色用了整片。
这一版**以应用默认主题（`packages/ui/src/themes/github.css`）为准**：

| 用途 | 浅色版（主） | 深色版（备） | 出处 |
| --- | --- | --- | --- |
| 纸面 | `#ffffff`，面板 `#fafafa` | 画布 `#121212`，面板 `#1a1a1a` | `--ui-canvas` / `--ui-surface` |
| 线 | `#e5e5e5`（hairline 1px） | `#262626` | `--ui-line` |
| 墨 / 次级 / 注释 | `#171717` / `#737373` / `#a1a1a1` | `#d6d6d6` / `#a1a1a1` / `#8a8a8a` | `--ui-fg` 三级 |
| 强调（全片唯一的品牌彩色） | **`#0b57d0`** | `#8ab4f8` | `--ui-fg-link` |
| 品牌环（只在开场与收尾） | `#0258ee` | 同 | 应用图标的轨道蓝 |
| 企鹅 | `#0e1c37` | 同 | 应用图标 |
| 完成态 | `#047857`（emerald-700） | `#34d399`（emerald-400） | `--ui-tone-success-fg` |

深色版不是「把片子调暗」：它是同一套语义在应用深色主题下的取值，用于 README 深色模式、
B 站这类以暗背景为主的播放环境。**两版共用一份排版与时间线，换的只有颜色变量。**

### 强调色的四条规矩

蓝在这条片子里只做四件事，多一件都不做：

1. **图标与字标的轨道**（开场、收尾各一次）——「这是 Adelie」。
2. **可点的东西**：输入框的光标、被选中的卡片、diff 的左边框——「这里能动手」。
3. **全片只有两个动词上色**：「写一段话」（第 2 场）与「改这段文字」（第 6 场）。
4. **数据只在一种情况下变蓝**：它是「改完之后的结果」（第 6 场的 78 / 91）。

进度条、箭头、柱状图、分数字（除第 6 场的两个）**一律墨色**。第一版把这些全涂成蓝，
结果蓝不再表示任何东西，只剩下「科技感」——那正是「主题色不符合」的根源。

### 构图：满幅，不许居中漂浮

| 规则 | 数值 | 为什么 |
| --- | --- | --- |
| 安全边 | 96px（第一版 180px） | 留白超过一个拇指宽就会读成「空」 |
| 每场出血 | 至少一条边（左 / 右 / 下） | 让画面有「被裁切」的感觉，一个 1920 宽的画框里就有内容在继续 |
| 演示窗口 | 1728×880，下沿与画面下沿齐平 | 屏幕立在纸面上，不是浮在虚空里 |
| 能力四卡 | 1776 宽、876×300、间距 24 | 接近满幅 |
| 字标 | 92% 宽 | 画面最后一帧要「顶满」 |
| 标题对齐 | 不居中：左上 / 右下对角 | 对角线组织让四角都有东西 |

### 背景：纸面网格 + 边缘文字

替换掉第一版的两件东西：

- ~~纯黑底~~ → **纸面**：`#fafafa` 底 + 32px 网格（1px `#e5e5e5`，40% 不透明度）。
- ~~中心辉光~~ → **边缘文字**：`AGENTS.md` / `SKILL.md` 的片段，等宽 12px、2.5% 墨色，
  从左上向右下缓慢流（每场偏移 30px），永远铺到四条边上。

这两件东西的作用是让**边缘永远有细节**。第一版用点阵（中心 70% 渐隐）和一层 0.16 透明度的径向
辉光，两者都在中心最亮、边缘最淡——恰好是「四周空洞」的成因。

### 字体与字号

全片用系统字体栈（中文落到 `Microsoft YaHei`），不引任何 webfont——一是离线也不崩，二是中文
webfont 体积不划算。编辑器与地址用等宽（`ui-monospace, SFMono-Regular, Consolas`）。

| 层 | 字号 | 字重 | 用在哪 |
| --- | --- | --- | --- |
| 字标 | 104（开场）/ 116（收尾） | 600 | 开场、收尾 |
| 大标题 | 82 / 64 / 58 | 600 / 500 | 立题第二句 / 本地优先 / 其余标题 |
| 卡片标题 | 25 | 600 | 能力卡 |
| 正文 | 17–20 | 400 | 卡片描述、说明 |
| 界面文字 | 13–15 | 400–600 | 演示窗口 |
| 编辑器 | 15 / 行高 26 | 400 | 第 3 场的 AGENTS.md |
| 数字 | 86 / 38 | 600 | 等宽，分数与指标 |
| 注释 | 12–13 | 400 | 药丸、免责声明 |

中文不用大于 0.02em 的字距（正文），只有小号字和全大写英文才拉开；标题一律负字距（-0.02em），
让中文标题有「块」的感觉。

## 五、动效系统

只有一套缓动，全片复用：

| 动作 | 实现 | 参数 |
| --- | --- | --- |
| 进场 | spring + 10 帧淡入 | `damping 200, stiffness 110, mass 0.6`，位移 28px |
| 弹入（图标） | spring | `damping 15, stiffness 120`，带 8° 回正 |
| 收拢（字标） | spring + 字距插值 | `damping 200, stiffness 90`，几乎不过冲 |
| 数字滚动 | 三次缓出 | 40–46 帧 |
| 卡片生长 | 线先拉、卡后淡 | `stiffness 160, damping 24`，线 8 帧、卡 10 帧 |
| 场景进出 | 8 帧交叉淡化，**不压黑** | 浅底压黑会闪；两场之间用纸面网格的连续做衔接 |
| 每场缓推 | `scale 1 → 1.012` | 覆盖整场时长 |

三条判断：

- **不用炫技转场**（擦除、缩放、噪点溶解）。这条片子是产品说明，不是预告片。
- **文本不做逐字打字**，只有两处例外：第 3 场的 `AGENTS.md`（打字本身就是这一场的论点）与第 4 场
  的输入框（模拟真实输入）。
- **每场都缓推，但幅度降到 1.2%**。第一版 1.8%，在满幅构图下会把出血的边缘推出去露出纸面；
  1.2% 人眼几乎注意不到，但画面一直在动。

## 七、技术实现与验证

Remotion 4.0.5xx + React 19，纯代码出片。时间线只有一处：`src/Promo.tsx` 的 `SCENES` 数组，
总长由 `TOTAL_FRAMES` 推导，加一场/改时长只动这里。这一版的 `SCENES` 必须长这样（九项，和第二节
的表逐行对应）：

```ts
export const SCENES = [
  { id: "open",      from: 0,    to: 120  },
  { id: "thesis",    from: 120,  to: 270  },
  { id: "text",      from: 270,  to: 570  },  // 新：一段文字 = 一个智能体
  { id: "demo",      from: 570,  to: 840  },
  { id: "skills",    from: 840,  to: 1080 },
  { id: "evolve",    from: 1080, to: 1350 },  // 重写：改文本 → 分数
  { id: "cost",      from: 1350, to: 1515 },
  { id: "local",     from: 1515, to: 1650 },
  { id: "close",     from: 1650, to: 1800 },
] as const;
export const TOTAL_FRAMES = 1800; // 60.0s @ 30fps
```

**注意：第一版的成片还在，出片工程不在这台机器上。** 成片是
`assets/promo/adelie-promo.mp4`（57 秒，第一版，已在仓库里、README 首屏在用）；2026-11-14 全盘
找过 `Promo.tsx`、`TOTAL_FRAMES`，只剩这份 DESIGN.md 和另一个只做图标/片头的 Remotion 工程。
所以这一版是**设计稿**：要出 v2，先把工程重建起来——

1. 新建工程，或复用本机那份 Remotion 工程（图标 / 片头 / README 截图动图，Remotion 4.0.463 +
   React 19.2，`node_modules` 已装好）——加一个 `Promo` composition 比从零搭省事；不管走哪条，
   `src/Root.tsx` 里注册的必须是 `1920×1080`、`fps={30}`、`durationInFrames={TOTAL_FRAMES}`；
2. `src/Promo.tsx` 的 `SCENES` 照上面的数组；每场一个组件，共用 `theme.ts`（色板变量）与
   `motion.ts`（第五节那张表）；
3. `remotion.config.ts` 里探测本机 Chrome、`concurrency: 4`；
4. 出片与验证照下面的流程走一遍。

验证流程（第一版每一步都实际跑过，这一版重建后照做）：

1. `tsc --noEmit` 通过；
2. 先 `still` 渲关键帧看图——**满幅构图尤其要单独看四边**：第 2 场的出血、第 3 场的编辑器装订线、
   第 4 场窗口下沿齐平不切输入框、第 9 场字标顶满；
3. 出整片后用 PyAV **重新解码**，核对 `1920×1080 / 30fps / 1800 帧 / 60.0s`，并抽帧或拼 4×3
   联络表过一遍——`still` 只证明某一帧对，不证明整条片子对；
4. 场景交界单独抽 3–4 帧看，确认交叉淡化不超过 0.27 秒、没有死黑帧（浅底上出现一帧全黑是
   剪辑事故）。

渲染 1800 帧约 6–9 分钟，成片预计 8–9 MB（浅色画面压缩率比纯黑略低）。

## 八、已知取舍与下一步

- **浅色是主版，深色是备版。** 应用默认浅色主题，片子跟着产品走；但 README 深色模式与 B 站都以
  暗背景为主，所以浅色版之外保留一份同排版、同时间线的深色版（`theme.ts` 换变量）。两版一起发，
  首屏用浅色。
- **横版优先。** 9:16 竖版不是把画布转过来就行：得去掉侧栏、把工具流放大成主视觉、把「写一句 →
  长出一个东西」改成上下两栏。要发抖音再做一版独立的 `PromoVertical`，而不是缩放横版。
- **无配音。** 如果之后有了 TTS key，配音按现有拍点写：每场一句话，落在场景开头 0.3 秒。
- **文案可 A/B。** 第 2 场两句与第 3 场底部那两行是全片最贵的四行，值得再试一版更狠的。
- **真截图可以作为补充**：放在演示场之后做一个 1 秒的「这是真的」插入镜头，但不要替代重建的演示。
- **第 3 场是全片唯一的「需要读」的场。** 10 秒里观众要读一段 AGENTS.md 与四张卡，节奏已经压到
  极限；如果试映时有人读不完，缩短文本（每句一行）比拉长时间更有效——时间一长，前 3 秒的钩子就废了。
