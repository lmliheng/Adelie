# 示例：放在数据根里的主题

`warm-paper.json` 是一份应用能读的主题：暖色纸张底、陶土强调色，另带三个强调色预设。

```bash
cp examples/themes/warm-paper.json "<数据根>/themes/"
```

刷新页面，它就会出现在**设置 › 外观**的主题列表里——页面上会写出读的那个目录，不用猜。默认安装
的数据根是 `~/.penguin/data`。不用重启，也没有缓存：服务端每次请求都会读一遍目录，所以改过、加过、
删过的文件，下一次刷新页面就是结果。

管理员也可以省掉这一趟：**设置 › 外观**的目录那行里点「导入主题…」，选这个文件上传，或者填一个
`warm-paper.json` 的地址让服务端取回来——两条路落成的东西和上面 `cp` 完全一样。

## 主题能写什么

主题只是**一组 UI 令牌名的取值**，别的都不是——没有组件、没有布局、没有会跑起来的代码。正因为
每个组件都只读这些名字、从不问当前是哪个主题，所以外置主题不需要重新构建前端。

- 这些名字是 `packages/ui/src/tokens.ts` 里的契约。三个自带主题（`packages/ui/src/themes/*.css`）
  在明暗两种模式下把每个名字都写满；你的文件漏掉的名字，沿用自带默认主题的值，所以只写一半也照样
  能画出来。
- `light` 是两种模式共同的底，`dark` 只写明暗不同的部分，`accents`（可选，最多 12 个）是强调色行
  给出的预设，各自只在自己的主题下生效——别的主题的预设到这里不会上色。
- 每个值只写一行、最长 120 个字符，不能含 `;`、`{`、`}`、`<`、`\`、`@` 和换行，也不能去取外部资源
  （`url(`、`image-set(`）：外置主题只能改这些令牌的取值，不能加规则、藏元素或往外发请求。

外观页会把文件写错的地方列出来：这边不认识的令牌名不会生效，会作为警告列出；完全读不了的文件会连
原因一起列出，并且一点颜色都不会画。
