# 安卓上的 Adelie（原生 APK，无 Termux / 无 proot）

这个目录把 Adelie 做成一个可以直接侧载的 APK：Node 运行时、Adelie 本体（`lib/` + `web/`）
和前端全部在包内，装完打开就在手机上起一个只监听回环地址的服务，界面是 Adelie 自己的 Web 前端。

```
android/
  build-node-android.sh      用 NDK 交叉编译 Node（x86_64 给模拟器，arm64 给真机）
  patch-zlib-cpufeatures.py  arm64 构建时 zlib 找不到 cpu-features.h 的修复
  gen-icons.py               从官方 adelie-icon.svg 生成启动图标（含自适应前景）
  build-apk.sh               把编好的 node + Adelie 打进 APK
  publish-3003.sh            把 APK 发布到设计站的 /downloads/android/ 并更新清单
  finish-v2.sh               一条命令：校验 → 打包 → 发布 → 公网下载校验
  notify.py                  长任务结束后的通知（飞书 webhook 优先，否则 CSU 邮箱）
  settings.gradle            Gradle 工程（AGP 8.7.3 + AndroidX + Material 3）
  build.gradle
  gradle.properties
  app/build.gradle           minSdk 24 / targetSdk 34 / versionCode 55
  app/src/main/java/         MainActivity（Material 3 外壳）、Core（解包与起 node）、BootService
  app/src/main/res/          layout / menu / 图标 / 主题
  app/src/test/java/         Robolectric 界面截图测试（没模拟器也能看界面）
  screenshots/               渲染出来的界面 PNG
```

## 为什么这么做

Termux 里的 `node` 用不了：它的 RUNPATH 与 19 处前缀都写死在
`/data/data/com.termux/files/usr`，换个包名就废。所以自己编一份 bionic 版 Node。

编好之后还有一关：Android 10（targetSdk 29）起，应用数据目录是 `noexec` 的，
从 `files/` 里 `chmod +x` 再 `exec` 会被 SELinux 拒绝。APK 的做法是把 node 以
`lib/<abi>/libnode.so` 的名字打进 native 库，安装时它被解到 `nativeLibraryDir`
（那份目录允许执行），运行时直接按那个路径启动。

## 界面（1.0.1 起：Material 3）

外壳是原生 Material 3 界面，内容仍是 Adelie 自己的 Web 前端。**没有顶栏** —— 页面上方
留给 Web 前端自己的头部，只有底部一条导航：

```
状态提示（只在服务没起来时出现，失败变红并给「重试」）
内容区（WebView / 原生设置页 / 深色日志浮层 / 2dp 加载进度条）
底部 navigation bar：对话 / 智能体 / 模型 / 设置（选中项用胶囊指示器 + 实心图标）
```

- **启动页**：透明企鹅图标 + 名字 + 版本，下方不确定进度条与实时阶段文字（解包进度、
  启动服务、服务已就绪）。整块内容做一次淡入上浮，就绪后整体 260ms 淡出；启动慢时点一下
  可以跳过。**不做 WebView 的透明度/位移动画** —— WebView 被合成进离屏图层后滚动会留残影，
  真机上看起来就是「字叠在一起」。
- **底部 tab** 对应前端的真实路由 `/chat`、`/agents`、`/models`；「设置」是原生页
  （工作区入口 + 开发者 + 关于）。网页自己跳转（点链接、深链）时 tab 跟着 URL 走；停在
  非 tab 的页面（例如机器管理）时底部不假装选中任何一项。
- **开发者模式**：`设置 → 开发者` 里一个开关（`SharedPreferences` 记住），打开后多出
  「运行日志 / 重新加载网页 / 复制运行日志」。日志是深色浮层，返回键先关它。
- **应用图标**：`gen-icons.py` 从 `/root/.adelie/web/adelie-icon.svg` 生成五档 mipmap
  （圆角 + 圆形）、API 26 自适应前景、启动页用的透明大图。
- 返回键：关日志 → 回「对话」→ WebView 后退 → 默认退出。

## 1.0.2 修的两个问题

1. **设置这类弹层滑不动**。根因在网页端：弹层的内容列是 `flex-1` 但没写 `min-height:0`，
   flex 项的 `min-height:auto` 让它被内容撑到 1471px，内层那个 `overflow-y:auto`
   就永远没有可滚动的余量，手机上底部（明暗、强调色、版权信息）被裁掉还滑不出来。
   外壳在每次 `onPageFinished` 注入一条兜底样式（`MainActivity.injectMobileFix`）：

   ```css
   [class*="ui-scrim"] [class*="flex-1"][class*="flex-col"]{min-height:0!important;}
   ```

   只动手机外壳、不碰网页产物；网页端自己修了也不冲突。
   `MobileFixInjectionTest` 锁住「页面加载后确实注入了」，修复效果在真 Chromium
   393×852 视口下验过：内容列 1471/547 可滚，滚到底能看到明暗与强调色。

2. **手机操控**（见下一节）。

## 手机操控（1.0.2 起的能力底子）

思路参考 dsh-go 的「手机操控」：不 root、不 Shizuku、不 ADB，走系统的无障碍服务，
所以能力上限就是 `AccessibilityService` 能给的那些 —— 读屏、点按、滑动、输入、
打开应用、截图。dsh-go 那套「看得见的操作感」也已经补上了（1.0.3 起）：顶部胶囊写着这一步
在做什么 / 在哪个应用 / 走了多久，动作前弹确认卡，屏幕四周亮一圈光带 —— 详见下面几节。

```
系统无障碍（用户手动打开）→ AdelieAccessibilityService → PhoneControl
                                                            ↑
内置 Node（同一个 uid）── HTTP ──→ ControlServer（127.0.0.1，随机端口 + token）
```

- **怎么开**：设置 → 手机操控 → 无障碍服务（跳到系统无障碍设置，打开「Adelie 手机操控」）。
  侧载的包在部分系统上要去「设置 → 应用 → Adelie → …允许受限制的设置」才能勾上。
- **操作时的浮层**（1.0.3）：屏幕顶部一条深色胶囊，左边是正在被操作的应用图标，中间是
  这一步在做什么（「点「发送」」）与第几步、用时，右边是**暂停 / 继续**和**停止**；按住胶囊
  能拖动位置。任务结束、点了停止、或者 3 分钟没有新动作，胶囊自己消失。
  用的是 `TYPE_ACCESSIBILITY_OVERLAY`，所以**不需要**额外申请「显示在其他应用上层」。
- **要人点头的动作**（1.0.3）：发送、提交、删除、付款、下单、安装/卸载、授权，以及打开
  别的应用之前，屏幕底部会升起确认卡，三个按钮：**允许一次 / 本轮免确认 / 取消**。
  取消时这次请求返回 `error=cancelled`；点「本轮免确认」后这一轮剩下的步骤不再问。
  设置 →「确认方式」还能把这个默认改成免确认（密码、验证码、付款仍然要人来）。
  请求是同步等的（最长两分钟），模型那边不用轮询。卡片上有一行倒计时（「1:46 后自动取消」，
  最后 10 秒变红），超时没人点返回 `error=confirm_timeout` —— 和主动取消分得开。
- **怎么调**：控制口地址与 token 落在 `files/adelie/phone-control.json`
  （设置页「本地控制口」那一行点一下也能复制）。协议：

  ```
  POST /cmd   X-Adelie-Token: <token>
  {"action":"doctor"}                      自检：无障碍 / 控制口 / 技能装了几份 / 下一步怎么办（没开无障碍也答得出）
  {"action":"screen"}                      读当前界面（带编号的控件清单）
  {"action":"tap","index":7}               点第 7 个控件；也可 {"text":"发送"} / {"x":540,"y":2100}
  {"action":"text","text":"你好"}           往输入框写字
  {"action":"key","name":"back"}           back / home / recents / notifications / quick / enter
  {"action":"key","name":"enter"}          输入法的回车 / 搜索 / 发送（Android 11+）
  {"action":"long_press","text":"昨天那条消息"}  长按控件叫出菜单；也可 {"x":540,"y":1200,"duration":800}
  {"action":"open","name":"微信"}           按名字或包名打开应用
  {"action":"apps"}                        可启动的应用清单
  {"action":"screenshot"}                  Android 11+ 直接截图，返回 base64
  {"action":"wait","text":"已发送"}         等这段文字出现（"gone":true 等它消失；"package":"…" 等前台换应用）
  {"action":"wait","until":"still"}        等界面不再变，直接返回这一屏（带编号）
  {"action":"scroll_to","text":"张三"}      一屏一屏翻着找，找到返回 index（"max":8、"dir":"up"）
  {"action":"wait","ms":800}               纯等一会儿（最长 5 秒）
  {"action":"swipe","x1":540,"y1":1800,"x2":540,"y2":600}
  ```

  一次调用就是一步动作，每次都回报「点了哪个控件、命中哪些边界、走的哪条路径」，
  模型据此决定下一步；`GET /help` 给全文说明。
- **权限边界**：密码、验证码、支付、把应用装到系统里的那些设置，仍然要人来做；
  无障碍服务关掉之后控制口只会回 `accessibility_off`。
- **边缘光带**（1.0.6）：操作期间屏幕四周亮一圈呼吸式的光，提示「现在它在动你的屏幕」；
  设置里能关。是独立的 `FLAG_NOT_TOUCHABLE` 浮层，不吃触摸。
- **截图时自动让开**（1.0.6）：胶囊和光带本身也会被截进去，模型看到「读屏」「暂停」会糊涂，
  所以 `screenshot` 之前先把两个浮层摘掉、拍完再挂回去。
- **用法自动装成技能**（1.0.6，1.3.3 修了路径）：App 把 `assets/phone-skill.md` 写进每个 Agent 的
  `agent_state/skills/phone-control/SKILL.md`，把 `assets/phone.js` 写到
  `$ADELIE_HOME/tools/phone.js`（`node $ADELIE_HOME/tools/phone.js screen` 就能读屏、点按、
  输入、截图，截图会落盘给路径）。启动后每分钟对一遍，新加的 Agent 也会拿到；内容没变不重写。
  设置页「操作技能」显示已经写进几个 Agent，点一下可以立刻重写。
  **1.3.3 以前装在 `<ADELIE_HOME>/agents`，可服务端的布局是 `<ADELIE_HOME>/<项目>/agents`
  （项目 id 不固定），技能一份都没落到 Agent 眼里** —— 真机上就表现为「模型说自己没有无障碍能力，
  去 shell 里试 input / uiautomator」。现在数据根下每个项目的 agents 都扫一遍，旧的别名路径也保留。
- **允许操作的应用**（1.0.7）：设置里勾选一批应用，名单非空时只允许操作它们（Adelie 自己永远允许）。
  前台应用不在名单里，任何动作直接返回 `error=app_not_allowed`；`open` 也会先过名单。
  一个都不勾 = 不限制。勾选界面是应用清单 + 搜索框（1.2.1），保存后生效。
- **任务日志**（1.0.7）：每一步都记一条（时间、动作、成功与否、错误码、当时的前台应用），
  内存里留最近 200 条，同时追加到 `$ADELIE_HOME/phone-journal.jsonl`（超过 1 MB 换一份，
  旧的那份留作 `.1`）；`{"action":"journal"}` 可以取回来回放，排「到底点了什么」很有用。
- **版本号统一从 APK 读、首页那行改成安卓版**（1.3.4）：真机上装的是 1.3.3，启动页写着「1.1.4 内测版」，
  设置页副标题和关于页一样旧；首页那行写着 `v0.6.11 · 最近更新日期 11月20日 · 最新版本 v0.8.7 有新版本可用`
  —— 那是 Adelie 本体 + 桌面版的更新检查，手机上既不是这个包的版本，还劝人升到桌面版。
  现在 `strings.xml` 里不再写死版本（`version_label` 删掉，换 `version_label_format`），
  `versionLabel(ctx)` 从 PackageManager 读 versionName、去掉 `-beta` 再加「内测版」，启动页 / 设置副标题 /
  关于页三处都用它；首页再注入一小段 JS（`injectVersionTag`）把那行改写成 `v1.3.4 内测版 · 安卓`，
  抹掉「最新版本 v0.8.7」与「有新版本可用」，并用 MutationObserver 盯着 SPA 重渲染后再改回来。
  只认「带最近更新日期 / 最新版本 / 有新版本可用，或者本身就是带 `text-gray-400` 的纯版本号」的 `<p>`，
  别的段落一个不碰（用真实 Chromium 验过：首页行改写、普通段落与纯版本号段落不动、重渲染后仍正确）。
  安卓包检查更新只走 设置 → 关于（读自己的 `android-test` 清单）。单测 +5（共 393，`VersionLabelTest`）。
- **技能落到正确目录 + `doctor` 自检**（1.3.3）：真机反馈「让它打开闲鱼，它说这台 App 没有无障碍能力」。
  查下来是 `PhoneSkill` 少拼了一层项目目录：Adelie 的 Agent 在 `<ADELIE_HOME>/<项目>/agents/<id>/agent_state`，
  技能却写到 `<ADELIE_HOME>/agents/…`，服务端扫不到 → 系统提示里没有 `phone-control` → 模型只能去 shell
  里试 `input` / `uiautomator dump` / `screencap`，被 uid 权限全挡回来，最后得出「App 没注册无障碍」的错误结论。
  现在 `agentStates()` 扫数据根下每个项目的 agents（`tools` / `tmp` 这类没有 agents 的目录自然筛掉），
  旧布局也认；新增 `{"action":"doctor"}`：无障碍 / 控制口 / 技能装了几份 / `agents` 名单 / 下一步该让用户
  做什么 / 明确写着别走 shell 那条错路——**无障碍没开时也能答**（放在开关判断之前）。技能文档开头也改成
  「第一句先跑 doctor」。单测：`PhoneSkillTest` 7（真实布局、多项目、旧布局、tools/tmp 不误认、不重写、
  被改过会补、没解包时返回 -1），`DoctorTest` 5（没开无障碍时给指引且不被当成未知动作、技能计数、
  零份时不乱报、help 里有 doctor）。

  **付款、转账、删除、卸载、退出登录这类做完退不回来的硬边界照样问** —— 省的是点头，不是刹车。
  记住的应用落盘（`control_trusted_apps`），重启还在；设置 → 手机操控 →「不再追问的应用」一行写着
  几个，点进去先问一句再清空。确认卡的四个按钮在窄屏上改成竖排，小屏也点得到
  （`screenshots/16-confirm-small.png` 就是 320×480 上的四个按钮）。
  单测锁住「普通动作信任后不问 / 别的应用不受影响 / 硬边界照样问 / 打开应用按目标应用判断 /
  本轮免确认与按应用信任叠着也不放硬边界 / 信任落盘与清空 / 点『以后都允许』只放行这一步并记下应用 /
  没有前台应用时不记脏数据」，以及设置行与清空对话框；`ConfirmCardTest` 同步到四个按钮。

- **回放页搜索**（1.1.7）：日志攒到几十步以后，人记得的往往只是一个词 ——「发送」「not_found」、

- **回放页按动作类型筛选**（1.1.6）：一轮里点按、输入、截图混着来，出了事人常常只想看

- **任务结束留一份回执**（1.1.5）：进度通知在任务结束时收走之后，通知栏什么都不剩 ——
  人往往是看着别的应用、等回头才发现「刚才那一轮做完了没有、翻车没有」。现在
  `endSession()` 会按这一轮的会话留一条安静的回执（独立 id 45，和进度通知 42 分开，
  可划掉、不响）：标题先说结果（「这一轮操作完成了」/「这一轮有 N 步没成」），正文说规模
  （「7 步 · 1 次失败 · 微信」），点开 `MainActivity` 带上 `open_journal`，直接落到回放页并勾上
  「最近一轮」，刚才那几步就在眼前。失败数在 `record()` 里跟着日志一起数，和回放页的小红点是
  同一份判断，不会两处对不上。一步都没做（只开了个任务头又停掉）不留东西；下一轮开始时
  旧回执自动收走，通知栏不会越堆越多。单测锁住文案、通知字段（id / autoCancel / 点击 extra）、
  `endSession` 的留与不留、以及 `onCreate` 与 `onNewIntent` 两条路都能开到回放页。
- **一键导出诊断包**（1.1.4）：手机上出问题时没法给开发者看 logcat，也没有 adb，
  来回问「版本多少、无障碍开了吗、后台服务起来没」既慢又容易问错。设置 → 开发者 →
  「导出诊断包」把这些一次打成一个 txt：版本号与 versionCode、包名、Android 版本、机型、
  ABI、内置服务状态与地址、四项准备检查的现状、手机操控状态（无障碍 / 前台应用 / 任务是否在跑 /
  免确认 / 允许的应用数 / 屏幕尺寸 / 后台屏是否授权）、最近 120 行运行日志（ANSI 颜色已剥掉）、
  最近 100 条任务日志；写完交给系统分享面板（`text/plain`，FileProvider 给临时读权限）。
  每一段都单独 try/catch，读不到只写一行「读不到：异常名」—— 诊断工具自己不能崩。
- **首屏提醒排队**（1.1.3）：原来那条只提醒无障碍。可「装上却用不了」还有两件事：电池优化会在后台
  把服务清掉、通知关了就看不到进度与「暂停 / 停止」。现在三件事按重要程度排队 —— 无障碍 → 电池 → 通知，
  一次只说一件，用户去开了之后自动换下一件（`nextHintKey()`，每次 `onResume` 与 600ms 的心跳都会重算）；
  「去开启」按钮跟着当前这件走（无障碍开关页 / 电池「不优化」确认框 / 应用通知设置）。✕ 只关**这一件**、
  只关到本版本（`hint_dismissed.<项目>` 记版本号），关掉电池那条不该把通知那条也压下去。
  1.1.2 及更早只有一个总开关，升级时会被认成「无障碍那条已经关过」（迁移），免得刚关掉的提醒又弹回来。

- **小屏上的确认卡**（1.1.2）：确认卡贴底弹、高度 `wrap_content`，理由一长（动作名写得详细、
  或者一串要确认的动作）就会顶出屏幕 —— 三个按钮跟着被推到看不见的地方。现在文字区放进
  `ScrollView`，`ControlOverlay.fitCard()` 先量一遍：超出屏幕上限（屏高减去上下留白、最少 220dp）
  就把多出来的高度从文字区扣掉，让它自己滚动，倒计时和三个按钮永远留在底部；屏幕太窄
  （比如 240dp）或用户把字体调大、一行放不下三个按钮时，改成竖着排，谁也挤不掉谁。
  单测用原生图形模式量真实字宽，锁住「卡片不高过上限、按钮都在卡片里、窄屏竖排、宽屏一行、
  重复适配结果不变」；`screenshots/16-confirm-small.png` 是 320×480 上那张卡的实际样子。
- **长按与输入法回车**（1.1.1）：手机操控原来只能点、滑、输入，两类界面碰不到 ——
  菜单藏在长按里的（聊天消息、桌面图标、文件），和没有可点「发送 / 搜索」按钮、只能按输入法回车的
  （微信搜索框就常常这样）。现在多了 `long_press`（按 `index`/`text` 指定控件，或给 `x`/`y`；
  `duration` 默认 800ms，挡在 400ms–5s）：先找控件自己声明的长按能力发 `ACTION_LONG_CLICK`，
  没有就退成「在控件中心按住不放」，两种都能叫出菜单。`key` 多了 `enter`（也认 send / search），
  走 `ACTION_IME_ENTER` 发给正在编辑的输入框，Android 10 及以下如实回 `error=unsupported`，
  让模型改去点界面上的按钮，而不是瞎猜。技能文档（自动装进每个 Agent 的那份）与
  `phone.js` 的用法同步更新，并加了一条单测盯着「文档里必须出现每个动作」，免得以后加了动作模型却不知道。
- **网页录像直取**（1.1.0）：1.0.18 给 `<input type="file" accept="image/*" capture>` 接上了「拍照」，

  录完直接回传网页；图片和视频都收的输入，拍照与录像两个入口都给，标题也改成「拍照、录像或从文件里选」。

- **任务日志按应用筛选**（1.0.26）：一轮任务常常横跨好几个应用（微信 → 文件管理 → 相册），

  翻车的那几步」）。副标题写的是这个应用自己的步数与失败数（`只看 微信 · 12 步 · 1 次失败`），
  该应用在日志里没记录时空状态会说明白，而不是丢一句「还没有操作记录」。收起回放页时筛选清空。

- **首屏提醒「手机操控还没开」**（1.0.25）：装上就停在对话页的人不会翻设置，而无障碍没开时
  整套手机操控都是空的 —— 模型点了没反应，也不解释为什么。现在首屏顶上挂一条细条：
  「手机操控还没开——开了 Adelie 才能读屏、点按」+「去开启」+ ✕。点「去开启」直接进系统的
  无障碍开关页，回来时 `onResume` 再查一遍，开了它自己消失，不用杀进程重开；点 ✕ 记下版本号
  （`hint_dismissed_version`），本版本内不再出现，升级到新版本会再提醒一次。停在设置页时不显示 ——
  那里「准备检查」已经把同一件事写在明面上了，重复只会变成噪音。
- **确认卡倒计时与超时区分**（1.0.24）：确认卡原本两分钟没响应就自己消失，但卡片上不写这件事，
  人回来发现没了还以为是坏了。现在卡片底部有一行「1:46 后自动取消」，只在最后 10 秒变红；
  真超时了返回 `error=confirm_timeout`（「等你确认超时了（两分钟没人点），这一步没有执行」），
  主动点取消仍是 `error=cancelled` —— 日志里一眼看出是「人没在」还是「人不同意」。
  倒计时跑在浮层自己的 handler 上，卡片一收就停，不会留个定时器在后台转。
- **更新失败留通知、一键重试**（1.0.23）：1.0.16 起校验对不上就删包，但提示只是个 Toast ——
  人在别的应用里看不到，回头还得自己想起来去设置里再点一遍。现在校验失败与「包没下回来」
  各留一条通知（`adelie_update` 安静通道，ID 43 / 44），带「重新下载」：点了打开 Adelie 并带上
  `retry_update`，界面起来后自己重读一遍清单 —— 还有新版就直接交给下载器，不再弹「发现新版本」

- **日志「最近一轮」筛选**（1.0.22）：回放页第三颗 chip。日志攒到几十上百条时，找问题只要看刚才那一轮：
  点「最近一轮」，只剩最新那段（段头仍写着这一轮几步、失了几步），再叠上「只看失败」就是
  刚才那一轮里翻车的几步。顶部「N 条 · M 次失败」说的始终是全部记录，筛选只改列表。

- **准备检查**（1.0.21）：侧载包最常见的四种「怎么用不了」其实都不是程序出错 —— 无障碍没开、

  只列出还没就绪的那几项（都就绪时整块不出现），每行一句人话说明 + 右侧「去开启」，
  点了直接送到系统的对应页面（无障碍设置 / 本应用通知设置 / 申请忽略电池优化 /
  安装未知应用）。状态判断在 `SetupChecks`（`Probes` 可按需注入，单测能喂任意组合）：
  无障碍读系统的 `enabled_accessibility_services` 认长名与 `.短名`、通知读
  `NotificationManager.areNotificationsEnabled`、电池读 `isIgnoringBatteryOptimizations`、
  未知来源读 `canRequestPackageInstalls`（8.0 以下算已允许）。
- **通知栏一键免确认**（1.0.19）：1.0.10 的通知里只有「暂停 / 停止」两个按钮，人在忙的时候
  还是要一遍遍回来看确认卡。现在中间多一个「免确认」：点一下这一轮剩下的动作都不再问，
  按钮变成「恢复确认」，副标题后面挂上「· 已免确认」；屏幕顶部胶囊的副标题也会带上同样的标记，
  免得人以为确认卡坏了。点「恢复确认」就又要点头。免确认只属于这一轮，任务结束（含 3 分钟空闲
  自动结束）就归零，不会一路带到下一轮；全局的「新任务默认免确认」还是设置里那个开关。
  **免确认省的是点头，不是把刹车拆了**：付款、转账、删除、清空、卸载、退出登录这些「做完退不回来」

  「做完退不回来，这一步总要你点头」。
- **网页拍照直取**（1.0.18）：网页里 `&lt;input type="file" accept="image/*" capture&gt;`
  以前只能从相册里挑，现在点开是「拍照或从文件里选」：拍照那一项是 `ACTION_IMAGE_CAPTURE`，
  输出写到 `cache/photos/shot-<毫秒>.jpg`，地址经 `FileProvider`（`dev.adelie.app.files`）交出去
  （带 `EXTRA_OUTPUT` 与读写临时权限，Android 7 起 `file://` 递不出去）；相机回来时 `data` 是空的，
  所以按「那个文件有没有内容」判断拍成没成 —— 有内容就把这张图交回网页，空文件当没拍（个别 ROM
  会忽略 `EXTRA_OUTPUT`）。从「选文件」里挑的那张照旧优先。只对图片生效：`video/*` 的 capture
  不会冒出拍照入口。不声明 `CAMERA` 权限，拍完也不会顺手存进相册。
- **下载完先校验再装**（1.0.16）：清单里的 sha256 从「给人核对」变成「装之前必须对上」。
  `MainActivity` 把 `release.sha256` 连同队号一起记进 prefs，`UpdateInstallReceiver` 收到
  `DOWNLOAD_COMPLETE` 后在 `goAsync()` 撑起的后台线程上把包整份读一遍算摘要（100 MB 的包
  不卡主线程，也不会让接收器超时），结果 post 回主线程再决定装不装：对得上才拉起安装器；
  对不上直接 `DownloadManager.remove(id)` 把包和通知一起删掉，提示「更新包校验没通过，已经
  删掉；稍后再试一次」；清单里没带 sha256、或者文件读不出来，一律算不过 —— 链路上只有 HTTP，
  这一条是唯一能挡住「下回来的不是我们要的包」的东西。
- **下载完自动弹安装器**（1.0.15）：`UpdateInstallReceiver` 接 `DOWNLOAD_COMPLETE`，
  只认自己排进下载器的那一单（队号记在 prefs 里，别的 App 的下载不碰），没下成什么都不做；
  8.0+ 没给「安装未知应用」时先把那个开关页打开并提示；给了就直接
  `ACTION_VIEW` + apk mime 拉起系统安装器（带读权限与 NEW_TASK）。包里因此多了
  `REQUEST_INSTALL_PACKAGES` 权限。
- **应用内检查更新**（1.0.14）：侧载的包没有商店提醒新版本，所以设置 → 关于里加了一行
  「检查更新」：读发布站的 `index.json`，按 `android-test` 那一块的文件名抠出版本号
  （`adelie-android-arm64-1.0.14-beta.apk` → `1.0.14`），只比前三段数字，比当前新才提示。
  开屏后 4 秒顺手查一次（一天最多一次，没网就算了，安静失败）；点开手动检查会给出
  「当前 → 新版（大小）」对话框，「下载」把地址交给系统 DownloadManager（公共 Downloads
  目录、通知栏进度、下完点通知即可覆盖安装），也可以「复制地址」。用的还是 HTTP 发布站，
  1.0.16 起下完会先按清单里的 sha256 校验整包再装（见上一条）。
- **服务看门狗**（1.0.13）：手机上的 node 是前台服务里的普通进程，被系统回收、被清理器杀掉都
  可能发生。进程意外退出后按 1.5s / 5s / 15s 的退避自动拉起（`Supervisor` 只看「上次撑了多久」
  和「连续失败几次」，跑够一分钟就重新计数），三次还起不来就停下，横幅说「服务反复退出」并留
  重试按钮 —— 不会把电池耗在一份必崩的数据上。用户自己点停止的不会被拉起；拉起之前会清掉旧的
  `baseUrl` 与一次性的首登链接。界面上能看到「N 秒后自动重启」。
- **深色模式**（1.0.12）：跟系统走。`values-night/` 里另有一套配色：纯黑底（不是蓝灰）、
  卡片靠 1px #1F1F1F 细线分层、正文 #F3F4F6，强调色在深底上换成亮一档的 `#8AB4F8`，
  亮蓝底上的字反过来用深色（`accent_on`）；状态栏/导航栏图标跟着切成浅色。
  切系统主题会重建 Activity（把 `uiMode` 从 `configChanges` 里去掉），界面与配色一次到位；
  顺手修掉一个真机可见的毛病：第一页还停在 `about:blank` 时，底部 tab 同步会把「对话」
  的选中清掉，导航停在错的那一项（`settings`）上 —— 现在空 URL 时不动底部。
- **网页选文件**（1.0.11）：WebView 接上 `onShowFileChooser`，网页里的 `<input type="file">`
  （聊天发图、给 Agent 加附件）现在会拉起系统的文件选择器；`accept` 是单一类型就按类型过滤，
  多种类型走 `EXTRA_MIME_TYPES`，`multiple` 打开多选，取消回调 `null`、连点两次会先把上一次
  的等待放开，选到一半退页面也会放开上游。结果自己解（`data.getData()` / `ClipData`），
  不依赖 `FileChooserParams.parseResult` 的内部实现。
- **通知栏进度**（1.0.10）：任务跑起来时通知栏有一条安静的通知（IMPORTANCE_LOW，不发声、
  不亮屏、不弹窗），标题随状态变（「Adelie 正在操作手机 / 已暂停」），正文是当前这一步，
  副标题是「第 N 步 · 应用名」，右边跑着秒表；下面三个按钮「暂停 / 继续」「免确认」「停止」，
  点了就走 `ControlActionReceiver` 广播直接改任务状态——人在别的应用里也点得到。
  浮层看不看得见都不影响，通知栏一直在；任务结束（含 3 分钟空闲自动结束）时通知自己收走。
  同一个状态 400ms 内不重复刷。任务动作（`task start/pause/stop`）现在不依赖无障碍服务，
  服务被系统关掉时也能把任务停掉。
- **任务日志回放页**（1.0.9）：设置 → 手机操控 → 任务日志，那一行直接显示「N 条 · M 次失败」
  （有失败时数是红的）。点进去是原生回放页：新的一步在最上面，左边圆点标成败，
  每行是人话（「点「发送」」）+ 动作类型 + 当时的前台应用 + 时间，失败的行下面多一行红色错误码；
  顶部可以切「全部 / 只看失败 / 最近一轮」（最近一轮与只看失败能叠着用，看刚才那轮里翻车的几步）、
  复制整份 JSONL、清空（会问一次）、关闭；点某一行会弹出这一步的原始 JSON，可以单独复制。
  收起回放页时筛选自动清掉，下次进来先看全部。数据从磁盘的 `phone-journal.jsonl` 读，
  跨重启也在（读最后 256 KB）。
- **日志按轮次分段 + 导出**（1.0.17）：每一轮任务开始的那一刻记进每条日志的 `task` 字段
  （会话开始时间），回放页照着它把记录切成一段一段：最新一轮在最上面，段头写着「任务 14:32:05 ·
  7 步 · 1 次失败」，这一轮出过事的话前面点一个小红点（和每一步左边的成败圆点同一套语汇）。
  「只看失败」也按段显示，一眼看出是哪一轮翻的车；1.0.16 之前写的老日志没有 `task`，归成
  「更早的记录」一段。筛选项右边新加「导出」：把磁盘上的整份记录（换走的 `.1` + 当前那份，
  不是回放页那 256 KB 的窗口）写成 `adelie-journal-<日期>-<时刻>.jsonl` 放到 `cache/share/`，
  再经 `FileProvider`（`dev.adelie.app.files`）把 `content://` 地址递给系统分享面板 ——
  发微信、发邮件、存网盘都行；`file://` 从 Android 7 起不能直接递出去。
- **后台屏（1.0.8，试验）**：设置 → 后台屏 → 系统弹「开始录制或投屏」，允许后建一块
  `VIRTUAL_DISPLAY_FLAG_PUBLIC` 的虚拟显示（+ ImageReader 帧流），右侧小窗实时预览；
  再用 `projection {op:"launch", package}` 把应用启动到那块显示上，`screen {"display":"virtual"}`
  读它、`tap {"display":"virtual","text":"…"}` 点它、`capture` 拿它的画面。
  安卓 14 要求的 `mediaProjection` 类型前台服务（`ProjectionService`）与授权 Activity
  （`ProjectionActivity`，透明）都齐了。**注意**：虚拟显示上只支持语义点击（按控件），
  不支持坐标手势；有些系统不允许把别的应用启动到虚拟显示，失败时 `projection launch`
  会带出系统给的原因，设置 → 后台屏自检里也能看到授权/显示 id/帧数/窗口数/最近错误。
- 设置页还能**读一下当前屏幕**：只显示读到多少控件、前台是哪个包，不发给你选的模型。
- 已知没做（dsh-go 有、我们还没有）：**系统灵动岛**那种进度显示、Shizuku / 自连 ADB 提权、iOS。
  后台屏已经是第一步（授权/虚拟显示/读屏点按/小窗），真机上能不能把别的应用拉进虚拟显示
  取决于系统，这一块等真机反馈再调。

## 构建

```bash
bash build-node-android.sh x86_64     # 模拟器验证用
bash build-node-android.sh arm64      # 真机产物
bash build-apk.sh x86_64              # 产物 build/adelie-android-x86_64.apk
bash build-apk.sh arm64               # 产物 build/adelie-android-arm64.apk
```

交叉编译踩过的三个坑（脚本里都修了）：

1. host 工具链必须显式给 —— 否则 host 的 V8 用 NDK clang 编，链接时炸；
2. `tools/v8_gypfiles/v8.gyp` 引用了 Node 24 里不存在的 `host_os` 变量；
3. V8 的 trap handler 在 Android 上要关掉（Termux 同样处理），否则
   `undefined reference to v8::internal::trap_handler::TryHandleSignal`；
   arm64 还多一个 zlib 的 `cpu-features.h`（见 `patch-zlib-cpufeatures.py`）。

## 运行时结构

```
files/adelie/
  lib/             Adelie 本体（含 node_modules）
  web/             前端构建产物
  bin/node         启动 libnode.so 的 sh 包装（PATH 上能被 `env node` 找到）
  data/            ADELIE_HOME：Agent、会话、SQLite 全在这里
  home/            HOME
  tmp/             TMPDIR（bionic 没有 /tmp）
```

启动流程：首启把 `assets/payload.zip` 解到 `files/adelie/`，然后

```
libnode.so lib/dist/penguin.js server --port 0 --host 127.0.0.1
```

从输出里认两样东西：`penguin-server started: http://localhost:<port>`（真实端口），
以及首登链接 `…/api/auth/claim?token=…`。后者是 Adelie 给「还没设过 admin 密码」的实例
准备的魔法链接，打开就下发 30 天的 `penguin_session` cookie —— 所以 WebView 直接加载它
就登进去了，手机上不需要输任何密码。

## 已知限制（这一版是测试包）

- 只出 arm64-v8a 与 x86_64 两个 ABI，没有 armeabi-v7a（32 位机器装不了）。
- 最低 Android 7.0（API 24）；`startForegroundService` 只在 26+ 存在，7.0/7.1 走
  `startService`，这条在代码里分了岔。
- APK 用工程里的 `keystore/adelie-debug.jks` 签名（口令都是 `adelie`），侧载时会提示「未知来源」。
- Node 用 `--with-intl=small-icu` 编的：`Intl` 可用，但只有英文 ICU 数据；
  `toLocaleString('zh-CN')` 之类会退化成英文格式，日期与数字格式不影响聊天主流程。
- `node-pty` 没有安卓预编译产物，Web 终端标签用不了；`bwrap` 不存在，沙箱退化为直接执行。
- 手机上先有 git/bash 之类的工具才好用（Agent 的工具调用会用到），APK 不自带。
- 前台服务用 `dataSync` 类型；Android 14 起这类前台服务有每日时长上限。
- 选文件走系统的文件选择器（1.0.11 起）：网页里点「选择文件」能用；只要图片且带 `capture`
  的输入（1.0.18 起）会多一个「拍照」，拍完直接回传，录像那种还没接。

## 工程与打包

标准 Gradle 工程（`app/src/main/{java,res,AndroidManifest.xml}`），`build-apk.sh` 只做两件事：
把 node 与 Adelie 本体摆进 `src/main/{jniLibs,assets}`，然后调 Gradle 出包。

```bash
bash build-apk.sh arm64     # → build/adelie-android-arm64.apk
```

- Gradle 8.9 在 `/opt/gradle-8.9`（`GRADLE_BIN` 可覆盖）；首次构建会从 Google Maven 拉
  AGP 8.7.3 与 AndroidX/Material，之后离线可编。
- `jniLibs { useLegacyPackaging = true }` 对应 `extractNativeLibs=true`：libnode.so 必须
  被解到 `nativeLibraryDir` 才能 exec。
- **打包前必须 `:app:clean`**：AGP 的增量打包会把上一版 74 MB 的 `payload.zip` 留在原位置，
  新的一份追加到文件尾，APK 里就多出上百 MB 死数据（曾出现 170 MB 的包）。
- 签名用工程里的 `keystore/adelie-debug.jks`（`signingConfigs.debug` 指过去）：
  环境一重置 `~/.android/debug.keystore` 就没了，换密钥就装不上旧包。口令 `adelie`。
- 工具链（JDK 17 / Gradle 8.9 / cmdline-tools + platform 35 + build-tools 36.0.0）装回
  `/opt/jdk-17`、`/opt/gradle-8.9`、`/opt/android-sdk`；`libnode.so` 与 `payload.zip`
  可以直接从旧 APK 里解出来复用，不必重编 Node。

## 界面验证（没有模拟器也能看）

这台机器没有 `/dev/kvm`，x86_64 镜像只能软件模拟，AVD 一直 system_server 重启 —— 所以界面
用 Robolectric 在 JVM 上渲染成 PNG 来验收：

```bash
/opt/gradle-8.9/bin/gradle :app:testDebugUnitTest --tests dev.adelie.app.ShellScreenshotTest
/opt/gradle-8.9/bin/gradle :app:testDebugUnitTest --tests dev.adelie.app.JournalScreenshotTest
# 图在 app/build/ui-shots/，同一份拷进了 screenshots/
# 全量单测（1.3.4 是 393 个）：
/opt/gradle-8.9/bin/gradle :app:testDebugUnitTest
```

测试会真的把 Activity 建起来、量好、画到 Bitmap 上：onCreate 里任何主题属性、布局 id、
Material 组件用错都会直接让测试失败。`JournalTest` 另外锁住日志的读盘行为（顺序、条数上限、
坏行跳过、失败计数、清空）；`JournalScreenshotTest` 直接把回放页、只看失败、空状态
和设置页那一行画成图。首次运行要从 Maven 下 `android-all-instrumented`
（~190 MB）；如果卡在 `SocketException`，把那个 jar 手动放进
`~/.m2/repository/org/robolectric/android-all-instrumented/<版本>/` 再跑。
