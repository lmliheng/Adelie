# 主题可以放在数据根里自己导入，外观页会把它列出来

- **Date:** 2026-10-23
- **Type:** feat
- **Scope:** `core`, `server`, `ui`, `web`
- **Breaking:** no

[English](2026-10-23-imported-themes.md)

主题一直只有一件事：给 UI 的那些令牌名一组取值。每个组件都只读这些名字、从不问现在是哪个主题，所以以数据
形式来的主题能重画整个应用——不用重新构建、不用插件、没有会跑起来的代码。把一个 JSON 文件放进
`<数据根>/themes/`，下一次刷新页面它就会出现在**设置 › 外观**的主题列表里，和自带的三套并列。

外观页还会写出文件该放哪儿（服务端真正读的那个目录）、某个文件哪里写错了，以及当前这套主题提供哪几个强调色
——包括主题自己的那个，也是从同一个文件里读的。

`examples/themes/warm-paper.json` 可以直接拿来改：暖色纸张底、陶土强调色，外加三个预设。

## 细节

- **格式**：`{ "schemaVersion": 1, "id", "name", "nameZh"?, "light": {"--ui-…": 值}, "dark"?: {…},
  "accents"?: [{ "id", "light", "dark"? }] }`，一个文件最多 400 个名字、12 个预设。`light` 是两种模式共同的
  底，`dark` 只写明暗不同的部分，每个预设只在自己那套主题下生效。一个值只写一行、最长 120 字符，不能含
  `;` `{` `}` `<` `\` `@` 和换行，也不能去取外部资源（`url(`、`image-set(`）：外置主题只能改这些令牌的取值，
  不能加规则、藏元素或往外发请求。
- **服务端**（`server/src/http/routes/themes.ts`）：`GET /api/themes` 给出读到的主题与读不了的文件，要登录；
  `GET /api/themes.css` 是同一批文件拼成的一张样式表，**不需要登录**——`index.html` 在 `<head>` 里就链接了它，
  而登录页也是一张页面。每次请求都重读目录（不用重启、没有缓存），一个坏文件也不耽误别人：它带着原因被列出来，
  只是不进样式表。两个文件抢同一个主题名时，后一个被拒。
- **规则**（`core/src/internal/external-theme.ts`，两端共用一份读法）写在具名的 `ui-theme` 与 `ui-accent` 层
  里，选择器是 `:root[data-theme="…"]` 且基础规则同时覆盖明暗两种模式——不分层会压过用户自选的字体搭配，而
  一次覆盖两种模式的选择器就不需要假定浏览器先读了哪张表。
- **应用侧**（`web/src/state/external-themes.ts`）做另外两处做不了的判断：令牌名是 UI 包的契约，所以这边不认识
  的名字会被列出来（它不会生效），而某个名字没写只作为提示（它沿用默认主题的值）。`state/theme-prefs.ts` 的
  读取与 `index.html` 里的预绘制脚本都改成按格式校验，不再对着固定列表：外置主题的 id 在文件还没读回来之前也
  能扛过一次刷新；格式不对的、以及没存过的值，仍然读作默认主题。
- 测试：`core/test/external-theme.test.ts`（形状与安全）、`server/test/themes.test.ts`（两条路由、坏文件、
  重名、改完下一次请求即生效）、`web/test/external-themes.test.ts`（契约判断、色卡、读取），以及跟着开放 id
  空间更新的 `web/test/theme-prefs.test.ts` 与 `ui/test/boot-script.test.ts`。

## 兼容性

- 已存数据、接口与构建产物都没有变化：没有 `themes/` 目录时，那张样式表只是一句注释，主题仍是原来那三套；对
  它来说这个链接是一次空请求。
- 文件格式带版本（`schemaVersion`）：不认识的版本会被连原因一起拒掉，不会读一半。
- 没有依赖变化。自带的三套主题没动——外置主题只能在它自己的 id 下上色。
