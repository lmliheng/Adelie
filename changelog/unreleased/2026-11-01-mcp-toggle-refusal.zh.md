# MCP Server 的开关被拒时，原因留在那一行下面，不再只活六秒

- **日期：** 2026-11-01
- **类型：** fix
- **范围：** `web`
- **破坏性：** 无

[English](2026-11-01-mcp-toggle-refusal.md)

工具 tab 的 MCP Server 表每行有一个开关（`config.enabled`）：关掉时条目与它的每个字段都保留，
只是这个 Server 不再连接 —— 插件带的桥（比如 WPS 那个）就这样停在那儿，不必删掉再加回来。
这个开关同样不做乐观写入：它把整份 `mcpServers` 列表经这块里唯一那个配置 PUT 发回去，写入
落地之前行里显示的一直是服务端记着的状态。所以**被拒**时这张表此前什么都不会变，原因只剩一条
六秒后自己消失的 toast：一颗没动过的开关，以及一句已经看不见的解释。

现在这句话留在发起它的那一行下面 —— 一条横跨表格各列的提示带：共享引子 `S.common.refused`、
danger 色、`role="alert"`、限两行、整句挂悬停。它留到下一次翻转（那是那一次点击的答复，不是
这一行的长期状态），或留到这块里任意一次写入落地为止 —— 行是按它在列表里的位置认的，而落地的
写入可能已经把它们挪过。没有新增文案。

## 细节

- `packages/web/src/features/agents/mcp-servers-toggle.ts`（新）：`flippedEnabled()` —— 一次翻转
  产出的列表，沿用原来的规则（关掉写 `false`，重新打开则删掉这个键，让条目继续跟随默认值）——
  以及 `toggleRefusalFor()`，决定哪一行可以画这句话。行按位置认、不按名字：Add/Edit 弹窗会拒绝
  重名，但手改过的配置里可能有两个同名条目，按名字画的句子会画两遍。
- `packages/web/src/features/agents/mcp-servers-section.tsx`：多一个 `toggleRefusal` 状态，由失败的
  PUT 经 `apiErrorText` 填上（不再走 `toastError`），下一次翻转开始时清空、任意一次写入落地时也
  清空；句子画在它自己那一行下面、横跨整张表。成功的翻转照旧弹一条提示并重新拉取行。

## 测试

- `packages/web/test/mcp-servers-toggle.test.ts`（新，8 条单测）：一次翻转只改一个条目（也不改传入
  的列表本身）、关掉写 `false`、重新打开删掉键、位置已经不存在时什么都不改，并且只有被拒那一个
  位置会画这句话 —— 包括「同名两条」这个按名字回答不了的情形。
- `packages/web/e2e/mcp-toggle-refusal.spec.mjs`（新，真服务端两条）：被拒的翻转把原因留在那一行
  下面的提示带里、别处没有，通知区里没有可点的 toast，开关与服务端的列表都还停在原处，并且 toast
  该消失的七秒之后那一行还在；随后放开拒绝，同一颗开关真的落地 —— 那句话消失、开关变成关、旁边
  那一行的配置一字未动，再把它打开时发出去的条目里根本没有 `enabled` 这个键。

## 兼容

- 接口、磁盘格式、请求体都没变：PUT 的正文仍是这块原本拼的那份列表。只有失败那条路不再用 toast。
