# 插件卡片的弹窗不再在安装快照落地时自己关掉

- **Date:** 2026-11-25
- **Type:** fix
- **Scope:** `web`

[English](2026-11-25-plugin-dialogs-hold.md)

插件卡片自己会开三个弹窗：「管理安装」列表、插件详情、删除确认。其中任何一个都可能开出来之后转眼
自己关掉。插件页进来时安装快照是空的，等每个 Agent 的 skills/hooks 读回来才填上；这一答把当前
Agent 装着的那几张卡片重新归到另一个分区 —— 那是另一个列表，React 因此把卡片卸载、在原处挂一个新
实例，而卡片实例自己持有的弹窗跟着旧实例一起没了。读者在那次读回来之前点下去（机器上有负载、或首次
读得慢），就看着弹窗在已经花掉那一次点击之后消失。现在「哪张卡片的哪个弹窗开着」由页面持有 —— 与
它一直以来的安装拒绝句同一个理由。

## 细节

- `packages/web/src/features/plugins/plugins-page.tsx`：页面一份状态 `cardDialog` —— `{ plugin, kind }`，
  `kind` 取 `installs` / `detail` / `delete` —— 取代卡片里的 `useState`；`PluginCard` 收 `dialog` /
  `onDialog`，三个弹窗都按它来画。
- 行上的安装 / 卸载结算后仍然把「管理安装」列表关掉：从前那一步是重挂载顺带做的，重挂载不再带走列表，
  所以改由卡片里的 `closeAfterWrite` 显式关。无论成没成都关 —— 被拒的安装，原因画在卡片下面
  （`install-refusal.ts`），列表留在上面就把它盖住了。
- `packages/web/e2e/plugin-card-dialogs-hold.spec.mjs`：三个弹窗各一条。夹具把 skills 读按住不放，
  等弹窗到了屏幕上才放它回来，于是每条用例的弹窗恰好开在这个缺陷需要的那段窗口里；分区表头的计数
  （「已安装的插件 (0)」→「(1)」）用它确认重新归档真的发生了。

## 兼容性

只改了「哪个弹窗开着」以及这份状态放在哪里。接口、数据根与成功路径都没变；行上安装 / 卸载之后列表
关掉这个行为与从前一致。
