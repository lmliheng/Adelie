# 主题文件浏览器读不了时，原因留在选择框旁边，不再是一条会走的通知

- **Date:** 2026-11-20
- **Type:** fix
- **Scope:** `web`

[English](2026-11-20-theme-import-pick-refusal.md)

超过 256 KB 的主题文件在浏览器读第一个字节之前就被拒掉 —— 而那句话落在一条盖在**打开着的**导入弹窗上的
通知里。弹窗自己于是什么都没有：选择框旁边没有文件名、确认按钮灰着，六秒之后连那句话也没了，没人说得出这次
选择为什么什么也没拿到。浏览器读取失败走的是同一条通知。

现在两句都画在弹窗自己的身体里、就在选了那个文件的选择框下面（7.19 的规矩：句子留在尝试发生的地方），
并且留到下一次选择为止。哪句话是哪句仍是一个有测试的纯函数。

## 细节

- `packages/web/src/features/settings/theme-import.ts`：新增 `pickedFileRefusal(cause)` —— 文件在送出
  之前就失败的两条路（`too_large`、`unreadable`）各有一句自己的话；两者都不是服务端的答话，所以都不走导入
  失败那张码表。
- `packages/web/src/features/settings/theme-import-dialog.tsx`：`onPickFile` 把上限那条拒绝与读取失败都
  放进弹窗自己的 `refusal` 槽位，不再 `toastError`；选择就是新的一次尝试，所以每次选择先清掉那句话，落在
  上限内的文件被收下、不留痕迹。

## 测试

- `packages/web/test/theme-import.test.ts`（+2 条，本文件共 11 条）：两个原因说的是两句不同的话、都不是空的、
  且都跟着界面词典走。
- `packages/web/e2e/theme-import-refusal.spec.mjs`（+1 条，本文件共 4 条，真服务端 + 真浏览器）：选一个
  300 KB 的文件后，句子画在弹窗里、只一条，通知区 0 条，弹窗仍在、没有文件名、确认按钮灰着，七秒后那句话
  还在；随后选一个小的文件，句子消失、文件名出现、确认按钮可用。
- **反证**：同一份 spec 挂改前产物 → 这一条失败（弹窗里根本没有那句话），没被本笔碰到的另外三条照旧全绿。

## 兼容性

只动前端渲染：接口、线上格式与已存数据都没变，服务端一句没改。256 KB 的上限没变，仍是 core 的
`MAX_THEME_FILE_BYTES`。
