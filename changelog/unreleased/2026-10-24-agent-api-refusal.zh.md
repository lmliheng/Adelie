# 智能体的 API 页：关闭访问 / 无密钥访问 / 删除密钥被拒时，框留着，原因也留在框里

- **Date:** 2026-10-24
- **Type:** fix
- **Scope:** `web`
- **Breaking:** no

[English](2026-10-24-agent-api-refusal.md)

智能体设置 › API 页上有三个会先问一句的动作：关闭 API 访问、允许无密钥访问、删除密钥。三处过去都是先关框、
再写请求，于是写入被拒的时候页面上与服务端上什么都没变（开关还是开着、那一行密钥还在），原因却落进一条六秒后
自己消失、还浮在框上方的通知里 —— 用户面对的仍是原来的样子，屏幕上没有任何一句说明这次写入为什么没成。

现在每张框都留到自己的写入落地；被拒时框留着，服务端的原话画在它自己那句话下面（`ConfirmModal` 的
`refusal` 槽，用的是应用既有的「操作被拒绝：」前缀），重试就是同一个按钮。写入在途时框上两个按钮置灰，重开这
张框会先清掉上一次的原因 —— 那句话属于上次那次尝试。

## 细节

- `features/agents/api-tab.tsx`：三张确认框（`AgentApiOffConfirm` / `KeylessOnConfirm` /
  `DeleteKeyConfirm`）不再在写之前调 `onClose()`，而是把结果交回去，由这一页只在写入落地时才关框。每处拒绝各
  有一个状态（`offRefusal` / `keylessRefusal` / `deleteRefusal`），经 `S.common.refused` 画进框里；删除密钥
  过去弹 toast，现在把服务端原话交给 `onRefused`。三个入口（API 开关、无密钥开关、行上的删除按钮）在打开框时
  先清掉各自的原因。
- 没有自己那张框的控件（打开 API、审批模式、关掉无密钥）被拒时仍用 toast：没有框可留，开关也停在服务端持有的
  那个值上。
- 新增浏览器用例 `e2e/agent-api-refusal.spec.mjs`（三条）：关闭 API、无密钥开关、删除密钥各用
  `page.route` 拒成 500 之后，框、框里那句话与服务端持有的状态都不变（通知区没有可点的按钮），重开不带旧原因；
  在同一张框上重试才真正写入 —— 框关，服务端回的是新状态。

## 兼容性

- 没有接口、传输格式、已存数据或依赖变化：只改了「框什么时候关」「原因画在哪」，以及写入在途时框上的按钮置灰。
  除既有的 `S.common.refused` 前缀外没有新文案。
