# 已有对话里发不出去的消息，原因留在输入卡上方

- **Date:** 2026-11-15
- **Type:** fix
- **Scope:** `web`

[English](2026-11-15-session-send-refusal.md)

在一条已经有内容的对话里按发送，如果这条消息没发出去（网络断了、服务端拒绝、这把模型 key 不可用），
屏幕上什么都不变：文字、附件、发送按钮原样留着，所以再按一次就是重试。原先只有一条**六秒后自己消失**的
提醒说了原因，之后屏幕上和按之前一模一样 —— 一次按压看起来根本没发生。现在原因写在**输入卡上方**那一行
（危险色、限两行、整句在悬停里），一直留着，直到下一次尝试开始。

## 细节

- 新增 `packages/web/src/features/chat/message-send-refusal.ts`：`SendRefusal`（哪条会话 + 那句话）、
  `sendRefusalLine(sessionId, err, modelId)` 组句、`sendRefusalShown(refusal, sessionId)` 决定现在该不该画。
  用词与草稿页那条首条消息完全相同，所以两边共用同一个判断（`sendRefusalReason`）与同一句文案。
- `chat-page.tsx` 的发送三条路径都改走它：任务（`onSend`）、运行中的跟进队列（`onQueueFollowUp`）、
  插话（`onSteer`，409 不算拒绝 —— 那表示本轮已结束，输入区会改写成本轮的普通任务）。每次尝试先清上一句，
  一成功就只剩空；句子按会话分开存，切到别的对话不会跟过去。
- `chat-input.tsx` 多一个可选 `sendRefusal`，画在卡片上方那一排里（与思考等级、权限预设两条拒绝句同一个位置，
  因为它们解释的都是卡片里的控件）—— 发送按钮就在它下面一行。
- 文案 `chat.sendRefused(reason)` 的中英各一句：键名从 `draftSendRefused` 改成 `sendRefused`，
  因为现在两个屏幕共用这一句，名字说的是消息而不是页面。旧键没有第二处引用。
- 文档 `chat.zh.md` / `chat.en.md` 的「发送消息」一节各加一段：发不出去时原因在上方、按钮仍是重试。

## 测试

- `packages/web/test/message-send-refusal.test.ts`（新，10 条）：句子归哪条会话、服务端答复走界面自己的话
  （带缺失密钥时的模型名）、请求没到路由时保留原话、什么都没有时用通用文案、跟随当前语言、
  与草稿页那句逐字相同；以及「同一条会话才画、别的会话不画、上一次成功后不画」。
- `packages/web/e2e/session-send-refusal.spec.mjs`（新，2 条，真服务端 + 仓库自带 mock 模型）：任务 POST 被拒
  → 句子在卡片上方（量了它的下缘在输入框上缘之上）、不是通知、文字还在、按钮仍可点、**七秒后**仍在；
  放行后按同一颗按钮 → 消息发出、句子消失。第二条：换一个错误码再按一次 → 句子换成新原因、
  **只有一行**、文字仍在。

## 兼容性

只动前端的状态与显示，接口、线上格式与已存数据都没变。
