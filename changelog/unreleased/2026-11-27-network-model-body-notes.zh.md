# 网络面板的模型行：取的过程中、取不到、本来就没有，三件事分开说

- **Date:** 2026-11-27
- **Type:** fix
- **Scope:** `web`

[English](2026-11-27-network-model-body-notes.md)

「网络」面板里一行模型调用只有边界（来自流的 `request_begin` / `request_end`），请求体与响应体是打开这一行时向服务端取的 —— 服务端把最近 100 次模型调用的请求与响应放在内存里。原来的写法是：取不到就什么也不留下，于是「请求体」「响应体」两栏落到与「这一次调用真的发了空请求」一样的 `（空）`。长会话里（一个进程内的模型调用一旦超过 100 次）打开较早的一行，或者取的过程中、或者这次请求本身被拒，读到的都是 `（空）` 三个字。

现在这三件事各有各的话：「正在向服务器取这次调用的内容…」/「服务器上没有这次调用的记录（模型调用只保留最近 100 次）。」/「取不到这次调用的内容：<服务端那句话>」。模型行是服务端发的请求，这一页从没看见它的请求头与响应头，所以那两张空表现在写「未采集」而不是 `（空）`。

## 细节

- `packages/web/src/features/network/model-exchange-pick.ts`（新）：把「哪一条记录是这一行」从面板里提出来 —— 取结束时间最近的一条，5 秒窗口之外的不算（多步回合一回合就有几次调用，窗口外的一定是别人）。原来这段逻辑藏在面板的 `useEffect` 里，且 5 秒是写死的字面量。
- `packages/web/src/features/network/network-panel.tsx`：详情里保存这次取的结果（`正在取` / `没有记录` / `被拒 + 原因`），`BodyBlock` 与 `HeaderTable` 多一个 `empty` 参数，说明这张空表在这里意味着什么；详情按行 id 挂载（`key={open.id}`），换一行时上一个答案不会跟过来。
- `packages/web/src/lib/strings{,-en}.ts`：三条新文案。
- `packages/web/test/model-exchange-pick.test.ts`：4 条，钉住最近的一条、并列时取更近的、窗口外与空环都返回 null、窗口两端包含关系。
- `packages/web/e2e/network-panel.spec.mjs` 多一条真浏览器用例：把 `model-exchanges` 答成空列表，打开模型行的「请求」页，读到的必须是那句「服务器上没有这次调用的记录」，而不是 `（空）`。

## 兼容

只改这一页在取不到内容时的说法，接口与数据没动，没有新依赖；能取到记录的情形一个字没变。
