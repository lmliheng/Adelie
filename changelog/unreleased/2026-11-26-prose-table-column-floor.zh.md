# 回复里的表格在窄屏下不再被挤成一字一行

- **Date:** 2026-11-26
- **Type:** fix
- **Scope:** `ui`

[English](2026-11-26-prose-table-column-floor.md)

Markdown 表格的样式写着「宽表格在正文里横向滚动，不把整页顶宽」，但只做了半件事：表格总是先按表格布局把每一列压向它的最小内容宽度，压不动了才开始溢出。CJK 文字的最小内容宽度是**一个字**，所以窄屏上一条四列表格会把最后一列压成一条一字的竖杠（390 px 实测：32 / 36 px 宽、十一行高），而正文根本没有东西可滚 —— 因为还没有溢出。

现在单元格有一道 6rem 的下限，列宽压到这里就不再缩，溢出于是真的发生，滚动条也就成了它原本该有的样子。下限挂在单元格上而不是给表格定宽：本来就放得下的表格布局一字未变（宽度仍由内容决定），单元格里是一段话的表格照旧换行。390 px 实测：36 px / 11 行 → 96 px / 4 行，表格本身可横向滚动；1280 px 上表格照旧铺满正文、不滚动。

## 细节

- `packages/ui/src/components/content/prose/prose.css`：`.md-body :where(th, td)` 加 `min-width: 6rem`，并在注释里写下为什么单靠 `.md-body table` 的滚动盒不够。
- `packages/ui/test/prose.test.ts`：一条新用例把这一对规则（表格上的滚动盒 + 单元格上的下限）钉住 —— 少任何一半都是回退。

## 兼容

只改排版。桌面宽度的表格外观只多出「窄列不再窄于 6rem」这一点；表格的滚动盒本来就存在，行为没变。文档站用自己的样式表，不受影响。
