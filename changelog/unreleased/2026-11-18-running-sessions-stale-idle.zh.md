# 「正在运行」不再被一条过期的状态把真正在跑的会话藏掉

- **Date:** 2026-11-18
- **Type:** fix
- **Scope:** `web`

[English](2026-11-18-running-sessions-stale-idle.md)

账号菜单里那块「正在运行」要把两个来源合起来：打开菜单时问一次项目的快照
（`GET /sessions/running`），以及用户频道一路推来的状态。合并以前是无条件的——频道里的值永远
盖过快照。频道是**唯一**会报告「运行结束了」的来源，所以它必须把 `idle` 记着；可这也意味着，
页面上早先收到过一次 `idle` 之后，这个会话的下一次运行只要没投递到（中间设备扣住响应体，正是
在网吧会遇到的），快照明明说它在跑，也会被那条陈旧的 `idle` 盖掉、再被当成「已经结束」过滤
出去：菜单写着**没有正在运行的会话**，而会话正在跑。

现在只有相对这次快照「动过」的状态才有权改写一行。请求发出那一刻频道已经持有的值，一定比服务
端自己读表更早，于是那一行由快照说了算；只有在那之后才变的状态，才可能比答案更新，才改写或丢弃
这一行。

## 细节

- `packages/web/src/features/account/running-sessions.ts`：`mergeRunningSessions(fetched, live,
  baseline)` 多一个 `baseline` 参数——发起请求那一刻的 `liveStatuses`。`live` 里与快照相同的条目不
  再覆盖该行（原来的「运行结束立刻消失」照旧，只是限定为*快照之后*的结束）。
- `useRunningSessions` 把答案与它对应的快照存在同一格里（`{ sessions, baseline }`），在 effect
  里、发请求之前读 `liveStatuses`；还没有答案时用一张空表（此时没有任何状态能算「更新」）。
- 一处已知夹缝，写进了函数注释：状态在这一次往返之内翻转又翻回来，映射看上去没动，行会保留快照
  的判定。要彻底消掉它得给每条状态带上写入时刻，代价是这个 store 的形状；这一版不换。

## 测试

- `packages/web/test/running-sessions.test.ts` 7 条：快照之后移动的状态改写行、频道此前没提过的
  状态改写行、快照之后的 `idle` 丢弃行、**快照里就有的旧 `idle` 不掩盖快照说在跑的行**（就是本次
  报的现象）、快照重复的状态由快照说了算、频道没提过的会话保留自己的状态、顺序不动。
- 真浏览器两态对照（用现网那份程序目录起临时实例 + 仓库自带 mock 模型，页面挂在能定向吞掉
  `text/event-stream` 的 TCP 中继后面）：
  - 旧产物（`index-KpKmrzbd.js`，与现网那份逐字节相同）→ 菜单显示「没有正在运行的会话」，而服务端
    接口说 `running`：用例红。
  - 新产物 → 页面自己那次 `sessions/running` 请求 200 并带回该会话，菜单显示它：用例绿；两条用例
    （健康路、中继路）全过。

## 兼容性

只动前端的一处合并逻辑与它的用例。接口、线上格式、已存数据都没变。
