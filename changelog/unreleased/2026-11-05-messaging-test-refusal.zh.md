# 消息绑定卡片的凭据探测没通过时，原因留在按钮下面，不再只活六秒

- **日期：** 2026-11-05
- **类型：** fix
- **范围：** `web`
- **破坏性：** 否

[English](2026-11-05-messaging-test-refusal.md)

消息绑定卡片里那颗「测试连接」跑的是所选通道**尚未保存**的值，服务端只探测、不写任何东西。探测没通过时
（Telegram 拒了 token、飞书的 base domain 根本连不上、微信存的机器人 token 已失效），卡片与按键前一模
一样，而原因只落进一条六秒后自己消失的通知 —— 那句话点名的 App ID、密钥与 base domain，正是它下面那几格
字段。

那句话现在画在两颗探测按钮下面（`role="alert"`、危险色、限两行、整句挂悬停），一直留到表单被编辑、切换
通道或下一次探测开始 —— 同一颗按钮就是重试。**连通的那一次仍是通知**（耗时、Telegram 的机器人名与
群组隐私提示）：那个结果没有留在卡片上的东西要解释。请求本身没到服务端时，现在念错误码自己的本地化句子，
而不是它的线上英文原文 —— 全应用拒绝位早就按这条规则走。

## 明细

- `packages/web/src/features/messaging/messaging-test-refusal.ts`（新）：`messagingTestRefusal(...)` ——
  纯判断，念哪句话只在这一处，不依赖卡片就能测。
- `packages/web/src/features/messaging/messaging-binding-editor.tsx`：hook 多一个 `testRefusal` 状态 ——
  探测的失败分支写上（原来走 `toastError`），表单编辑、切换通道、切换会话、下一次探测开始各自清掉；卡片
  把它画在两颗探测按钮下面、前提提示上面。四条通道各自的探测调用收成一个答复形状，只有连通那条分支还分开
  （Telegram 的通知照旧）。

## 测试

- `packages/web/test/messaging-test-refusal.test.ts`（新，6 条）：连通的答复什么都不留；平台的细节原样
  带上；无细节退回通用句；没到服务端的请求按 `refusalText` 读（不念线上原文）；客户端自己抛的错误保留原话；
  用的是当前语言。
- `packages/web/test/messaging-binding-editor.test.ts`：加一条渲染用例 —— 那句话只出现一次、在探测按钮与
  凭据字段之间、限两行且整句挂悬停，没有失败时一条都不画。
- `packages/web/e2e/messaging-test-refusal.spec.mjs`（新，真服务端 + 真浏览器）：给一个会话绑定飞书，把
  探测路由桩成三种答复。被拒时那句话出现、通知区里没有它，**7 秒后**仍在；改一格字段后它消失，重试的探测
  （这次连通）带的是改过的值、并以通知报出耗时；路由 500 时画的是错误码自己那句。

## 兼容性

不碰接口、不引入新依赖、不改 Project 配置。旁边那颗「发送测试消息」仍走通知：它失败之后要改的东西在聊天
平台那一边，不在这张卡片的字段里。
