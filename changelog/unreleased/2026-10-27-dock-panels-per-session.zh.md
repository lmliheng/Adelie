# 停靠面板只属于各自的 Session

- **Date:** 2026-10-27
- **Type:** fix
- **Scope:** `web`
- **Breaking:** no

[English](2026-10-27-dock-panels-per-session.md)

每个停靠面板现在只属于屏幕上的那个 Session。此前有几条自动路径在切换之后的一次渲染里还拿着上一个
Session 的数据，于是操作了刚切过去的对话：子智能体面板可能在它从未派生过子会话的会话里打开、下一个
对话的面板可能执行上一个对话点过的文件链接或记忆条目、需要确认的标签关闭若答复得晚就会关掉别处的同类
面板、首次发送若在用户离开之后才完成还会把用户拽回新 Session。

## 细节

- 浏览器：「面板显示时保留一个标签页」这条规则判断面板是否显示时，改为问**效果运行那一刻**的停靠栏，
  而不是那次渲染的插槽。切换对话时停靠栏先变，离开的那个对话的面板还会多挂载一次渲染、插槽仍然可见 ——
  规则此前会因此给刚切过去的对话新开一个页面。
- 子智能体面板：`useSessionStream` 现在会写明它的状态属于哪个 Session
  （`SessionStreamState.sessionId`）。切换后的那次渲染仍带着上一个 Session 的模型与任务状态，跟踪器
  现在会忽略它；面板只在屏幕上的停靠栏属于该 Session 时才打开。
- 首次发送与自愈的 id：`adoptDockScope(from, sessionId, stillOpen)` 只移交 `from` 自己的布局、不碰屏幕
  上的那份，并返回「用户是否仍在 `from` 上」——草稿页与自愈路径据此才跳转。已经切走的用户留在原处，
  新 Session 照常出现在侧栏，布局也照常随它移交，除非屏幕上同一 Project 的另一张草稿页正用着这份布局。
- 草稿在发送开始时记下自己的停靠 scope，并用 `openRef` 记录自己那一页是否还挂着：发送比页面活得久时
  布局照样移交，但不跳转。
- 交给面板的请求（文件链接、记忆条目、子会话 chip）改为在「渲染到另一个对话的路由时」丢弃，而不是渲染
  之后再靠效果清除 —— 下一个对话的面板因此不会带着上一个对话的请求挂载一次。
- 需要确认的标签关闭（文件面板有未保存的编辑）只在「当初发起关闭的那个对话仍是屏幕上这个」时才真正关闭。
- `dock-state.ts`：写 scope 映射的那段收成 `writeScopes()`，由 `persist()`、scope 切换与移交三处共用 ——
  移交移动的是映射本身，此时写一遍当前布局会把布局放回它刚离开的那个键上。
- 移植自上游 `ce9b3e69`（#1335），照改动落、不是合分支。**有意未取**（本树没有它们要用的东西）：浏览器
  那一半里与「对话自己的标签页」比对的部分（`wantsNewTabPage` 的 `{ conversation, browserShown }` 形状与
  上游 #1105 的 `state.scope` / 按会话分片的标签页 —— 本树的浏览器状态是整个窗口一份标签表）；终端面板
  在关闭自己前重新核对 `dockSessionId()`（`features/terminal/terminal-panel.tsx` 在本树不存在）；自愈
  路径里的 `adoptBrowserSession` / `reownTerminals`（本树没有这两个函数）；它那份 jsdom 用例
  （`test/builtin-browser-sessions.test.ts`，本树不装 jsdom，改由真浏览器取证）。

## 兼容性

- 不改依赖、不改已存数据、不改包名与配置格式。`penguin.dock.layout` 的格式未变，已有的布局照常读取。
