# 换布局不再丢掉读者看到的那一行

- **Date:** 2026-11-19
- **Type:** fix
- **Scope:** `web`, `ui`

[English](2026-11-19-files-reading-across-layout.md)

文件面板是一块停靠面板：窗口跨过断点（宽窗口的右侧栏 ↔ 窄屏的合并面）时，同一个标签页被搬到另一侧重新挂载。
「打开的是哪个文件、展开了哪几层」上一轮已经留住了，**「当时是怎么看它的」**没有：Markdown / HTML 的「预览 / 源码」
退回「预览」，预览与树这两个框都回到最上面。真浏览器里量出来是这样：一份很长的 Markdown 切到源码、往下滚了半屏，
跨过去回来又变成渲染后的最上面；树滚到 `row-06`，回来又从 `row-01` 开始。

现在这三样跟着同一处地方一起走，规则不变：**只有「换布局」才把它们交回来**。同一个标签页关掉再打开、会话切走再
切回来，面板依旧从树根、按渲染、从最上面开始。

## 细节

- `packages/web/src/features/chat/workspace-view-memory.ts`：记录多三项 —— `reading`（`"rendered" | "source"`）、
  `previewScroll`、`treeScroll`（`{ top, left } | null`）。「与刚打开时无异」的判据也跟着扩：还得按渲染、两个框都在
  顶上，才整条删掉；反过来，**没开文件但树滚下去了也是一处地方** —— 那几行对重新挂载来说和打开的文件一样会丢。
  两个偏移与展开项一样，进出各拷一份。
- `packages/web/src/features/chat/workspace-browser.tsx`：
  - 「渲染 / 源码」给切换按钮做初值，并在文件回来时作为 `previewPath` 的 `reading` 交回去 —— 于是读者自己的选择
    压过「过大的 Markdown 默认打开源码」那条规矩（那是默认，不是读者知情的决定）。这个选择属于那个文件：之后
    再打开别的文件仍从「预览」开始，和以前一样。
  - 两个偏移在各自框的 `scroll` 事件里直接读、直接写进记录（不走 React 状态 —— 滚动按刷新率发生，屏幕上没有别的东西
    依赖它），所以换布局来得比下一次状态变化更早也照样拿得到。预览的偏移与它所属的路径绑在一起存，打开另一个文件
    不会把它带过去。
  - 交回时不用挂载效果，而是两个 layout 效果各等自己的东西就位：预览等它那个文件上屏（在那之前画的是骨架），
    树等每个展开目录都列完、并且树真的画着（窄屏上开着文件时树不画）—— 早一步滚只会被夹住。
- `packages/ui/src/components/files/file-tree/file-tree.tsx`：新增 `bodyRef` 与 `onScroll`，把树自己的滚动盒交出去
  （它的布局与滚动本来就归调用方，`className` 就是这么来的），面板因此不必伸进 DOM 里找滚动盒；
  `workspace-tree-view.tsx` 把两者透传下去。

## 测试

- `packages/web/test/workspace-view-memory.test.ts`（9 条，+2）：没开文件但树滚下去了也算一处地方；`reading` 与两个
  偏移随文件一起回来；拷一份的断言覆盖到偏移对象。
- `packages/web/e2e/files-reading-across-layout.spec.mjs`（新，3 条）：① 长 Markdown 切「源码」后跨 1280 → 390 → 1280，
  三刻都是「源码」按下，且之后另开一个文件仍是「预览」；② 预览滚到 240 后往返跨断点，仍在原处；③ 不选文件、把树
  滚下去后往返跨断点，仍在原处。
- 同一份 spec 的反证（改前源码 + 改前产物）：**3 条全红** —— 选择退回 `预览: true`、预览与树都回到 0。放回改后源码
  重建，产物与留底**逐字节相同**。
- 两态探针：改后三刻都是 `source true / previewTop 240 / treeTop 160`；改前跨过去之后是 `source false / previewTop 0 /
  treeTop 0`。

## 兼容

只动前端状态：接口、线上格式、已存数据都没变。这一处只活在内存里，刷新页面仍是从树根、按渲染、从最上面开始
（与本笔之前一致）。
