# 会话分页读取时，记忆更新卡片不再丢失

- **Date:** 2026-10-14
- **Type:** fix
- **Scope:** `server`, `web`

[English](2026-10-14-memory-updates-pagination.md)

移植自上游 PenguinHarness（#1138，提交 `d51c4577`）。

打开一条很长的会话时，记忆更新卡片可能整块不见，尽管它对应的文件其实已经改成功了。原因是：历史窗口可能
从 `session_meta` 那条记录**之后**开始，而 Agent State 目录正是那条记录带着的 —— 于是流模型手里没有
`<agent_state>/memory/` 这个根，认不出哪些文件写入属于记忆。

现在历史分页的信封里带上「窗口起始那个上下文记录下来的」Agent State 目录，流控制器在回放这一页之前先把它
填进去。打开会话、往上加载更早的消息、断开后重连，三种情形下卡片都回来了；同一个话题被反复编辑仍只画一行，
对记忆索引的编辑照旧不算。没有给 OmniMessage 增加字段，也没有改写已存的 Trace 或记忆文件。
