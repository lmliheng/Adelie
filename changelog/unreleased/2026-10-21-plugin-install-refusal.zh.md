# 安装模块插件被拒时，确认框留着，原因也留在框里

- **Date:** 2026-10-21
- **Type:** fix
- **Scope:** `web`
- **Breaking:** no

[English](2026-10-21-plugin-install-refusal.md)

插件市场里给项目安装（或移除）一个模块插件要先确认，而那张卡片过去在 `finally` 里关掉：成功与失败一样关。
于是被拒的安装虽然什么都没装（那一行仍在「未安装」），原因却跟着框一起没了；那句话只出现在一条六秒后自己
消失、且浮在框上方的 toast 里。

现在只有写入真的落地，卡片才关。服务端拒绝时，卡片留着它那句话，服务端的原话画在下面，于是重试就是同一个
按钮 —— 装插件失败本来就是最常见的那种拒绝。

## 细节

- 规则沿用模型库、定时任务与评估中心那几轮（`ConfirmModal` 的 `refusal` 槽）：原因画在发起写入的那张卡片
  里，而打开这张卡片时先撤掉上一次的原因 —— 那句话说的事是上一次。
- `features/plugins/plugins-page.tsx`：`setPendingApply(null)` 搬进成功那一条，`catch` 把服务端的原话交给
  新的 `applyRefusal` 状态，不再弹 toast；两个打开卡片的入口（安装 / 移除）合并成 `askApply`，落「先开框、
  再清旧原因」的写法。
- 新增浏览器用例 `e2e/plugins-install-refusal.spec.mjs`（两条）：被拒的安装留着卡片、句子与那一行，不弹
  toast、不改变任何状态；重试真的写进去，而只有写成功的那一次才关框。

## 兼容性

- 没有接口、传输格式或依赖变化；只改了卡片什么时候关、拒绝提示画在哪。
- 同一页里「批量更新」与「单 Agent 的卸载 / 更新」那几张卡片仍是旧的「发出即关」，见台账的「还差什么」。
