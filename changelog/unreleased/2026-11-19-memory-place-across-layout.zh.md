# 换布局不再把记忆面板拽回列表顶上

- **Date:** 2026-11-19
- **Type:** fix
- **Scope:** `web`

[English](2026-11-19-memory-place-across-layout.md)

记忆面板同样是一块停靠面板：窗口跨过断点（宽窗口的右侧栏 ↔ 窄屏的合并面）时，同一个标签页被搬到另一侧重新挂载。
上一轮那条线修的是「命令不重放」—— 读者按「返回列表」之后跨断点不会再被拽回那条记忆。**读者自己停在哪一层、
滚到哪一行**没有留住：正在读一条记忆，跨过去就退回列表；列表往下滚了半屏，跨过去就回到顶上。真浏览器里量出来
是这样：一条 41 段的记忆滚到 600 px，跨到 390 那一刻变成列表；列表滚到 400 px，跨过去是 0。

现在面板自己的位置跟着一起走，规则与文件面板那一处相同：**只有「换布局」才把它交回来**。同一个标签页关掉再打开、
会话切走再切回来，面板依旧从列表顶上开始。

## 细节

- `packages/web/src/features/chat/memory-place.ts`（新）：按会话记一处位置 —— 所在的停靠面、读者停在哪一层
  （列表 / 某一条记忆）、列表的偏移、那条记忆的偏移。与文件面板的 `workspace-view-memory.ts` 同一套规则：只有新挂载
  落在**另一个**停靠面时才交回（换布局落别处，换会话与重开标签页落回原处）；「与刚打开无异」（列表、在顶上）的记录
  整条删掉，不留一个「什么都没有」的地方等下一次换布局；记录是快照，进出各拷一份。
- `packages/web/src/features/dock/panel-context.tsx`：`DockSurface` 挪到停靠面自己的模块里（它就是「这块面板画在哪」的
  说法），文件面板那处改为从它导入并原样转出，读它的人一行不用改。
- `packages/web/src/features/chat/memory-view.tsx`：
  - 挂载时读一次记录作为初始位置；`goTo()` 收下所有导航（行、返回、页面的跳转命令），每次写完记录 —— 偏移属于它
    所在的那条记忆，换一层或换一条就作废（那条记忆从顶上开始，和以前一样）。
  - 两个偏移在各自滚动盒的 `scroll` 里直接读、直接写进记录（不走 React 状态）。
  - 交回交给两个 layout 效果各等自己的东西就位：列表等行（或空态 / 报错）画出来，记忆正文等那次读取落地 ——
    早一步设偏移只会被夹回 0。
- `packages/web/src/features/chat/builtin-dock-panels.tsx`：记忆面板那条体从 `useDockPanel()` 取所在表面
  （`merged ? "merged" : position`）交给面板，与文件面板同一写法。

## 测试

- `packages/web/test/memory-place.test.ts`（新，9 条）：没去过就没有；另一个停靠面才交回；同一个面不交回；两个会话
  互不相干；「列表、在顶上」整条删掉；只有列表滚下去也算一处地方；工作区作用域的键带 scopeKey；进出各拷一份；层级
  对应的键与 `memoryRowKey` 一致。
- `packages/web/e2e/memory-place-across-layout.spec.mjs`（新，3 条）：① 打开长记忆、滚到 600 后跨 1280 → 390 → 1280，
  三刻都是那一条、都在 600；② 列表滚到 400 后往返，三刻都是列表、都在 400；③ 打开记忆再按「返回列表」，跨过去仍
  是列表（不弹回那条记忆）。
- 同一份 spec 的反证（改前源码 + 改前产物）：**2 条红** —— ① 390 与跨回 1280 都是 `detail: 0, scroll: null`（退回列表）；
  ② 列表的 400 变成 **0**；第三条改前就绿（它讲的正是「返回列表之后仍是列表」）。
- 两态探针（同一脚本两条腿各挂自己的产物）：改后三刻都是 `{"detail":1,"scroll":600}`、列表 `400 → 400`；改前
  `{"detail":1,"scroll":600} → {"detail":0,"scroll":null}`、列表 `400 → 0`。

## 兼容

只动前端状态：接口、线上格式、已存数据都没变。这一处只活在内存里，刷新页面仍从列表顶上开始（与本笔之前一致）。
