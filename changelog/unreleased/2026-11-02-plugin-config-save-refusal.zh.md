# 插件卡片保存被拒（而服务端没点名字段）时，原因留在卡片上，不再只活六秒

- **日期：** 2026-11-02
- **类型：** fix
- **范围：** `web`
- **破坏性：** 无

[English](2026-11-02-plugin-config-save-refusal.md)

设置 →「插件」每张卡片自己保存。服务端校验不过时会点名字段，那句话画在字段下面 —— 这一半一直
是对的。但保存还能以别的方式失败：这个配置组在页面底下没了（插件或后端被卸掉，404
`plugin_config_unknown`）、登录过期、服务端出错、机器连不上。这些都不点名任何字段，而此前它们只进
了一条六秒的通知 —— 通知一走，卡片上每一个输入框都还是原样，看上去就像「点了没反应」。

现在这类失败那句话画在卡片里、保存按钮的正上方（保存按钮就是重试）：`role="alert"`、危险色、限两行、
整句挂悬停，引子复用共享的「操作被拒绝：」。它留到下一次点保存（那时先清空）或换了机器 / 重新打开
这一页（一次新的读）。

## 细节

- `packages/web/src/features/settings/plugin-config-save.ts`（新）：`pluginSaveRefusal(error)` ——
  一次被拒的保存该落在哪一格：`plugin_config_invalid` 且消息以 `"<字段>"` 开头就交回那个字段名
  （表格单元格的 `<字段>.<行>.<列>` 原样带过去，表格自己会在下面列出来），其余一律交回卡片。
  文案仍走 `refusalText()`：应用有说的按码说，没有的就照服务端写的那样说。
- `packages/web/src/features/settings/plugins-section.tsx`：多一个 `saveRefusals`（按卡片名记），
  保存开始时清掉这一张的、失败且没点名字段时写上、改动机器或重新挂载时整体清空；`toastError` 从这
  条路上撤掉（安装那条路一个字节没动）。点名字段那一支原样保留，只是判定搬进了上面那个纯函数。
- 没有新文案、没有新接口、没有新依赖：那句话用的是共享的 `S.common.refused()` 引子。

## 测试

- `packages/web/test/plugin-config-save.test.ts`（新，7 条）：点名字段 → 字段格；单元格全名原样带过去；
  `plugin_config_invalid` 却不在开头点名 → 卡片；404 / 500 / 401 → 卡片（有译文的码按译文说）；
  客户端自己抛的失败用它自己的句子；什么都没有时用通用失败；跟着界面语言走。
- `packages/web/e2e/plugin-config-save-refusal.spec.mjs`（新，真服务端一条）：读桩成一张只有文本框的
  卡片、写桩成 500 `internal` —— 点保存后卡片上一条句子、完全没有通知、输入框里的值没变、七秒后仍在；
  放开拒绝再点一次同一颗保存按钮：句子消失、第二次请求发出、保存落地。

## 兼容

- 接口、请求与存储都没变：还是同一个 `PUT /api/admin/plugin-config`。改变的只有「没点名字段的失败」
  画在哪里 —— 从通知里挪到卡片上。
