# MCP Server 可以停用，而不必删掉

- **Date:** 2026-10-18
- **Type:** feature
- **Scope:** `core`, `web`, `docs`, `plugins`
- **Breaking:** 否 —— 没有 `enabled` 的条目行为与以前完全一样

[English](2026-10-18-mcp-server-enabled-switch.md)

Agent 设置里的 MCP Server 区块现在每行都有一个开关。关掉之后，条目和它的每个字段都留在配置里，但任何一轮都不会连接这个 Server，它的 `mcp__*` 工具也从工具列表里消失。此前想让它「别再每轮都连一次」，只能把条目删掉、以后要用再重新填一遍 —— 插件装上的桥（比如 WPS 加载项的桥）于是即使不用也一直留在每一轮对话里。

## 细节

- 开关往条目的 `config` 里写 `enabled: false`；再打开时把该键删掉，开着的条目继续跟随默认值。同一个字段也可以在 `system_config.yaml` 里手写，文档（`/docs/tools` 的 MCP Servers 一节）中英文都已写明。
- core 的解析在**看传输方式之前**就丢掉停用的条目：停用的条目目标已经不存在（插件卸了、桥没了）也不会每轮报一条警告，更不会把会话弄失败。
- `enabled` 必须是布尔值。带引号的 `"false"` 会被判为无效，而不会被悄悄当成「开着」。
- `POST /config/mcp-test` 对停用的条目照常能测，所以可以先测通再打开；测试不保存任何东西。
- WPS 加载项的桥不再对它记住的、已经不存在的会话无限重连：会话流返回 404/410 时停止订阅并在 info 级别记一条。此前它把每一次失败都当临时故障，于是每 10 秒写一条警告，永不停止。
