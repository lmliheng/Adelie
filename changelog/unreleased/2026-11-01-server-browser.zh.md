# 服务器自己跑一个浏览器：没有桌面窗口的机器也能看网页

- **Date:** 2026-11-01
- **Type:** feature
- **Scope:** `server`, `web`, `ui-gallery`, `docs`

[English](2026-11-01-server-browser.md)

侧栏多了一个**服务器浏览器**页面：浏览器进程跑在服务端那台机器上，画面实时传到页面里，点击、滚动和打字都从页面传回去。

内置浏览器做不到这件事。它的页面是桌面应用窗口里的元素，所以用浏览器打开 `penguin web`、在 Docker 里、或者访问一台远程机器，都没有浏览器——`penguin browser` 在这些场合回答 `browser_unavailable`。这个页面正相反，它只要求服务器上有一个 Chromium 或 Chrome：给它一个虚拟显示器，它就是一台正常的窗口浏览器，而不是无头模式——无头 Chromium 认不出很多站点，也常常放不出视频。

只有管理员能用：启动会在服务器上拉起一个进程，而它用的浏览器配置是整机共用的。

## 画面用一条 MJPEG 流

`GET /api/server-browser/frames` 回的是 `multipart/x-mixed-replace`，也就是一个 `<img>` 天生就能播的东西。页面上因此没有 canvas、没有帧解码、没有 WebSocket——栅格化由那台机器上的浏览器自己做，页面只负责显示结果。落后时丢帧而不是排队：看画面的人要的是最新的一张，不是一堆积压的旧图。没有观众时，浏览器那边的录屏整个不启动，静止的页面因此也不耗什么。

## 最后一帧不会停在上一张

一条 `multipart/x-mixed-replace` 的流里，浏览器要等到下一段开始，才会把上一段取上来显示。页面一直动的时候这看不出来，页面只重画一次的时候就是致命的：点一下画面、页面变了，可画面里显示的还是点之前那张——看着就像点击没生效。所以一帧写出后 150 毫秒内没有下一帧时，它会被再写一遍；被取走的是这一份，画面因此立刻是最新的。一直在动的页面照原样，一帧也不多写。落后时丢帧的规则也一样：丢的是被替换掉的旧帧，不是最新那帧。

## 地址和标题来自浏览器的历史记录

画面的像素里没有地址栏，所以页面每 1.2 秒读一次状态。标题不能取浏览器给目标报的那一个：一个明明带着 `<title>` 提交的页面，在目标的报告里仍然写着主机名——`example.com/` 报成 `example.com`，本机地址报成 `127.0.0.1:38809`——而回看浏览历史里那一条是对的。所以标题问的是历史记录，不是在页面里跑脚本。

## 页面按窗口的框重绘

画面不是把一张固定尺寸的图缩小了放上来：页面按这块区域量到的大小去重绘服务器上的页面（收敛在 320×240 到 1920×1200 之间）。所以窗口拉窄，里面的网页也跟着变窄，而不是变成一个看不清的小图。输入坐标按 `object-fit: contain` 实际画出来的那块区域换算，上下或左右留白时点击也不会偏。

## 它是谁的浏览器

打开这个页面就会启动它（画面请求送达即为请求），关掉页面它**继续运行**——它不是页面的附属物，别人打开看到的是同一个浏览器和它那一个页面。要真放掉它，用工具栏最右边的停止按钮。登录状态留在数据根目录的 `browser-profile` 里，重启和升级都还在。应用被热替换或结束时，这个进程随它一起下去，不会留下两个浏览器抢同一份配置。

## 做不到和前一台机器一样的事

服务器上没有 Chromium 或 Chrome、或者被 `ADELIE_SERVER_BROWSER=off` 关掉时，状态读出来是 `available: false` 加一句原因，页面照原样显示，任何路由都不会去启动进程——这是配置事实，不是故障。浏览器装在别处时用 `ADELIE_SERVER_BROWSER_BIN` 点名。

这个页面只有一个页面、没有标签页：它存在的意义是看一个自己的机器够不到的页面，而第二个标签页正是「窗口管理器」的开始。桌面应用那套多标签留在那里。

## 门槛在能看，不在能刷

画面、点击、滚动、键盘都通。至于用一个数据中心 IP 的浏览器登录某个平台、或者让视频起播——那是那个平台的风控和登录问题，跟这个页面能不能显示无关。一个默认 UA 的浏览器打不开某些站点（会撞上验证码中间页），而这样的站点在真实桌面浏览器里也会要求登录。

## 输入法还接不上

传回去的是键盘事件：字母、数字、符号、回车、Tab 和方向键都能到那个页面；中文这类要输入法先组合、再整段交出来的字还传不过去——组合发生在你自己这一侧，那边还没有一个接住它的地方。这是下一步要补的，不是配置问题。
