# 记忆页选中的文件没有导入成时，原因留在那一组里

- **日期:** 2026-11-11
- **类型:** 修复
- **范围:** `web`
- **破坏性变更:** 否

[English](2026-11-11-memory-import-refusal.md)

记忆页每一组的标题条上，主人还有一颗「导入」：它是包着文件输入的那个标签，读到选中的导出文档就打开导入框。选中的
文件不是记忆导出文档时，那个框根本不会打开 —— 而唯一解释原因的那句话是一条六秒后自己消失的通知，它浮在列表上方，
而读者刚才是对着某一组的标题条选的这个文件。什么都没发生、框没开、过了一会儿也没有任何东西再提这件事。

这正是 7.19 禁止的形状，也是记忆页在导出（7.109）、技能页（7.101）、钩子页（7.103）、插件卡片（7.107）各自改过
之后还剩下的一处通知。原因现在画在那一组里、与导出的拒绝共用同一个槽（`role="alert"`、危险色、最多两行、整句挂
悬停），留到下一次尝试开始为止。宿主是那一组，是因为**文件选择器就是这一组自己的控件** —— 句子就贴在打开它的那条
标题条下面，组折起来时也照样看得见。选到真的文档时，句子清掉、导入框照旧打开，所以重试还是同一个控件，不必再去找
别处。

句子说「这个文件没有读成，记忆一条都没有被改动」，这确实是实情：解析就在页面里做，一个请求都没有发出去。

## 细节

- `packages/web/src/features/agents/memory-group-refusal.ts`（原 `memory-export-refusal.ts`）：一组记忆
  整组转移的两个方向共用这一个模块 —— 它们挂在同一条标题条上、画进同一个槽。`MemoryGroupRefusal` /
  `memoryGroupRefusalFor` 决定这句话归哪一组（按**键**而不是按标题：两个工作区的目录可能叫同一个名字）；
  新增 `memoryImportRefused(scope, error)` —— 文档解析错误保留它自己的本地化句子（「这个文件里没有记忆。」
  不会被压成「不是记忆导出文件。」），读文件时别的原因（File API 自己的拒绝，消息是浏览器原话、从不本地化）
  则落到「这个文件不是记忆导出文件。」。
- `packages/web/src/features/agents/memory-tab.tsx`：组的 `notice` 槽改由一个 `groupRefusal` 承载（后一次尝试
  盖掉前一次，不分方向），不再是只服务导出的那个；`pickImport` 失败不再 `toastError`，写进它，并在选文件开始时
  先清上一句。槽的测试 id 现在是 `memory-refusal`。
- `packages/web/src/lib/strings{,-en}.ts`：新增一句 `memory.importRefused(scope, reason)`。

## 测试

- `packages/web/test/memory-group-refusal.test.ts`（由 `memory-export-refusal.test.ts` 改名，现有 14 条）：导出
  那九条原样，另加导入五条 —— 文档自己的话保留、File API 的失败落成「不是记忆导出文件」而不是浏览器原文、念出组名、
  点明文件没有读成、英文那一句。
- `packages/web/e2e/memory-group-refusal.spec.mjs`（由 `memory-export-refusal.spec.mjs` 改名，现有 4 条，真服务端
  \+ 真浏览器）：导出那两条原样；另加一条选中 `.txt` 时那一组里逐字出现这句话、导入框没开、通知区 0 条、**没有任何
  发往记忆路由的 POST**、七秒后仍在且折起来也看得见，换成真的文档后句子消失、导入框打开；还有一条：先被拒的导出
  紧接一次坏文件，一组只显示后一次的那句话。

## 兼容性

线上接口没变、没有新依赖、Project 配置没变。导出的那句话、组里的其它动作、以及导入框自己的拒绝（服务端拒绝的
一次导入，画在发问的框或确认框里）都一字未改。
