# 列表行的操作始终可见，无论文字多长

- **Date:** 2026-10-17
- **Type:** fix
- **Scope:** `ui`, `ui-gallery`

[English](2026-10-17-list-row-actions-visible.md)

移植自上游 PenguinHarness（#1157，提交 `ef12d442`），并一并落下 #1157 所依赖、本 fork 还没取的 `#1133`（`5d01f6a4`）里那一段列表行布局。

上游的原始报告：在 Agent 设置 → 记忆中，只要有一条记忆的说明很长，所在分组的每一行都会排得比卡片更宽，卡片于是把每一行的查看、编辑、删除按钮都裁掉了，说明很短的行也不例外；说明再长一些，连日期也会被挤出去。修复落在 `packages/ui` 的共享列表行与可折叠分组上，所有基于它们的列表都随之生效。

## 细节

- `CollapsibleSection` 把分组主体限制在卡片宽度内（折叠网格的子项设 `min-width: 0`，与 `Fold` 的做法一致）。此前主体的 `auto` 列会撑到子项的最小宽度，而截断的行用 `nowrap`，最小宽度按文字的完整长度算。
- `ListRow` 不再按文字宽度向容器要空间：标题与说明放在单列 `minmax(0, 1fr)` 网格里，因此一行最窄只需容下标志、日期与操作，不论放在什么容器中。标题与说明仍各截成一行、悬停显示全文。
- 日期与操作保持原有宽度，放不下时整组换到文字下方（行上 `flex-wrap`、文字上 `basis-40`，日期与操作收进一个可换行、右对齐的组）。这段布局来自 `#1133`；#1157 自带的 gallery 检查正是在最大字号下量它 —— 少了它，220 px 宽的卡片会把三个操作按钮裁掉。
- `ListRow` 对字符串形式的标题或说明最多只放 1,000 个字符到页面上，末尾加省略号，完整文字放进该行的悬停提示；说明再长，一行的排版开销也至多相当于一千个字符。
- 组件库的数据看板新增一组带超长文字的记忆行；gallery 新增 Playwright 检查（`pnpm --filter @adelie/ui-gallery test:e2e`），在每个主题与语言下、于看板原宽及收窄到 360 / 280 / 220 px 时，逐一量出每行与每个操作是否都在卡片之内。该 spec 不归 vitest：gallery 的 vitest 收窄到 `test/**/*.test.ts`。
- `test/list-row.test.ts` 里两条既有断言跟着新的标记走：行自己的类名字符串、以及日期与操作位于那个组里、仍在开合按钮之外。

## 本 fork 的差异

- 折叠仍然裁在主体那一格（`overflow-hidden`），而不是上游后来的「裁在网格上」（`overflow-clip`，本 fork 还没取那一笔）。而 `overflow: hidden` 本来就把那一格的最小尺寸归零，所以本树从未出现上游那个「卡片被撑宽」的现象：在真服务端 + 真浏览器上（Agent 设置 → 记忆，三条记忆、其中两条的说明各几百字），1280 / 1024 / 768 / 390 / 320 px 下两态的行与操作都落在卡片之内。本笔在本树改变的是**一行向容器要多少宽度** —— 行的 min-content 从 5417 / 5576 / 513 px 降到 120 px，在 390 px 宽 + 最大字号下从 6759 / 6958 / 629 px 降到 138 px。
- 本树的 `ListRow` 旁边没有 `SettingsList`（它随上游的 Workbench 一起进来，本 fork 未取），所以这次只落列表行本身的改动。
- gallery 里那条带版本号的示例记忆写的是 Adelie，不是上游产品名。
