# 错误中心能忽略某一类报错，记录一条都不删

- **日期:** 2026-11-08
- **类型:** 新功能
- **范围:** `server`, `web`
- **破坏性变更:** 无

[English](2026-11-08-errors-ignore-rules.md)

成本中心的错误表一直是「要么看着，要么清空」。而清空是真删：按当前筛选把整批记录从库里抹掉，全项目的人
此后都查不到 —— 对一个下午重试几百次、每次都叫 `[llm] llm_fatal` 的那类噪音来说，代价太大，于是它就一直
躺在表的第一页，把真正要看的那三条挤到后面。

现在可以只忽略某一类：每一行多一颗眼睛图标，按下后按它那一行的**来源 + 错误码**立一条规则，这类记录就从
这张表里消失 —— 一条都没删。想连「同一类里的另一种声音」一起留下也行：规则可以再窄到「消息包含某段文字」，
于是同一来源与错误码里只有带那段的记录被隐藏（`llm_fatal` 一次 500 的报错可以留着，整下午的套接字断流不用看）。

忽略与取消是项目主人（owner）的事，和清空同一条线：规则改的是所有人看到的表。成员照样看得到统计行里那个
「已忽略 N」，也照样能切到「已忽略」视图读那批记录 —— 被规则挡住的东西，从不对他们隐身。

## 细节

- 服务端：新表 `error_ignore_rules`（按项目存，`source` + `code` + 可选的 `message_like`），记录照旧照常写进
  `error_records`；**过滤只发生在读路径上**（`ErrorsRepo.conds` 里多一个「不被任何规则覆盖」的条件，`ignored=1`
  时反过来只取被覆盖的），删除记录仍然只有清空一条路。三条路由，都走 `requireProjectOwner`：
  `GET /api/projects/:p/usage/errors/ignores`（规则+各自覆盖多少条、最近一条何时）、
  `POST …/ignores?from&to&fromTs&toTs&agentId`（新增，回一句「在这个范围内隐藏了几条」；同一类已有规则即
  409 `ignore_rule_exists`）、`DELETE …/ignores/:id`（删规则本身就是撤销，404 `ignore_rule_not_found`）。
  `GET/DELETE /usage/errors` 新增 `ignored` 参数（`1`/`0`，其余取值 400），仪表盘多一个 `errors.ignored`。
  规则有意**不设过期时间**：永久，直到有人取消 —— 现在没有任何地方读「什么时候失效」（见 changelog 的
  「没做」一节）。
- Web：错误表的分段控件从三个变成四个（全部 / 未预期 / 预期内 / 已忽略，四颗排一行），统计行多一格
  「已忽略 N」。行里那颗眼睛按钮叫「忽略这类异常」，按下弹一张卡：写着这一行的来源与错误码，给一个可留空的
  「只忽略消息包含以下内容的记录」。忽略之后，表上方留一条**可撤销**的横条（「已忽略 … · 本次隐藏 N 条记录」
  + 「撤销」）——它落在表的位置上，因为那颗按钮原来所在的行已经消失了；通知区那条同样的句子会自己在六秒后
  走掉，撤销不会。规则列表画在「已忽略」视图的表上方：每条规则念自己覆盖什么、已隐藏多少条、最近一条何时，
  带「取消忽略」。
- 清空照旧只清屏幕上那一批，但它的确认句现在会说清被忽略的那批不在其内（「另有 N 条已忽略的记录不在此列。」）；
  站在「已忽略」视图上按清空，句子说的就是那一批已忽略的记录 —— 那正是该视图的表所显示的。

## 测试

- `packages/server/test/errors.test.ts`（+391 行）：规则在范围内覆盖多少条的计数、`message_like` 的匹配、
  重复规则的 409、没有这条规则的 404、id 非法 400、`ignored` 参数的校验、过滤只发生在读路径（记录一条不少、
  取消后全部回来）、以及三条路由对主人的要求（成员读得到 `errors.ignored`，但读不到规则、也立不了规则）。
- `packages/web/test/errors-panel.test.ts`（+151 行）：`errorsClearScopeText` 在「已忽略」视图上的句子、
  `errorsClearKeepsIgnoredText`（被忽略的记录要在此列的句子里出现，在它自己那个视图上不出现）、
  `IgnoreRulesBox` 的三种状态（还没读、没有规则、有规则时每条念什么），以及 `ignoreRuleText` 对窄化过的
  规则的念法。
- `packages/web/e2e/errors-ignore.spec.mjs`（新增 2 条，真服务端 + 真浏览器）：一条走行内按钮 —— 忽略后表里
  不再有它、通知与横条都说隐藏了几条，而 API 读回来那条记录**还在**（同一个 id）、默认视图读不到它、`ignored=1`
  读得到；规则列表里正是这一类；按「撤销」后规则没了、那条记录回到默认视图。另一条走「已忽略」视图 ——
  清空确认句里那句「另有 N 条已忽略的记录不在此列。」、规则列表念出这一类与已隐藏多少条、表里就是那批记录，
  按「取消忽略」后规则清空、记录回到「全部」视图。

## 兼容性

新增表与路由，不改已有接口的形状：`GET/DELETE /usage/errors` 只是多一个可选参数，仪表盘多一个字段。升级后
老数据一条不动，没有规则的项目读到的表与以前逐行相同。不引入新依赖，不改 Project 配置。
