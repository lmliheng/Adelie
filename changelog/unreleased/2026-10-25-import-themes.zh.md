# 主题也能在界面上导入：选个文件，或者填个地址

- **Date:** 2026-10-25
- **Type:** feat
- **Scope:** `core`, `server`, `web`
- **Breaking:** no

[English](2026-10-25-import-themes.md)

主题一直可以放进数据根的 `themes/` 目录里用。现在**设置 › 外观**那块写着目录的地方，管理员多了一个
「导入主题…」：选一个 `.json` 文件上传，或者填一个地址让服务端取回来——和插件那两条导入一个道理。导入与
手放文件没有区别：写的还是同一个目录、同一个文件，校验用的还是同一个读法。

导入的文件按主题自己的名字落盘（`暖纸` → `warm-paper.json`），所以同一个主题再导一次是更新，而不是多出
一份：这时会先问一句覆盖，确认后替换它原来那个文件（哪怕那个文件叫别的名字）。读不出来的文件一个字节都不
写，而且把读法的原话带回来——哪个字段、哪个值不能要，写文件的人照着改就行。

## 细节

- **服务端**（`server/src/http/routes/themes.ts`）两条新路由：`POST /api/themes/upload`（文件以 base64 放在
  请求体里，和插件、技能、钩子的导入同一个形状）与 `POST /api/themes/download`（由服务端去取，本机与内网
  地址直接拒掉）。两条都要管理员，否则 403 `admin_required`；409 `theme_exists` 表示这个主题名已经有文件
  占了，带上 `overwrite: true` 重发即替换。
- **「服务端去取」是一次有界请求**：30 秒时限、边读边卡上限（`content-length` 只是声明，chunked 连声明都
  没有）、并对真正回答的那个地址再查一次主机——重定向可能把请求带到别处。主机守卫直接复用插件那条
  （`services/plugin-download.ts` 的 `isBlockedHost`），没有第二份。
- **上限是格式自己的**：`MAX_THEME_FILE_BYTES`（256 KB，在 core）。读目录的那道检查、上传解码后的字节、
  取回来的字节，三处是同一个数——收下一个读法会拒的文件，等于装了一套永远不上色的主题。
- **外观页**（`features/settings/appearance-section.tsx` 与 `theme-import-dialog.tsx`）：目录那一行里，
  管理员多一个入口，打开一个框：上面两选一（本地文件 / 地址），下面是对应的字段，确认按钮只有一个。非管理员
  那一行一个字都不多——服务端本来就会拒，入口只画给能用的人。
- **测试**：`server/test/themes.test.ts` 增补 9 条（落盘与两处读取立刻可见、同名先 409 再覆盖以后只有一份、
  别的文件占了这个主题名时替换的是那个文件、坏文件带原因且不落盘、超限 413、成员 403 且不发出请求、地址
  导入、取回来不是主题／404／连不上／非 http 地址、内网地址与两种超限方式），`web/test/theme-import.test.ts`
  5 条（错误文案，以及界面上的上限与 core 是同一个数）。

## 兼容性

- 没有接口破坏：原来两条读路由一个字没改，`/api/themes` 的响应形状也没变。
- 不想用界面的管理员什么都不用改：手放文件进目录照旧是完整的用法，导入只是把这一步搬到界面上。
- 仍然是「只收令牌取值」：外置主题改不了组件、布局与规则，只能给令牌名换值。
- 没有依赖变化，没有版本号变化。
