# 重试一个读不出来的目录时，仍开着的后代也跟着重新列一遍

- **Date:** 2026-11-22
- **Type:** fix
- **Scope:** `web`

[English](2026-11-22-files-retry-descendants.md)

文件树里一个目录的列表读失败时，原因画在那一行下面，那一条列表被丢掉 —— 它下面仍展开着的目录因此不再
画出，但各自的列表还留着。读者点那一行重试成功之后，那些后代又回到屏幕上，带着的却是失败之前读到的那
一份：这段时间里删掉的文件还在、新写进去的不见，直到逐层收起再打开才恢复。

现在那次重试落地之后，仍开在这个目录下面的每一层都会重新列一遍。某个后代重读再失败时，原因照常画在它
自己那一行下面，而不是先显示旧行再说。根目录不受影响：它的失败替换整棵树，「刷新」本来就会重读每一个
开着的目录。

## 细节

- `packages/web/src/lib/workspace-tree.ts`：新增 `openDirsUnder(expanded, dir)` —— 严格落在这个目录下面的
  开着的目录。只共享前缀的兄弟不在内；根目录按这个拼法没有后代，因为根的失败走的是另一个槽（整棵树）。
- `packages/web/src/features/chat/workspace-browser.tsx`：`loadDir` 开跑时先记住「这一次是一次重试」，成功
  那一支把 `openDirsUnder` 里的每一层排进读取队列（经 `loadDirRef`，回调不能把自己列进依赖）。注释写明了
  为什么只能在这里做：点行是唯一「只重读一个目录」的入口，而「刷新」本来就会重读每一个开着的目录。

## 测试

- `packages/web/test/workspace-tree.test.ts`（+1）：严格在目录内部、不含自己、不含只共享前缀的兄弟、
  根不含。
- `packages/web/e2e/files-retry-descendants.spec.mjs`（新，2 条，真服务端 + 真浏览器）：① docs 的列表被
  拒 → 「刷新」→ 此刻已改过盘上的树（两层都换了文件）→ 点 docs 重试：新行出现、旧行消失；② 后代 api
  自己也被拒 → 它的行带着原因、旧行不在，放开后点它又是重试。

## 兼容性

不碰接口、不碰存储、无新依赖。
