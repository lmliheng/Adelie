# 工作区选择器的地址栏够不着的路径留在原地，原因也留在它下面

- **Date:** 2026-11-26
- **Type:** fix
- **Scope:** `web`

[English](2026-11-26-finder-address-refusal.md)

工作区选择器的地址栏会被点成一个路径输入框（⌘⇧G / Ctrl+Shift+G，或直接点它）。它进不去的那条路径，不管服务器答什么都把输入框关掉：地址栏退回原来那个文件夹，输入的文字随输入框一起消失，原因只剩一条六秒后自己消失的通知。于是一条长路径打错一个字母，代价是整条重打；而读者回头看地址栏时，它看上去什么问题也没有。

现在输入框带着刚才那条路径回来 —— 整条选中，和打开输入框时一样 —— 服务器按错误码给的那句话就压在它下面。在同一条路径上改对再回车，选择器就走到那里去；按 Esc 或把焦点移开，地址栏退回分段、那句话也一起收走。一种情形保持原样：目录在那儿、只是不许读 —— 选择器就停在那儿，它自己的面板说明为什么什么都没显示。

## 细节

- `packages/web/src/features/chat/workspace-finder.tsx`：新增 `addressRefusal`（那句话，画在它所属的输入框下面）与 `addressAttempt`（只有仍是当前这次尝试的答复才把输入框放回来 —— 用户可能已经自己拿回输入框或离开了）。`commitAddress` 的失败处理里 `dir_permission_denied` 照旧；其余情形显示 `refusalText(err)` 并把输入框重新打开；`editAddress` / `cancelAddress` 清掉那句话、结束这次尝试。
- 原来那条通知（`S.chat.workspaceDirInvalid`，「目录不存在或无法访问，已回退」）从两本词典里删掉：地址栏不再「回退」，按错误码给的那句话自己会说清是「不存在」还是「没权限」。
- `packages/web/e2e/finder-address-refusal.spec.mjs`：两条 —— 输入框与那句话活过七秒（toast 的寿命），且在同一条路径上改对再回车就走到那里；Esc 与 Tab 把地址栏退回分段、把那句话一并收走。

## 兼容

只改 Web App。不碰接口、不碰服务端、无新依赖。
