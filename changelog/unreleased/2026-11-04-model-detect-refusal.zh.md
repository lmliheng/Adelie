# 模型库配置弹窗的「检测协议」没认出协议时，原因留在 base URL 字段下面，不再只活六秒

- **日期：** 2026-11-04
- **类型：** fix
- **范围：** `web`
- **破坏性：** 无

[English](2026-11-04-model-detect-refusal.md)

模型库配置弹窗里那颗「检测协议」跑的是表单当前的 base URL（以及里面填了还没保存的 key），
什么都不写：认出来只把协议填进字段，认不出则表单一个字都不变。于是那次没认出来就是读者改同一张
表单时要一直看着的一句话 —— 它点名的 API Key 与 base URL 就在同一屏 —— 而此前它只落进一条通知：
盖在弹窗上方、六秒后自行消失，六秒之后屏上没有任何东西说明这颗按钮被按过。

现在这句话画在弹窗里、base URL 字段的正下方（`role="alert"`、危险色、限两行、整句挂悬停），
留到表单被编辑、手动选了协议或下一次检测开始为止。认出来的那次仍是一条通知（协议落在的字段就是
字段右端那枚后缀，屏幕上已经有地方放着它）；保存时顺带检测没认出来的那条提示也仍是通知 —— 它讲的
是一次已经写下去的保存，不是一次拒绝。

顺带修一处指错地方的诊断：请求本身就没发出去（服务端 500、登录过期、连接断了）此前也念那句
「请检查 API Key 与 base URL」，可这两个字段可能一点问题都没有。这种情形现在念错误码自己的本地化
句子，与这个弹窗里「测试连通性」那颗按钮同一条规则。

## 细节

- `packages/web/src/features/models/detect-refusal.ts`（新，47 行）：`detectProtocolRefusal(press)`
  把一次按键的结局变成那句话，认出协议给 `null`。三种结局：路由答复但没认出协议、URL 根本没能离开
  浏览器（`detectableBaseUrl` 判的）、请求本身失败。前两种共用那句点名「API Key 与 base URL」的
  老话 —— 探测过程中更细的区别从外面看不见，把其中一种说成「端点有回应」会被读成成功；第三种走
  `refusalText` 的既有规则（7.19 那条，全应用一致的拒绝口径）。
- `packages/web/src/features/models/models-page.tsx`：一个 `detectRefusal` 状态 —— 手动检测开始时
  清掉、任何一次表单编辑或手动选协议时清掉（这句话描述的是那一次的 URL、key 与 id）、没认出来时写上。
  句子画在 base URL 字段下面（错误行之后、锁定说明之前）；`failed()` 从「弹 toast」改成「交一份结局
  进来」，保存流程那条 `detectFellBack` 提示原样保留。
- `packages/web/src/lib/strings{,-en}.ts`：**没有新文案** —— 复用 `detectFailedBody`，外加错误码
  表里本来就有的句子。

## 测试

- `packages/web/test/detect-refusal.test.ts`（新，6 条）：认出协议不留话 / 答复里没有协议仍是那句
  老话 / URL 没能离开浏览器给同一句 / 请求失败按错误码取本地化句子（原始英文不上屏、也不退回那句
  检查 key 的话）/ 客户端自己抛的错保留自己的话、什么都没有时退回通用那句 / 跟着界面语言走。
- `packages/web/e2e/models-detect-refusal.spec.mjs`（新，真服务端两条）：探测路由桩在
  `page.route` 上。用例①：答复里没有协议时 base URL 下面出现那句话、通知区 0 个可点条目、探测带走
  的是表单里的 URL、什么都没写，七秒后句子仍在；改一个字符即清掉。用例②：请求本身失败（500 加错误
  码）时按应用的本地化句子显示（不是那句检查 key 的话），探测带走的是未保存的 `sk-probe`；放行后
  同一颗按钮重试 —— 句子消失，换成那条「检测到 … 协议，已应用」的通知。

## 兼容

- 接口、请求与存储都没变：还是同一次 `POST …/models/detect`，不写任何东西。改变的只有没认出来之后
  画在哪里、以及请求本身失败时说的是谁的话。
