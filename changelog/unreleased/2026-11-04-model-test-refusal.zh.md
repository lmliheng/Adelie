# 模型库配置弹窗的「测试连通性」被拒时，原因留在按钮下面，不再只活六秒

- **日期：** 2026-11-04
- **类型：** fix
- **范围：** `web`
- **破坏性：** 无

[English](2026-11-04-model-test-refusal.md)

模型库配置弹窗里那颗「测试连通性」，跑的是表单当前（尚未保存的）值，什么都不写。每一种失败
都是读者改同一张表单时要一直看着的那句话：key 不对、base URL 没回应、这个 id 所在的分组路由
不了它。这些此前都只落进一条通知 —— 它盖在弹窗上方、六秒后自行消失，而表单一个字都没变：六秒
之后，屏上没有任何东西说明这颗按钮被按过。

现在这句话画在弹窗里、按钮那一行的正下方（`role="alert"`、危险色、限两行、整句挂悬停），留到
表单被编辑或下一次测试开始为止 —— 那几个字段正是探测送出去的值，同一颗按钮就是重试。连接成功
的那次仍然是一条带延时的通知（它没有留下需要解释的东西）；分组路由不了的那种也仍然给出建议，
而不是路由自己的那套词，被换掉的原句进控制台。

## 细节

- `packages/web/src/features/models/model-test-refusal.ts`（新，60 行）：`modelTestRefusal(answer,
  fix)` 把一次探测的答复变成那句话，连接成功给 `null`。三种答复各按既有规则取词：请求本身失败
  走它错误码对应的本地化句子（`refusalText`）；答复里连细节都没有时退回通用那句 —— 按钮下面
  一行空白比它取代的那条通知说得更少；能路由却失败的把路由自己的句子原样带过去，那正是让「key
  错了」和「地址错了」都诊断得出来的东西。`fix`（`unroutableFix`，按按下那一刻的表单判）把这句
  换成该条目自身形状对应的建议。
- `packages/web/src/features/models/models-page.tsx`：一个 `testRefusal` 状态 —— 探测开始时清掉、
  表单任何一次编辑也清掉（探测送的正是这句话描述的那几个值）、被拒时写上。句子画在按钮行下面；
  成功那条通知与「路由不了的原句进控制台」都保持原样。
- `packages/web/src/lib/strings{,-en}.ts`：**没有新文案** —— 复用 `testFailed(detail)` /
  `testStalePin` / `testNotRoutable`，也就是卡片自己那行状态用的同一批句子。

## 测试

- `packages/web/test/model-test-refusal.test.ts`（新，7 条）：连接成功不留话 / 路由的细节原样带
  过去 / 没有细节时退回通用那句 / 请求失败按错误码取本地化句子（原始英文不出现在屏上）/ 客户端
  自己抛的错保留自己的话 / 两种路由建议都替换掉路由的句子（不论答复是哪种形状）/ 跟着界面语言走。
- `packages/web/e2e/models-test-refusal.spec.mjs`（新，真服务端两条）：探测路由桩在 `page.route`
  上。用例①：路由答复失败时按钮行下面出现它的句子、通知区没有可点条目、什么都没写、表单原样，
  七秒后句子仍在；改一个字段即清掉。用例②：请求本身失败（500 加错误码）时按应用的本地化句子
  显示，而探测带走的是表单里未保存的 key（`sk-probe`）；放行之后同一颗按钮重试 —— 句子消失，
  换成那条带延时的成功通知。

## 兼容

- 接口、请求与存储都没变：还是同一次 `POST …/models/test`，不写任何东西。改变的只有被拒之后画
  在哪里 —— 从「只有一条通知」到「按钮下面多一条活得下去的说法」。
