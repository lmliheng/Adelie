# 生成 ID 的请求被拒时，原因留在 ID 框下面，不再只在一条六秒的提示里

- **日期：** 2026-10-31
- **类型：** fix
- **范围：** `web`
- **破坏性：** 无

[English](2026-10-31-semantic-id-suggest-refusal.md)

每个「用语义 id 命名对象」的创建对话框（项目、Agent、Benchmark、组织、渠道）都戴着同一个 id
字段，其中那颗「用 AI 生成」按钮向服务端要一个从显示名推出来的 id。服务端一定会给出一个 id，
所以框里原本只差一句「这个 id 值多少」的说明。**请求本身失败**是另一回事：没有那个项目的访问
权、组织 / 渠道对话框下公司模式被关掉、连接断了 —— 框里什么都不会变，而原因此前只有一条 toast，
用户看向别处的那六秒之后，屏幕上一个什么都没做的按钮，一句已经消失的解释。

现在这句话就写在 id 框下面，与「这个 id 是占位」「这是按名称转写」的说明同一个位置：共享的引子
`S.common.refused`、danger 色、`role="alert"`（出现时会被读屏念到）。下一次编辑或下一次点击都
会把它清掉 —— 它是这一次点击的答复，不是这个框的长期状态。五个创建对话框共用这一份正文，因此
五处同时生效；没有新增文案。

## 细节

- `packages/web/src/features/semantic-id/semantic-id-field.tsx`：多一个 `refusal` 状态，由失败的
  请求经 `refusalText` 填上（服务端有原话就用原话，正文自己举的错也有自己的句子），不再走
  `toastError`；输入变化与下一次生成都清空它。id 框本身保持不变 —— 这次点击什么都没有得到。
- `packages/web/src/features/semantic-id/id-suggest-notice.ts`：新增纯函数 `idSuggestLine`，把
  「框下面画哪一行」收成一处：拒绝 > 占位提示（attention）> 安静的转写说明。字段目前不会同时
  持有两者（生成前先清说明），把顺序写在这里是为了以后改动不会悄悄让说明盖住「按钮为什么没动」。

## 测试

- `packages/web/test/id-suggest-notice.test.ts`：新增四条，钉住这四种组合（都没有 / 一条说明 /
  一条拒绝 / 两者同时存在时拒绝在前）。
- `packages/web/e2e/semantic-id-suggest-refusal.spec.mjs`（新，真服务端两条）：被拒的生成把原因留
  在 id 框下面、框里仍是空的、通知区里没有可点的 toast，并且 toast 该消失的七秒之后那一行还在；
  随后放开拒绝，同一次点击真的拿到 id，那一行随之消失。

## 兼容

- 接口、磁盘格式、请求体都没变。生成成功时的三种说明一字未改，只有请求失败那条路不再用 toast。
