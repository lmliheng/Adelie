# 机器卡上打开 ssh 配置失败时，原因留在那张卡上

- **Date:** 2026-11-23
- **Type:** fix
- **Scope:** `web`

[English](2026-11-23-machines-configure-refusal.md)

机器卡上的齿轮会向服务端要这台机器的 ssh 记录，再带着它打开表单。这次读会失败 —— 别名已经不在
配置里、或者那个文件读不出来 —— 失败过去只落在一条通知里：通知六秒后自己走了，卡片与那颗齿轮
和点之前一模一样。

现在原因留在问它的那张卡上，说的是服务端口径的「操作被拒绝：…」，画在卡片自己那两行下面、而不是
展开的详情里面 —— 收起卡片也不会把它一起收走。同一颗齿轮就是重试：下一次尝试先把句子清掉，读成功
就照旧打开表单。

## 细节

- `packages/web/src/features/machines/machines-page.tsx`：`configure` 不再 `toastError`，读失败时
  把 `configureRefusal`（`{ alias, text }`，经 `refusalText` 写入）记下来，下一次尝试开始与切换
  Project 时清掉；只有别名对上的那张卡画它（`role="alert"`、危险墨色、最多两行、悬停看全文）。
- 没有新文案、没有新依赖、不碰接口。

## 测试

- `packages/web/e2e/machines-configure-refusal.spec.mjs`（新，1 条，真服务端 + 真浏览器；机器清单是
  桩，因为研发数据根的 ssh 配置里没有远程主机）：展开详情后点齿轮，读答 500 并带上自己的话 →
  句子在卡片上、通知区没有它、齿轮还在、收起卡片也不隐藏、六秒半后仍在；解除拦截后同一颗齿轮
  打开表单、句子消失。改前产物上卡片里根本没有这句话。

## 兼容性

没有动路由、存储格式或线上类型：这次拒绝只发生在客户端的一次读请求上。
