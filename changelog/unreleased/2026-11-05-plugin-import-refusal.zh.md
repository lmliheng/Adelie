# 插件导入被拒时，原因留在发问的那个对话框里，不再只活六秒

- **日期：** 2026-11-05
- **类型：** fix
- **范围：** `web`
- **破坏性：** 否

[English](2026-11-05-plugin-import-refusal.md)

插件库标题行里的两个导入对话框（「上传插件」与「远程下载」）都要一个来源，外加一个可选的插件名。
导入被拒时什么都没写：对话框留在原地，选好的压缩包或填好的地址一个字没变，而那颗确认按钮就是
重试。可理由只落进一条六秒后自己消失的通知 —— 六秒之后对话框与按下之前一模一样，而真正要改的东西
（地址、文件）就在眼前，却没有一句话说它。

那句话现在留在发问的那个对话框的来源字段下面（`role="alert"`、危险色、限两行、整句挂悬停），直到
来源被改动、下一笔导入开始、对话框关闭或导入成功 —— 所以它说的总是最近一次尝试。两种情况保留原来的
位置：409 `plugin_exists` 是一句提问，仍然在覆盖确认里问（那里会点出插件名）；而按下「取消」之后才
回来的答复（两个对话框的取消在请求进行中都可用）仍然走通知 —— 画进已关闭对话框的句子没人看得到。

用谁的措辞：插件自己的错误码用自己的文案，其余按 `refusalText` —— 全应用拒绝位都走这条规则（7.19）。
服务端答过的请求念它错误码对应的本地化句子，本仓库自己抛出的值按它写好的原话显示。

## 明细

- `packages/web/src/features/plugins/plugin-import-refusal.ts`（新）：`importFailure(error,
  fallbackName, dialogOpen)` —— 三种去向之一（`ask` 带插件名、`field` 带句子、对话框已不在时
  `toast` 带句子），把原先写在两个对话框里的分支收成一个可测的判定。
- `packages/web/src/features/plugins/plugin-import-dialog.tsx`：新增按「发问的对话框」区分的
  `refusal` 状态；两个打开标记的 ref 影子（答复回来时才决定去哪，而不是按下那一刻）；
  `ImportRefusalLine`（与全应用同形的那一行）在上传对话框里画在文件选择行下面、在下载对话框里画在
  地址字段下面；每次编辑、每次新尝试、关闭任一对话框与导入成功都会清掉它。

## 测试

- `packages/web/test/plugin-import-refusal.test.ts`（新，7 条）：409 从服务端原话里读出插件名，读不出
  就用调用方给的名字；对话框还开着时拒绝留在对话框里；插件错误码用自己的文案而不是服务端英文；未映射
  的错误码退回共享码表；对话框已关时改走通知；本仓库自己抛的错误保留原话；界面语言跟着切换。
- `packages/web/e2e/plugin-import-refusal.spec.mjs`（新，真服务端 + 真浏览器，2 条）：被拒的下载把句子
  画在地址下面、通知区里没有它、对话框/地址/按钮都还在；**7 秒后**仍在；改动地址它就消失；重试后对话框
  关闭并报出导入成功。第二条规定请求进行中按取消，句子出现在通知里。

## 兼容性

不碰接口、不引入新依赖、不改 Project 配置。路由、请求体与覆盖确认都没动。
