# 模型库的视觉探测没得出结论时，原因留在视觉开关下面，不再只活六秒

- **日期：** 2026-11-04
- **类型：** fix
- **范围：** `web`
- **破坏性：** 否

[English](2026-11-04-model-vision-refusal.md)

模型库配置弹窗里，视觉开关旁边那颗「检测」会花用户自己的额度发一次极小的图片请求。它的答复只有三种：
接受（视觉打开）、明确拒绝（视觉关闭）、什么也没学到（开关原样不动）。前两种在读者眼前把开关挪了位置，
那一下就是这次按键的全部交代；第三种什么都没写，于是**理由就是这次按键留下的唯一痕迹** —— 而它过去只落进
一条通知：通知浮在弹窗上、六秒后自己消失，屏上留下一张与按键前完全一样的表单，没有任何东西说明这颗按钮
被按过。它点名的三个东西（API Key、base URL、模型 id）全在同一个弹窗里，读者改它们时正需要看着那句话。

那两句话现在画在弹窗里、就在视觉开关那一行的下面（`role="alert"`、危险色、最多两行、整句挂悬停提示），
一直留到表单被编辑或下一次按键开始。两种「有结论」的答复仍走通知：开关已经动过，读者看得见。

顺带修掉一处**说错了标的**的诊断：这两条失败的句子此前借的是协议探测那句「无法检测接口协议，请检查
API Key 与 base URL」—— 读者按的是关于图片的按钮，答的却是协议;现在它们各自以「视觉检测失败：」开头，
并带出服务端转来的那句截断的上游原文（过去被那条通用句盖住，正好是最能定位问题的那一句）。请求本身根本
没发出去时（服务端 500、登录过期、连接断了），画的是错误码自己的本地化句子 —— 与这个弹窗里另外两颗探测
按钮、以及全应用其余拒绝位同一条规则（7.19）。表单里还没有模型 id 时，路线不会被问，但那一下仍然要交代，
于是同一行里说「请先填写模型 id」。

## 明细

- `packages/web/src/features/models/vision-refusal.ts`（新，54 行）：`visionProbeRefusal(press)` 把一次按键
  变成那句话，两种有结论的答复给 `null`。三种形状：表单没有模型 id（路线不该被问）、路线答复了（接受 /
  拒绝 / 没学到）、请求本身失败。前两种有结论的答复不留句子 —— 开关与它们各自的通知已经说完了；
  没学到的那次带出 `message`（路线截断过的上游原文），缺了就退回通用文本（空白的一行比它取代的通知说得更少）；
  请求失败走 `refusalText`（7.19 的全应用口径）。
- `packages/web/src/features/models/models-page.tsx`：一个 `visionRefusal` 状态 —— 每次按键开始时清掉、
  `set()` 里清掉（表单任何一次编辑都让那句话描述的表单不在屏上了）、没有模型 id 或没得出结果时写上。
  句子画在视觉开关那一行下面、视觉关闭时那行常驻说明的上面（贴着被按的控件，常驻说明不是这次按键的答复）。
  `detectVisionFromButton` 的三条失败路从 `toastError` 改成写这一行；两种有结论的答复仍是原来的通知。
- `packages/web/src/lib/strings{,-en}.ts`：新增一条 `detectVisionFailed(detail)`（「视觉检测失败：{detail}」/
  `Vision probe failed: {detail}`）—— 原来借的 `detectFailedBody` 讲的是协议，不能复用；其余复用
  `detectVisionNeedsId` 与错误码表里的句子。

## 测试

- `packages/web/test/vision-refusal.test.ts`（新，9 条）：接受不留句子 / 拒绝不留句子 / 没学到时原样带出
  上游那句 / 路线没给理由时退回通用文本 / 不再讲协议探测那句 / 请求本身失败按错误码取句子（英文原文不上屏）/
  客户端自己抛的错保留自己的话、什么都没有时退回通用文本 / 没有模型 id 时说缺什么 / 跟随当前语言。
- `packages/web/e2e/models-vision-refusal.spec.mjs`（新，两条真服务端用例）：探测路线在 `page.route` 上打桩
  （它真的会计费）。用例①：答复 `failed` 加一句上游原文 → 视觉开关下面出现那句话、通知区 0 个可点条目、
  探测带走的是表单里的 provider / model id / base URL、什么都没写，**七秒后句子仍在**，改一个字符即清掉。
  用例②：请求本身失败（500 加错误码）→ 画的是 `视觉检测失败：服务器内部错误，请稍后重试。`（不再叫读者
  去看协议），探测带走的是未保存的 `sk-probe`；放行后同一颗按钮重试 —— 句子消失、`该模型接受图片输入，
  已开启视觉` 那条通知出现、开关被打开、探测发了两次。

## 兼容

没有接口变化，没有新依赖，没有 Project 配置变化。文案只在中文与英文两个词典各加一条；此前那句错标的
「无法检测接口协议…」仍在协议探测那一处使用（它对那里是对的）。
