# 一个字节都送不到的实时流，不再让页面看起来卡死

- **Date:** 2026-11-13
- **Type:** fix
- **Scope:** `web`

[English](2026-11-13-stream-stall-refresh.md)

实时流被中途吃掉时——握手完成了，响应体却一直不来，中间的代理或 NAT 就可能这样——对话会彻底安静下来：页面停在
已经显示的内容上，再也不会动，而服务端明明在跑的 Task 看起来像卡死的智能体。客户端唯一的存活判断要靠服务端的
`ping` 来武装，于是一个 `ping` 都没送到的连接根本没人看。

现在两种失败各有各的期限。30 秒内一个事件都收不到的连接按「开着但没通」处理并重开；连着三条都这样，这条流就
判定为停止：不再立刻重开，改成每分钟试探一次，并告诉页面 —— 页面随即靠定时 `GET /messages` 刷新对话，并在对话框
上方用一条提示说明。第一个送到的帧会清掉这个判断、那个定时器和那条提示。

## 细节

- `packages/web/src/api/sse.ts`：在原有的静默窗口（`SILENCE_MS`，50 秒）之外新增首帧期限
  （`FIRST_FRAME_MS`，30 秒）；静默窗口仍然只对发送过 `ping` 的流生效。连续三条连接上什么都没有
  （`MAX_STALLED`）时不再立刻重开，改为每分钟试探一条（`STALL_REPROBE_MS`）。新增的 `onLiveness`
  回调报告这个判断，而且每一次重连——包括试探——都仍然从见过的最新事件 id 续传。
- `packages/web/src/lib/omni/stream-controller.ts`：新增 `refresh()`，就地重取尾部窗口；与 resync 重建不同，
  它保留未决审批表，所以流断了的时候屏幕上的审批仍然可答。加载在途、加载失败过、以及已释放之后，它都是空操作。
- `packages/web/src/features/chat/use-session-stream.ts`：这个判断负责开停一个六秒的刷新定时器，并作为
  `streamStalled` 交出去。
- `packages/web/src/features/chat/stream-stalled-banner.tsx`：那条提示本身，挂在对话框上方、目标横幅旁边。

## 测试

- `packages/web/test/sse.test.ts`：一个字节都没有的连接会在期限到点时被重开；连着三条会判定停止、不保留任何
  连接、只报告一次、一分钟后再试探；试探时收到一帧即恢复实时并停止试探；被浏览器放弃的那次试探会自己安排下一次；
  停住的流仍然从见过的最新 id 续传。
  原有保证一条没变：打过招呼的流 50 秒静默窗口、只会发 `ping` 的流、迟到的标签页，以及开过口但从不发心跳的流、
  被调用方关掉或被浏览器放弃的连接。
- `packages/web/test/stream-controller.test.ts`：刷新把重取到的历史放进新模型、不重复，保留未决审批，并且在
  取回之前屏幕上仍是原来的对话；加载在途、失败过、已释放之后都是空操作。

## 兼容性

线上协议没变、没有新依赖、Project 配置没变，只多了一条文案（那条提示）。比心跳事件更老的服务器不受影响：
它在订阅时就会发 `task_state` 快照，新加的首帧期限因此解除，而它的安静本来就不在观察范围内。
