# MCP Server 弹窗的「测试连接」被拒时，原因留在按钮下面，不再只活六秒

- **日期：** 2026-11-04
- **类型：** fix
- **范围：** `web`
- **破坏性：** 无

[English](2026-11-04-mcp-test-refusal.md)

Agent 设置 → 工具 → MCP Server 的编辑卡片里那颗「测试连接」，跑的是表单当前（尚未保存的）值。
每一种失败都是读者改表单时要一直看着的那句话：命令不在 PATH 上、地址超时、server 的 stderr
尾巴里写着证书问题。这些此前都只落进一条通知 —— 它盖在卡片上方、六秒后自行消失，而卡片本身
一个字都没变：六秒之后，屏上没有任何东西说明这颗按钮被按过。

现在这句话画在卡片里、按钮正下方（`role="alert"`、危险色、限两行、整句挂悬停），留到表单被
编辑或下一次测试开始为止 —— 表单的那几个字段正是它描述的连接，而同一颗按钮就是重试。连接成功的
那次仍然是一条带工具数与耗时的通知（模型库那张卡片的写法）：它没有留下需要解释的东西。

## 细节

- `packages/web/src/features/agents/mcp-test-refusal.ts`（新，44 行）：`mcpTestRefusal(answer)`
  把一次探测的答复变成那句话，连接成功给 `null`。三种答复各按既有规则取词
  （`refusalText`）：路由自己的细节（spawn 错误 / 超时 / stderr 尾巴）原样带过去；请求本身失败
  走它的错误码对应的本地化句子；路由答复里连细节都没有时退回通用那句 —— 按钮下面一行空白比它
  取代的那条通知说得更少。
- `packages/web/src/features/agents/mcp-servers-section.tsx`：一个 `testRefusal` 状态 —— 探测开始
  时清掉（那是上一次的答复）、被拒时写上；句子画在「测试连接」按钮那一行的下面。表单的任何一次
  编辑、以及打开另一张卡片都清掉它，因为探测送的正是这份表单的全部值。连接成功那句通知与原样
  保留；`toastError` 的导入随之去掉。
- `packages/web/src/lib/strings{,-en}.ts`：**没有新文案** —— 复用 `mcpTestFail(detail)`
  （「连接失败：…」），卡片里那张表单就是被说的那个 server。

## 测试

- `packages/web/test/mcp-test-refusal.test.ts`（新，6 条）：连接成功不留话（含「连上但一个工具都
  没有」）/ 路由的细节原样带过去 / 没有细节时退回通用那句 / 请求失败按错误码取本地化句子（原始
  英文不出现在屏上）/ 客户端自己抛的错保留自己的话 / 跟着界面语言走。
- `packages/web/e2e/mcp-test-refusal.spec.mjs`（新，真服务端两条）：探测路由桩在 `page.route` 上
  （500 → 后放行的成功答复）。用例①：被拒后句子在卡片里、通知区没有可点条目、卡片里只有这一条，
  探测请求带的是表单里那两个未保存的值，表单原样不动，七秒后句子仍在。用例②：改一个字段就清掉
  那句话，同一颗按钮重试走通 —— 句子不再出现、成功那条通知带上工具数与耗时，第二次探测发往改过的
  地址。

## 兼容

- 接口、请求与存储都没变：还是同一次 `POST …/agents/<agent>/config/mcp-test`，不写任何东西。
  改变的只有被拒之后画在哪里 —— 从「只有一条通知」到「按钮下面多一条活得下去的说法」。
