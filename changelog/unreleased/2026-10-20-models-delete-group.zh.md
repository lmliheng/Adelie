# 删除分组：写成功才收起确认框，被拒的分组回到页面上

- **Date:** 2026-10-20
- **Type:** fix
- **Scope:** `web`
- **Breaking:** no

[English](2026-10-20-models-delete-group.md)

用户自定义分组的「删除分组」会先问一句，说明要删的是哪个分组、组内几个模型连同它们的 API key 一起
移除。而它此前在请求发出时就关闭确认框，**不管删没删成**；同时 `persist` 会保留尝试中的表（那是为了
让正在填写的字段编辑不丢）。于是被拒的那次删除让页面**没了这个分组**，服务器却仍然留着它 —— 更难受的
是「删除分组」这个入口就长在分组表头上，它与分组一起消失了：没有地方可以重试，只剩一句错误提示。

现在删除把写入做完之后才收起确认框，被拒时把分组放回页面。

## 细节

- 确认框一直开到表写入有结果为止；被拒时句子与它写的条数原样留着，错误提示照旧显示服务端那句话，
  重试就是同一张确认框。
- 写入被拒时用删除前的表恢复页面，因此分组与它的「删除分组」按钮都还在，句子里的条数也仍然与重试
  将要删掉的一致。
- 请求在飞的时候确认框标为 busy（按钮禁用），连点不会发出第二次写入。

## 兼容性

- 没有接口、传输格式或依赖变化；只改了页面里写入与收起的先后。
