# 插件装不到某个 Agent 上时，原因留在那张卡片里，不再只活六秒

- **日期：** 2026-11-07
- **类型：** fix
- **范围：** `web`
- **破坏性：** 否

[English](2026-11-07-plugin-install-refusal.md)

插件卡片上有两个往 Agent 上装东西的入口：卡片自己的「安装到 X」，以及「管理安装」对话框里每一行
的「安装」。两个都不问一句就发请求，装不上时（服务端拒、插件不在库中、请求根本没到）什么都没变：
文件仍没装上去，卡片与那一行仍在原地、按钮仍是那个按钮，而原因只落进一条通知，六秒后自己消失。
此后屏幕读起来与按下之前一模一样，没说为什么。

那句话现在画在那张插件卡片里（`role="alert"`、危险色、限两行、整句挂悬停），并且点名装上不去的那
个 Agent —— 「管理安装」里每个 Agent 一行，卡片上的按钮又跟着当前选中的 Agent 走，不点名就分不清
是哪一个没装上。它一直留到下一次尝试开始，或被一次装成功的安装取代。

## 为什么这句话归页面记，而不归卡片

安装是**乐观**的：请求发出时页面先把插件在该 Agent 上标记为已安装，卡片因此被归进「已安装」那一
段；服务端拒绝后标记回滚，卡片回到「可安装」。也就是说，发请求的那个卡片实例在答复回来之前就已经
卸载过一次 —— 把句子存在卡片里，它会跟着那个实例一起消失（第一版就是这么写的，实测页面上一句话
都没有）。于是句子由页面按插件名记着，交回重新出现的那张卡片；「管理安装」对话框同样随卡片的移动
关掉，所以它自己的那几行不再留槽位。

## 明细

- `packages/web/src/features/plugins/install-refusal.ts`（新）：`installRefused(plugin, agent,
  reason)` 造那句话、`installRefusalFor(refusal, plugin)` 决定交给哪张卡片 —— 纯判断，不依赖
  页面就能测。原因沿用 `toggleInstall` 已经算好的那份（`apiErrorText`，本仓自己抛的值走
  `refusalText`，7.19 的规则），所以它与三个确认框里的拒绝句说的是同一套话。
- `packages/web/src/features/plugins/plugins-page.tsx`：页面多一个 `installRefusal`（插件名 +
  句子）；`toggleInstall` 在安装开始前清掉它、失败时写上它（卸载那条路不变，仍把结论交回问话的
  确认框），卡片经新增的 `installRefusal` 属性读到。卡片外层从单行 flex 改成列 —— 原来那一行
  加下面的句子。
- `packages/web/src/lib/strings{,-en}.ts`：一条新文案 `plugins.installRefused(plugin, agent,
  reason)`。

## 测试

- `packages/web/test/install-refusal.test.ts`（新，5 条）：句子点名插件与 Agent、原因原话带过；
  用的是当前语言；句子只交给它自己那张卡片，别的插件的卡片拿不到；没有拒绝时什么也不画。
- `packages/web/e2e/plugin-install-refusal.spec.mjs`（新，真服务端 + 真浏览器，2 条）：把安装桩成
  500（一个界面自己有文案的错误码 + 一句英文原文）—— 卡片一键安装被拒时，句子出现在卡片里、点名
  Agent、念的是界面自己的话而不是那串英文，通知区里没有它，重试按钮仍可用，**七秒后**（超过错误
  通知活着的 6 秒）它仍在，重试成功后它消失、两次请求体相同；第二条：从「管理安装」那一行安装被
  拒时，对话框随卡片的乐观移动关掉、卡片回到「可安装」并在下面留着同一句话（同样活过七秒），
  再打开对话框重试成功后它消失。

## 兼容性

不碰接口、不引入新依赖、不改 Project 配置。成功路径、三个确认框（更新 / 卸载 / 删除）与整段
「管理安装」的动作都没动。
