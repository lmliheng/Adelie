# 代理选项的保存被拒、设置读不出来时，原因都留在设置区里，不再只活六秒

- **日期：** 2026-11-02
- **类型：** fix
- **范围：** `web`
- **破坏性：** 无

[English](2026-11-02-proxy-settings-refusal.md)

设置 → 服务器 →「代理选项」上有两条失败的路，此前都把原因交给六秒后自己消失的 toast：

- **保存被拒，而原因不是地址**（会话丢了、服务端死了、500）。这一次什么都没写进去 —— 两个开关与
  地址都原样不动，再按一次保存就是重试 —— 但 toast 留在屏上的只是一个看起来没被碰过的表单。
  地址那一类拒绝（`invalid_proxy_url`）本来就已经画在地址框下面，这一条不碰它。
- **设置读不出来**。此时每一个控件都停用、显示的是表单自己的默认值而不是服务端的值，而页面对此
  一个字都没有留下 —— 读完六秒的 toast，剩下的是一整节灰着的控件。

现在两句话都画在设置区里：保存被拒的那句在地址下面、保存按钮上面（它就是这次保存的重试），读不出来
的那句在控件上面（先读到它，因为下面的开关与地址此刻并不代表服务端）。两句都是 danger 色、
`role="alert"`、限两行、整句挂悬停，并且一直留着 —— 保存那句留到下一次保存把它换掉，读不出来那句留到
离开这一节再回来（重新挂载即重新拉取，那就是重试）。两条句子都没有自己的按钮。

## 细节

- `packages/web/src/features/settings/proxy-save-refusal.ts`（新）：`proxySaveRefusal(error)` 给出
  `{ field: "address" | "section", text }` —— 什么拒绝画在哪一个槽，是一句话加一条用例，而不是散在渲染
  里的一个 `if`。`invalid_proxy_url` 走 `address`（服务端点名了唯一被校验的那个字段），其余一律走
  `section`；句子走共享的 `refusalText()`，因此服务端的答复照样本地化。
- `packages/web/src/features/settings/proxy-section.tsx`：`addressError`（原有，画在地址框下面）之外多
  两个状态 —— `saveRefusal`（下一次保存开始时清空）与 `loadRefusal`（只在重新挂载时自然清掉）；两条
  失败的路不再 `toastError`。连通性测速那一条（7.66）不动。

## 测试

- `packages/web/test/proxy-save-refusal.test.ts`（新，5 条）：`invalid_proxy_url` 落地址槽且是本地化的
  那句（不是英文原文）；别的服务端码落设置区槽；客户端自己抛的句子原样用；什么都没说的值退回通用那句；
  句子跟着当前语言。
- `packages/web/e2e/proxy-settings-refusal.spec.mjs`（新，真服务端两条）：保存被拒 —— 句子在设置区里
  一条、通知区 0 个可点按钮、七秒后仍在、服务端仍没有那个地址、输入框仍留着敲进去的值，放行后再存
  一次句子消失而地址真的落了库；读不出来 —— 句子在控件上面、两个开关 / 地址 / 保存 / 测速全禁用、
  七秒后仍在，退出再进这一节（重新挂载即重试）后句子消失、控件打开。

## 兼容

- 接口、请求与存储都没变：保存还是同一个 `PUT /api/admin/settings`，读还是同一个
  `GET /api/admin/settings`。改变的只有失败时那句话画在哪里。
