# 清理模式的开关与「固定」被拒时，原因留在控件旁边，不再只活六秒

- **日期：** 2026-11-03
- **类型：** fix
- **范围：** `web`
- **破坏性：** 无

[English](2026-11-03-storage-settings-refusal.md)

设置 →「存储台账」有两个写在 `StorageSettings` 上：清理模式的开关，与账单每一行的「固定 / 取消
固定」。两者都不做乐观写入 —— 开关永远显示服务端答回来的位置，被拒的固定也不会把那颗按钮改成
「取消固定」—— 所以失败此前只剩一条六秒的通知：六秒之后开关静静地还在原处、按钮还写着「固定」，
屏幕上没有一句话解释为什么。而这一页的开关正是其余每个写操作的闸门（「没有人看过就什么都不动」），
固定则是决定某条路径会不会再出现在下一份账单里的那一下。

现在原因留在控件自己旁边：开关那句在它的状态说明下面，点名是「开启」还是「关闭」失败；固定那句在
那一行的按钮下面，用按钮自己的措辞（固定 / 取消固定）带上路径与服务端原话。两处都是 `role="alert"`，
都留到下一次同一个写为止 —— 同一个控件就是重试。

## 细节

- `packages/web/src/features/settings/storage-settings-refusal.ts`（新）：`storageModeRefused(enabled,
  reason)` 给出开关要画的那句（方向来自这一次请求想去的那个位置，不是页面上显示的位置）；
  `storagePinRefused(path, pinned, reason)` 给出固定那句，连它该画在哪一行（`path`）一起。
- `packages/web/src/lib/strings{,-en}.ts`：三句话 —— 清理模式的开关、固定、取消固定 —— 挨着它们
  各自的按钮文案，每句都点明是哪一次动作。
- `packages/web/src/features/settings/storage-section.tsx`：两个状态（`modeRefusal` / `pinRefusal`），
  写操作开始时清掉、被拒时写上；`ModeRow` 多一个 `refusal`，画在状态说明下面；`BillRow` 多一个
  `refusal`，画在那一行的按钮下面（`BillGroup` 按 `path` 只交给对上的那行）。失败通知保留 ——
  这一页的「执行清理」被拒时本来就是「页面上一条 + 一条通知」并存，本笔是补上一条活得更久的说法。

## 测试

- `packages/web/test/storage-settings-refusal.test.ts`（新，9 条）：开关两个方向各自的措辞 / 固定与
  取消固定各自的措辞 / 路径原样带过去（含空格与冒号）/ 原因原样带过去 / 跟着界面语言走。
- `packages/web/e2e/storage-settings-refusal.spec.mjs`（新，真服务端两条）：
  - 清理模式：设置的那次 PUT 桩成 500，点开关 → 状态说明下面出现「关闭清理模式被拒：…」，开关仍
    在开位（它本来就没动）；七秒后那句仍在；放开之后同一颗开关真的把模式关掉、句子消失。
  - 固定：账单列表桩成一份条目、那一行的 pin 桩成 500，点「固定」→ 那一行下面出现「固定「…」被拒：
    …」、按钮仍写着「固定」；七秒后仍在；放开之后同一颗按钮走通、按钮变成「取消固定」、句子消失。

## 兼容

- 接口、请求与存储都没变：还是同一次 `GET`/`PUT …/admin/storage/settings`、同一次
  `POST …/plans/:id/pin`。改变的只有被拒之后画在哪里 —— 从「只有一条通知」到「控件旁边多一条活得
  下去的说法」。
