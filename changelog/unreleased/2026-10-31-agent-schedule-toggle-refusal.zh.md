# Agent 设置页的定时任务 tab：启用 / 停用被拒时，原因留在那一行的状态徽标下面

- **日期：** 2026-10-31
- **类型：** fix
- **范围：** `web`
- **破坏性：** 无

[English](2026-10-31-agent-schedule-toggle-refusal.md)

Agent 设置页的「定时任务」tab 把某个 Agent 的任务列成一张表，每行靠一个文字按钮「启用 / 停用」
来翻转。这个按钮同样不做乐观写入：它把整份文件连同翻转后的 `enabled` 一起发回去，写入落地之前
行里显示的一直是服务端记着的那个状态。所以**被拒**时，这张表此前什么都不会变 —— 按钮没动、徽标
没动 —— 原因只剩一条六秒后自己消失的 toast：一颗看起来点了没反应的按钮，以及一句已经看不见的解释。

用共用 `ScheduleRow` 的那两个界面（定时任务页与对话停靠栏里的定时任务面板）上一轮已经给它们的开关
加上了这一行；这里是同一件东西的第三处列表，现在把原因画在那一行的状态徽标下面：共享引子
`S.common.refused`、danger 色、`role="alert"`、限两行、整句挂悬停。它属于哪一行沿用另外两处的那条
规则（`scheduleRefusalFor`）—— 任务的名字 = Agent 目录 + 文件名 —— 下一次翻转会把它清掉，因为它是
那一次点击的答复，不是这一行的长期状态。没有新增文案。

## 细节

- `packages/web/src/features/agents/schedules-tab.tsx`：多一个 `toggleRefusal` 状态，由失败的
  `updateSchedule` 经 `apiErrorText` 填上（不再走 `toastError`），下一次翻转开始时清空；状态徽标
  下面多一块 `ToggleRefusal`，让这句话正落在「按钮没动」时读者看的那一格。文件其余部分未动 ——
  成功的翻转照旧弹一条提示并重新拉表。

## 测试

- `packages/web/e2e/agent-schedule-toggle-refusal.spec.mjs`（新，真服务端两条）：被拒的翻转把原因
  留在那一行的徽标下面、旁边那一行没有，通知区里没有可点的 toast，按钮与徽标仍停在服务端记着的
  位置，并且 toast 该消失的七秒之后那一行还在；随后放开拒绝，同一颗按钮真的落地 —— 那一行消失、
  按钮变成「启用」、徽标变成「停用」。

## 兼容

- 接口、磁盘格式、请求体都没变：PUT 的正文仍是 `toggleBody` 原本拼的那一份。只有失败那条路不再用
  toast。
