# 侧栏工位行打不开时，原因留在那一行下面

- **Date:** 2026-11-23
- **Type:** fix
- **Scope:** `web`

[English](2026-11-23-desk-row-refusal.md)

公司模式侧栏的工位组一行一个员工。某一行还没从缓存里学到工位会话的 id 时，点它会走工位路由
（没有就顺手建一个）—— 这次读会失败。失败过去只落在一条通知里：通知六秒后自己走了，而按过的那
一行与点之前一模一样。

现在原因留在问它的那一行下面，说的是服务端口径的那句「操作被拒绝：…」；同一行就是重试。读失败时
那一行不会离开侧栏，所以句子一直站着，不会像通知一样消失。折叠后的竖栏一项只有 48 px，没有一行可
以写字，那里的工位被拒时仍用通知。

## 细节

- `packages/web/src/features/company/org-session-groups.tsx`：`useOpenDesk` 留着 `refusal`
  （`{ agentId, text }`，经 `refusalText` 写入），下一次尝试开始时、以及切到另一个组织时清掉；
  `OrgSessionGroups` 用 `sayInPlace: true`，句子画在那个 `DeskRow` 的 `<li>` 里（`role="alert"`、
  危险墨色、最多两行、悬停看全文）；竖栏默认仍是 `toastError`。
- 没有新文案、没有新依赖、不碰接口。

## 测试

- `packages/web/e2e/desk-row-refusal.spec.mjs`（新，1 条，真服务端 + 仓库自带 mock 模型）：侧栏画
  这一组所用的两次读都按台账里写的那种「缓存还没学到」的状态交回（员工不带 `desk`、会话路由的
  `desks` 为空），工位路由答 500 并带上自己的话 → 句子在那一行下面、量到起点正好在那行下缘、留在
  侧栏之内、通知区没有它、七秒后仍在、那一行已恢复可点；解除拦截后同一行进入 `/chat/<会话>`。
  改前产物上这条红：侧栏里找不到那句话，只有一条六秒通知。

## 兼容性

没有动路由、存储格式或线上类型：这次拒绝只发生在客户端的一次读请求上。
