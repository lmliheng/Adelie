# 插件市场的货架不再只列随构建发布的插件，也列出发布到 npm 的插件

- **Date:** 2026-11-01
- **Type:** feature
- **Scope:** `server`, `web`, `plugins`, `docs`
- **Breaking:** no

[English](2026-11-01-plugin-market-reads-npm.md)

此前货架就是「这次构建带了什么」：插件要进市场，只能先进仓库、再随一次版本发出去。仅为了这一
条，`@adelie/gpu-model-serving` 也得先收进构建里。现在货架多了一侧，直接读自 npm，包的下一个版本
就会出现在上面。

规则写在包自己身上：作用域是 `@adelie/`、并带 `adelie-plugin` 关键词的包，就在货架上。作用域限制
了关键词的风险——关键词谁都能写，但项目之外的人发布不到这个作用域下。`plugins/` 里每个插件包现在
都带这个关键词（四个 `sandbox-*` 不带：它们是 `private` 的，根本到不了 npm），所以它们下一次发布
就会跟着出现。

npm 那一侧只有一条目时，唯一的动作是**装入插件库**——就是把运维本来要手工敲进下载对话框的 npm
导入搬到这一行上，管理员操作，和写插件目录的其他动作一样。装进来以后它就与别的插件无异：装到
Agent 上才算用上。本次构建已经带的条目仍旧取本地那一份，版本也是本机装的那个；npm 那一侧是为
「没有随发布进构建、但已经发布到 npm」的插件准备的。

## 细节

- `packages/server/src/plugin/registry.ts`：`npmPluginRegistry` 读 npm 的搜索接口
  （`keywords:adelie-plugin`，并限定 `@adelie/` 作用域），把每条结果映射成货架条目——名称、版本、
  简介、作者、许可证、把包的 npm 页面作为 `homepage`、仓库地址（去掉 npm 给的 `git+` 前缀与 `.git`
  后缀）、关键词与发布日期。缺字段、描述不全的结果宁可不列，也不摆一条没有名字的行。一次查询服务
  所有调用方，缓存十分钟（失败缓存两分钟并沿用上一次的结果）；说明文档读包自己的 packument，按名
  缓存，未命中同样缓存。
- `packages/server/src/http/routes/plugins.ts`：注册表路由现在由两个来源拼出整张货架——先本地构建
  带的，再 npm 那一侧——按名去重，说明文档取第一个有内容的那份。
- `packages/web/src/features/plugins/plugins-page.tsx`：构建与插件库都没有的发布条目各占一行，无条件
  归入**可安装**，按钮是**装入插件库**。遇到 409 时弹出与导入对话框同一份覆盖确认，确认后带
  `overwrite` 重发。
- `ADELIE_PLUGIN_MARKET=off` 关掉这一次对外查询，货架只剩本地那一侧，断网或封闭环境应当如此。服务
  器自动发起的对外请求现在是两个：新版本检查，以及这一条。
- `plugins/*/package.json`：十六个公开发布的插件包补上这个关键词（已有八个）。
- `packages/docs/content/skills.{zh,en}.md` 与 `configuration.{zh,en}.md`：货架的另一侧、那一侧的
  条目能做什么，以及新增的环境变量。

## 兼容

- 接口一个都没动：注册表响应与货架界面是多了一些行，不是多了字段。
- 到不了 npm 的部署看到的和以前一样——插件库、插件目录，以及本次构建自带的插件。这一次查询永远不
  会让页面加载失败。
- 关键词要等各包下一次发布才生效；在那之前，只要某个构建带了它们，它们仍在货架上。
