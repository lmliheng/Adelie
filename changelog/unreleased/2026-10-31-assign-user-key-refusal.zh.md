# 分配用户密钥被拒时，原因留在密钥列表上方，不再把列表顶掉

- **日期：** 2026-10-31
- **类型：** fix
- **范围：** `web`
- **破坏性：** 无

[English](2026-10-31-assign-user-key-refusal.md)

模型分组的「从用户密钥分配」写失败时（服务端 500、配置不可写等），对话框会把原因显示出来，
但它此前是**用原因替换整块内容**：勾好的那条密钥、以及列表里其余几条，一起从框里消失了。于是
这个刚被拒的动作变成「看不见自己勾了什么、也换不了别的密钥」，只能先用「取消」退出去再重新打开。

现在原因排在列表**上方**，列表与勾选原样留着，「确认」仍是同一次重试 —— 这条拒绝本来就没有写
下任何东西，所以框里除了多一行红字以外，与刚才完全一样。只有**读用户密钥本身失败**（那时框里
本来就没有列表）才只剩原因一句。

## 细节

- `packages/web/src/features/models/models-page.tsx`：`AssignUserKeyDialog` 的正文从
  「原因 / 骨架屏 / 空态 / 列表」四选一，改成「原因（可有）」+「骨架屏 / 空态 / 列表」三者之一，
  骨架屏只在没读到表、也没出错时出现。注释写明为什么原因不能顶掉列表（重试要重复的正是那次勾选）。

## 测试

- `packages/web/e2e/models-assign-user-key.spec.mjs`（新，真浏览器三条）：空账号被指到「用户密钥」
  且「确认」不可点；勾一条全局密钥 → 分组下全部模型拿到同一条（服务端回报的掩码为准）、自定义分组
  没有这个动作、账号自己的表不被消费；被拒一次 → 框还在、列表还在、勾选还在、服务端一行都没写，
  再点「确认」就真的落地。
- 反证：把这一处源码退回、重建 Web 产物，同一个套件里只有第三条红，红在「框里找不到那条勾选框」
  （改前框里只剩一段原因），另两条照旧绿。

## 兼容

- 接口、磁盘格式、文案键都没变；成功路径的界面与从前一致。
