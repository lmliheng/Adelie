# 智能体设置：还原配置与更新内核被拒时，原因留在框里

- **Date:** 2026-10-26
- **Type:** fix
- **Scope:** `web`
- **Breaking:** no

[English](2026-10-26-agent-config-refusal.md)

智能体设置的概览页有两个改写配置文件的确认框：还原为默认配置、更新内核。它们被拒时框本来就开着、
没改动任何东西，丢的只有那句话 —— 服务端为什么拒绝只落进一条通知，几秒后自己消失，而框还留在眼前，
重试按钮就在最下面。

现在两个框都自己留着回答：被拒时服务端原话画在框里那一句话的下面（应用既有的「操作被拒绝：」前缀），
就在重试按钮旁边。关掉框或重新打开都不会带上一次的原因。智能体列表页的同一次批量内核更新、以及本页 API
标签页的三张卡早就这么做了，这一处是同一套口径没有跟上的最后两处。

## 细节

- `features/agents/agent-settings-page.tsx`：概览页新增 `resetRefusal` / `kernelRefusal` 两份状态，
  两个确认框把它们交给 `ConfirmModal` 的 `refusal` 槽（与 API 标签页一致，状态里存服务端原话、
  画的时候套 `S.common.refused` 前缀）；打开与关闭两条路径都清空它，失败不再弹通知。
  概览页的「保存名称 / 描述」那条路径仍用通知 —— 它没有确认框，字段里的输入本来就留着。
- 新增浏览器用例 `e2e/agent-config-refusal.spec.mjs`，两条：用 `page.route` 把 `…/config/reset` 与
  `…/config/kernel-update` 拒成 500 之后，原因在框里、通知区里没有、框与它原来那句话一个字节没变、
  服务端的配置也没被改写；取消后重开不带旧原因，重试才落地并关框。内核那一条把配置读取里的
  `kernelOutdated` 改成 true，才有可点的更新按钮（开发数据根里默认智能体本来就是最新的）。

## 兼容性

- 没有接口、传输格式、已存数据或依赖变化：只改了「被拒时原因画在哪」。除既有的 `S.common.refused`
  前缀外没有新文案。
