# 删除模型：写成功才收起确认框，被拒的模型留在页面上

- **Date:** 2026-10-20
- **Type:** fix
- **Scope:** `web`
- **Breaking:** no

[English](2026-10-20-models-delete-model.md)

模型的配置对话框里，「删除模型」会先问一句，说明要删的是哪个模型、它的配置与 API key 一起移除。
而这张确认框和它背后的配置对话框此前在请求发出时就关闭，**不管删没删成**；同时 `persist` 会保留尝试
中的表 —— 对一次删除来说，那就是一张**没有这个模型**的表。于是被拒的那次删除让模型从页面上消失，
服务器却仍然留着它，而打开这张对话框的卡片也跟着没了：没有地方可以重试，只剩一句错误提示。

现在删除把写入做完之后才收起这两张对话框，被拒时卡片与服务器那一行都原样留着。

## 细节

- 两张对话框一直开到表写入有结果为止；被拒时句子原样留着，错误提示照旧显示服务端那句话，重试就是
  同一张确认框。
- 写入被拒时页面留在删除前的表上（而不是尝试中的那张）：卡片、它的「删除模型」入口、以及对话框本身
  都还在 —— 对话框是按「它那一行仍在表里」才挂载的，尝试中的表会在半途中把它卸掉。
- 请求在飞的时候确认框标为 busy（按钮禁用），连点不会发出第二次写入。

## 兼容性

- 没有接口、传输格式或依赖变化；只改了页面里写入与收起的先后。
