# 工位忙时错过的 @ 合并成一个工作轮送达，重启也不丢

- **Date:** 2026-10-06
- **Type:** fix
- **Scope:** `server`

[English](2026-10-06-org-desk-mentions.md)

过去员工在频道里每被 @ 一次，就在其工位上单独发起一个 Task；工位忙时这些 Task 排在会话的内存队列里。
工位跑完一个长 Task 回来，可能面对几十个排队的工作轮，每个都带着同一段频道上下文，而其中大多数说的是
它已经办完的事；服务重启或热更新会静默清空这个队列，而频道扫描早已越过这些消息，它们再也不会送达。
本次从上游 PenguinHarness 移植（`feat/org-trigger-coalesce`，提交 `c41fa086`），此前本 fork 没有这一条。

## Details

- @ 现在先记入公司模式新增的表 `org_desk_mentions`（迁移 13，`company-mode-desk-mentions`，swap-safe），
  与推进频道扫描游标在同一次对账里落库，按（员工、频道、消息）去重；工位会话的 follow-up 队列不再承载它们。
- 每次对账把待送达的 @ 合并成一个 `kind: mention` 工作轮送给空闲的工位：每轮至多 `MENTIONS_PER_RUN`（20）条，
  发起成功才出队，因此发起被拒或开不出工位时它们留待下一次对账；忙着的工位被跳过，它的 @ 继续累积。
- 只有一条时正文与过去完全相同；多条时合成一份清单：逐条列出完整的点名，按频道分组，今天早些时候的
  上下文每个频道只附一次、不再每条附一次；点名之间未 @ 它的消息留给 `penguin org channel tail` 去读。
  触发块的 `message` 写首条点名并注明后面还有几条；点名跨频道时省略 `channel`。
- 合并轮的 hop 取其中各条的最大值，连锁上限不因合并而重置。组织暂停或公司模式关闭期间待送达的 @
  保留；员工离任时一并清空。
- `company-employee` Skill 说明了合并送达的 `mention` 工作轮：每条点名回到各自的频道答复，已处理过的
  跳过。`agent-company` 版本为 `2026.10.06.1`。
- 排队比跑一轮便宜：这正是让一个长 Task 回来时不再面对十几个重复读同一份频道与同一份手册的工作轮的原因，
  差别在 `penguin cost --by session` 上看得到。
