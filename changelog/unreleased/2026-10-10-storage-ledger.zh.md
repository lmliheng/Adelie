# 数据根的存储分类账，以及对它什么都不会做的实现

- **Date:** 2026-10-10
- **Type:** feature
- **Scope:** `core`, `server`, `cli`, `web`, `docs`

[English](2026-10-10-storage-ledger.md)

Adelie 现在能说清自己的数据根是由什么组成的。`penguin storage`，以及 Web App 设置里的「存储」页，会逐类给出一行——用户资产、临时工作区、会话草稿、轨迹、工具环境、回收站、数据库、其他——然后是可供人清理的条目，每一条都写明它命中的规则，以及清掉它的代价。

**这一版里没有任何东西会删除任何东西。** 没有定时器，没有会自己动手的阈值，也没有能执行删除的接口：整个功能就是一次只读遍历加一份报告。它是记录在 issue #17 里的清理设计的第一步，那份设计的两个固定点是——默认保留每一个字节，以及此后任何删除都必须由人对着**一份具体候选清单**审核。

## 细节

- **词汇表在 core，以纯函数形式存在。** `state/storage.ts` 只遍历数据根一次，然后给出账本：每个字节都恰好落进一个类别，所以各类之和等于数据根本身的大小，未分类的文件无处藏身。`protected` 是用户资产——Agent State、Project 配置、用户自己指定的 Workspace、密钥库、插件、基准、快照——永远不是候选；可能成为候选的是派生数据：临时工作区（`empty`、`unreferenced`、`idle`）、会话草稿（会话已不存在时的 `orphan`、`idle`、`budget`）、轨迹（`idle`、`budget`）、工具环境（`idle`，另有一道 `agent_state` 文本检索作护栏）、回收站与数据库。
- **活性是输入，不是扫描能自己发现的东西。** `scanStorage(root, live)` 从调用方取会话 id、Workspace 真实路径与最后活动时间；`emptyLiveSet()` 被起了名字而不是做成默认值，因为「假设什么都没被引用」的扫描会把每个临时工作区都说成可以回收。只有服务端回答得了这个问题，所以命令与页面都是去问它，而不是各自去走一遍磁盘。
- **除临时工作区的静默规则（30 天）外，所有阈值默认关闭。** 在写下这份代码的那台机器上（数据根只有十天、6.0G），按年龄的规则报出的「超过三十天」的字节数是 0，所以年龄是慢杠杆；账本的价值在于它能把快杠杆点名。数字是**表观大小**（`st_size`），因此小文件多的目录树会显得比 `du` 报的轻，而卷自身的数字随报告一起给出，不靠推算。
- **`GET /api/admin/storage` 仅限管理员、只接受 GET、不带任何参数。** `StorageService` 用 `Projects.listAll` 上的 `SessionIndex.listByProject` 组装活性集合，再把账本映射到 API DTO；正在被删除的会话仍按「活着」算，因为那个窗口从节点里够不到，而且按活着算只会让条目看起来仍被引用，绝不会把删除将要带走的东西说成空闲。
- **CLI 明确说明自己是什么。** `penguin storage [--top <n>] [--json]` 先打印类别，再打印带规则的候选，然后是同名或同结构的工具环境——只报告、绝不提议删除，因为两个看起来一样的环境可能版本不同——最后一句写明：没有你的批准不会删除任何东西，也没有任何定时任务在跑。`--top` 折叠尾部而不是把它藏起来。
- **设置页写着同一句话。** 「存储」页并入管理员分组，画出类别表、候选清单（附每类「清掉它的代价」：旧消息附件不再能预览；历史回放与成本页失去重建依据；环境下次用到要重新装）、疑似重复的环境，以及扫描读不到的路径——报告从不显得比自己更完整。
- **文档。** `/docs/cli § penguin storage` 与服务端 API 参考描述了该路由与只读约定，中英两份都已更新。
